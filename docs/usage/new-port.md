# A new port

```sh
dockhand create https://github.com/owner/project --new --category devel
```

`--plan` prints the Portfile `create` would write, its checksums still to fill in, and writes nothing, starting no branch.

A Rust project's destroot installs the programs its packages build, its workspace members' among them, as an update's comparison reads them: each `[[bin]]`, and the one Cargo makes of a package with `src/main.rs`. A member named by a glob, as `crates/*`, isn't read.

In place of the URL, `pypi:NAME`, `crates:NAME`, or `go:MODULE` names the project by its registry: `create` reads where PyPI's project URLs, the crate's `repository` on crates.io, or the module path (or its `?go-get=1` answer) says its source is, and goes on from that project. A registry that names no source on GitHub, GitLab, or Codeberg says so; a source on GitLab or Codeberg is named, and refused as any non-GitHub URL is, for now. A Go module below its repository's root, as `go:golang.org/x/tools/gopls`, is created at its own tag, `gopls/v0.20.0`, at the version Go's module proxy has, and builds in its directory, with `build.dir` and a `dist_subdir` of its own, as `devel/gopls` does; its modules are fetched as it builds (`go.offline_build no`, marked), since go2port reads a module at its root. `golang.org/x` is read from its GitHub mirror, as the golang PortGroup fetches it.

`create` reads a GitHub project, its latest release, and the build files at that release, and writes a new port's Portfile. A name master already has, as a port's directory or a subport, is refused before `--new` starts a branch, with `--name` to name this one otherwise. It uses the github PortGroup, and cargo, golang, cmake, meson, or python as the project's files say. A Rust project's `cargo.crates` come from its `Cargo.lock`, read as `update` reads it, and the checksums are filled in. A Go project's `go.vendors` is written by the checksums step, through `go2port`, from its source's go.mod and go.sum, since a module's checksums come only from fetching it; `checksums` does the same for any port whose dependency block is declared empty. A Python project's `python.versions` starts from the python PortGroup's default, as MacPorts evaluates the new Portfile. The port fetches the release's own `project-version.tar.gz` where the release carries one (`github.tarball_from releases`), and GitHub's archive of the tag where it doesn't. A crate `cargo.crates` can't fetch, from another registry or from Git, is marked rather than written. Dockhand marks inferred values with `# dockhand: unconfirmed`. Review each value, correct it if needed, and remove the comment before submitting:
- the license, from the project's `Cargo.toml` or `pyproject.toml` where it declares one MacPorts has a name for, else from GitHub's detection. It's written in MacPorts' words: `MIT OR Apache-2.0` is `{MIT Apache-2}`, and CC0 or the Unlicense is `public-domain`;
- the long description;
- the category, unless `--category` names it: one of the tree's categories the project's description names (a "terminal text editor" is `editors`), else the build system's guess, and said with what it chose, since it picks the directory. Running `create` again with another `--category`, before the port is committed, moves it there, your edits included;
- a Rust or Go port's `destroot`, which installs the programs its manifest names, since neither PortGroup installs anything.

The description is the manifest's one line where it has one, else GitHub's. A plain-HTTP homepage is written as its `https://` form where that answers, since MacPorts prefers HTTPS, and said where it doesn't. The maintainer is your `maintainer` setting, else `nomaintainer`, marked, and `create` says the line to set: the one the ports naming your GitHub login write at the branch's base, as `{example.org:ada @ada}`, with any others they write named, each with how many ports write it, for you to choose from. It writes no configuration; where it can't find yours, it shows the forms a maintainers line takes, `@you` or `{example.org:you @you}`, for you to fill in. `outdated --mine` and `serve`, which needs the setting for its daily look, suggest the same line, at master, `serve` as it starts; each names the configuration file it read, `$DOCKHAND_CONFIG` where that's set. `--name` names the port when the project's name isn't right for it. The new Portfile is staged, so the next check includes it.
