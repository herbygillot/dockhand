# Dockhand v0.5.0 architecture and code organization review

Reviewed October 22, 2026, at `8c00797931b6006656d0b8bedc2acc1c25170808`, the current v0.5.0 release candidate source. The source checkout was clean and remained unchanged during the review. This review covers the Go package graph, commands, application workflows, state and persistence, build providers, MacPorts editing and assessment, upstream sources, and test organization. Three teammates reviewed separate areas; the findings below were reconciled against the October 16 and 19 reviews and the current roadmap.

Dockhand's architecture has improved substantially. The command split is real, several previously duplicated decisions have useful pure owners, and the dependency direction is disciplined. The strongest remaining problems concern loss of context at boundaries: invocation context, build environment, accepted-failure decisions, and upstream source identity. Four focused regression probes reproduce consequences of those losses. The next structural investment should finish ownership of those facts and decisions, then reduce the engine's responsibilities incrementally.

Priority here means recommended order of attention. P1 is a potentially misdirected operation; P2 is incorrect behavior or an important ownership problem; P3 is contained cleanup. Structural changes are not automatically release blockers.

## Findings to address first

### 1. P1 Watch actions lose the context of the displayed repository

**Reproduced.** [RunWith](../../internal/command/root.go#L83) receives an explicit environment, directory, dependencies, and host, but installs the process-level `Run` as the nested command runner. [Watch](../../internal/command/status/watch.go#L208) invokes that runner with only the verb and branch, or `logs check-N`; [watchVerb](../../internal/command/status/watch.go#L248) does not retain global tree, database, or Git selections.

For example, `dockhand --tree /repo-A --db /db-A status --watch` can display A and redispatch a typed operation using the process defaults for B. A colliding branch or check name makes an incorrect destination possible. The focused probe first checks a branch successfully in an isolated invocation, opens watch, and types `l`. The nested command fails against the review process's directory instead of reading the displayed check's logs. That proves context loss; mutation of another real repository was not attempted.

Bind nested dispatch to the current invocation and its effective tree/database/Git selections, retaining the injected host and dependencies. Keep the printable command distinct from the complete execution context. Verify with two repositories and databases containing identical branch and check names, asserting the operation's actual destination.

### 2. P2 Link declarations from one environment suppress findings in another

**Reproduced.** [Engine.UndeclaredLinks](../../internal/engine/links.go#L54) evaluates each target in its own environment but accumulates declarations in a map keyed only by target ID. [The evidence rule](../../internal/evidence/links.go#L53) then judges every result against that combined declaration list.

The probe builds the same target on arm64 and x86_64, linking `oniguruma` in both. Only the x86_64 evaluation declares it in `depends_lib`. No undeclared-link finding is returned for the arm64 build. Conditional dependencies across macOS releases have the same problem.

Pass a build-scoped observation containing the result, environment, and declarations into the pure rule. Judge each build before combining matching findings for display. Retain the environment in the finding so it can explain where the declaration is missing. The adjacent rule that considers a target read when any environment read it is explicit current policy; that is a separate coverage choice, not the reproduced declaration bug.

### 3. P2 Publication eligibility still has two definitions

**Reproduced.** [SubmitReadiness](../../internal/branchstate/submit.go#L26) requires `CheckPassed`, while [Standing](../../internal/branchstate/standing.go#L90) maps a failed run directly to `CheckFailed`. [PlanSubmit](../../internal/engine/submit.go#L572), however, applies standing acceptances and can allow that same failed dependency build. [BranchStatus.Facts](../../internal/engine/status.go#L230) carries no accepted-failure eligibility into branchstate, and [PassingBranches](../../internal/engine/servesubmit.go#L53) filters using the narrower definition.

The probe records a standing `libgcc15` acceptance, verifies that subsequent `PlanSubmit` has no blocks and reports `AcceptedStanding`, then finds `PassingBranches.Ready` empty and `Others` equal to one. Thus direct submission permits a branch that `ship --passing` and serve's candidate selection exclude. Status also continues treating the accepted failure as an unresolved attention item.

Give publication eligibility one result calculated from evidence plus applicable decisions, and use it in submission, candidate selection, and attention. Keep the historical run outcome as failed: acceptance changes whether work can proceed, not what happened during the build. Test agreement across those consumers, including expiration when dependency version or environment identity changes.

### 4. P2 Assessment reinterprets a Git source after its commit was resolved

**Reproduced.** [Assessment](../../internal/engine/assessment.go#L507) obtains the source through `PortInfo.GitSource()` and resolves its commit, then hands the original `PortInfo` to the archiver. [upstream.gitRepository](../../internal/upstream/source_archive.go#L55) gives the forge PortGroup precedence and only falls back to `git.url` when no forge was interpreted.

A Portfile retaining `github.setup owner project` while overriding `git.url` to `https://github.com/fork/project.git` resolves the fork's commit but asks `owner/project` for its archive. The probe confirms that exact repository mismatch. A fork-only commit can therefore produce an unreadable assessment even though its fetched repository is on a supported forge.

Carry the resolved source identity into `SourceArchiver`, rather than asking it to derive source identity again from the entire Portfile. Separate the repository used for upstream release discovery from the repository that actually supplies the fetched source. Test overrides within one forge and between supported forges.

### 5. P2 Git reference observations discard the failure kind needed for retry

**Confirmed by control flow.** [resolveGit](../../internal/engine/plan.go#L383) turns missing references, network failures, and timeouts into `GitSource.Unresolved` strings. [readCommits](../../internal/engine/assessment.go#L511) classifies every unresolved case as `refusal.Failed`. [lookAgain](../../internal/engine/assessment.go#L222) recollects only transient assessments or sufficiently old upstream-missing assessments.

Consequently, a temporary ref lookup outage can leave an incomplete assessment reused indefinitely for the same tree, base, and assessment-policy version. The recent fix that retries refused downloads after a day does not cover this path.

Return a typed source observation with resolution state and failure kind, preserving the underlying cause. Distinguish a missing ref from a temporary inability to read refs, and make both refresh policies explicit. Add a recovery test where the first lookup fails transiently and a later lookup succeeds without a tree change.

The same observation type would clarify a related policy gap: [movedSources](../../internal/engine/servesubmit.go#L200) skips an unresolved current commit, including tag lookups at line 214. Its comment explicitly chooses that behavior, while the branchstate activity note says unknown source freshness holds unattended publication. This discrepancy needs a policy decision and a contract test; it is not being presented as a reproduced publication incident.

## Remaining ownership and organization work

### 6. P2 Status acquisition remains mixed with rendering

**Confirmed by control flow.** [ShowStatus](../../internal/command/status/status.go#L119) gathers a judged branch status for JSON, then unconditionally calls [showBranch](../../internal/command/status/status.go#L561), which gathers it again. The text path also performs an [UndeclaredLinks lookup](../../internal/command/status/status.go#L613), even when its output is discarded for JSON.

This duplicates Git, evidence, and liveness work and allows the two reads to observe different states. A second status read can also fail after the JSON result has been prepared. Relatedly, [view.WriteNextFor](../../internal/command/view/next.go#L120) queries the engine from the nominal presentation layer.

Gather one detail model, including any requested link findings and attention facts, then pass it to pure text and JSON renderers. Move `WriteNextFor`'s acquisition to its caller. This is a useful concrete boundary improvement; another broad presentation abstraction is unnecessary.

### 7. P2 The engine remains the main concentration of responsibilities

The engine is still 21,202 production lines in 59 files, with 50 direct Dockhand dependencies. Its role as the application façade is reasonable, but three responsibilities now have clear extraction seams:

- **Assessment collection:** archive acquisition, source resolution, cache reading, patch checking, retry classification, and persistence span [assessment.go](../../internal/engine/assessment.go#L241) and [update.go](../../internal/engine/update.go#L891). A collector with explicit dependencies and typed acquisition outcomes would directly address findings 4 and 5 while preserving the pure `assess` package.
- **Concrete construction:** `compose` now assembles providers and the shared GitHub runtime, but [preparer.go](../../internal/engine/preparer.go#L35) still constructs evaluators, index and selection readers, discovery, editors, HTTP clients, and workspaces. Finish construction through compose-owned factories, preserving lazy initialization where it avoids unnecessary setup.
- **Publication analysis:** [PlanSubmit](../../internal/engine/submit.go#L303) still combines fact gathering and inline policy, while branchstate has narrower readiness and publication rules. Separate collected facts from the eligibility result described in finding 3.

Keep `Engine` as the façade. Extract coherent responsibilities when their contracts are understood; creating a package per large file or command would distribute the same coupling across more interfaces.

The command and serve preparation drivers also remain separate: [command shipOne](../../internal/command/ship/ship.go#L428) and [engine.ship](../../internal/engine/ship.go#L71) each sequence edit, tidy, and check. However, shared queue, commit, and publication gates have removed much of the previous duplicated policy. This is residual workflow duplication, not a reason to repeat the earlier review's claim unchanged. Keep future stage decisions in shared owners and add cross-driver contract tests before attempting another driver consolidation.

### 8. P2 Source comparison partly owns MacPorts assessment policy

**Design debt; no incorrect verdict demonstrated.** [sourcecompare.Compare](../../internal/sourcecompare/compare.go#L108) accepts callbacks describing what the Portfile names. [assess supplies them](../../internal/macports/assess/assess.go#L442) through `portfile.Mentions`. CMake comparison uses that context to decide which statements matter, produces `How: "options"`, and [assessment exempts that classification from holding](../../internal/macports/assess/assess.go#L759).

The intended separation is source facts in `sourcecompare`, MacPorts meaning in `assess`. Here the effective-build judgment spans both. When extending these rules, have comparison return structured changed statements, options, defaults, and guards, and apply the Portfile context in assessment. Avoid encoding the judgment partly in callbacks and partly in string classifications.

### 9. P2 Known deferred duplication remains in Cargo program inference

**Previously acknowledged as CX-7 and explicitly deferred to Then.** [portcreate.Binaries](../../internal/macports/portcreate/manifest.go#L48) invents a package-named binary whenever no explicit `[[bin]]` exists and otherwise returns only the explicit list. [CargoManifest.Programs](../../internal/project/cargo.go#L47) already owns the more complete inference used by source comparison, accounting for `src/main.rs`, `autobins`, and explicit targets.

Creation can therefore generate an install command for a library-only or `autobins = false` crate, and omit an inferred main binary beside explicit binaries. Let `project` discover programs once from manifest plus source layout, and have creation and comparison consume that result. Its existing roadmap placement remains reasonable; this is remaining debt, not a new v0.5.0 regression.

### 10. P3 Make edited Portfile identity explicit

[portedit.Result.Files](../../internal/macports/portedit/prepare.go#L85) is an unrestricted slice, but corrections, patch removal, Go minimum changes, stealth handling, and dependency regeneration repeatedly assume its first entry is the primary Portfile. Examples include [correction.go](../../internal/macports/portedit/correction.go#L46) and [dependencies.go](../../internal/macports/portedit/dependencies.go#L366).

The checked-correction machinery now centralizes valuable invariants, but this positional rule remains implicit. Add a named primary-Portfile accessor or field and centralize replacing it together with evaluated state and the fidelity report. This is a small contract improvement, previously acknowledged in R3-40; no current crash was demonstrated.

## Improvements that held up under review

The command split has useful boundaries: verb families sit above shared settings, host, branch flags, view, checkrun, and tidyrun. Import tests enforce that direction. Per-test invocation environments and stand-ins replace much of the former global-seam machinery, and command tests now run broadly in parallel. The watch redispatch issue is an exception to an otherwise substantial improvement in context handling.

`QueueCheck` now owns covered-run, follow, and replacement policy. Baseline and stopping runs use the shared branch-check predicate. Commit and publication gates are shared. Build-profile vocabulary and the coordination liveness window have single owners. The GitHub runtime is shared, and REST/GraphQL pull-request precedence uses common helpers.

The pure packages are meaningful: `model` depends only on the standard library; `planning`, `reuse`, `evidence`, and `branchstate` provide explicit rules; `project` stays independent of MacPorts; `assess` requests observations instead of performing I/O. Checked corrections publish edited files, evaluated state, and fidelity reports together. Distfile binding, transport, and contextual edit observation also have useful separate homes.

The store has a coherent record/transaction contract, repository scoping, fenced leases, uncertain-commit handling, and migrations applied in one transaction. No finding justifies introducing an ORM, replacing SQLite, splitting its records file into packages, or changing durability merely to make the package smaller.

## Recommended sequence

1. Fix watch redispatch first. It can direct an operation at a different context than the one on screen.
2. Fix the other reproduced disagreements in small batches: environment-scoped links, acceptance-aware publication eligibility, and actual Git-source archive identity. Promote the focused probes into repository tests at the appropriate owners.
3. Preserve typed Git-resolution failures and test recovery without source changes. Settle the explicit unknown-freshness policy at the same boundary.
4. Gather status details once and make rendering pure. This is a contained improvement with a clear ownership boundary.
5. After the candidate's behavior is settled, extract assessment collection and finish compose-owned construction incrementally. Do cohesive file splits while touching those areas. Keep the acknowledged Cargo work in its existing deferred batch unless its release priority changes.

The four reproduced failures share a useful lesson: a value crossing a boundary must retain the context that makes it meaningful. Package import rules are already doing their job; cross-consumer agreement tests are the next useful guardrail. Exercise the same evidence and decisions through status, submit, ship, and serve, and the same source identity through planning, fetching, and assessment.
