# 2026-10-07: a target builds with only its closure active (batch 118)

From field testing at e498a1a8, and the person's "Into rc9". taisei's revbump for libunibreak 8.0 passed its check, and MacPorts CI failed on all three runners: "Program 'msgfmt' not found", taisei declaring no gettext.

## The cause

The guest deactivates every port before a target and installs `depof:` its dependencies, as CI does. A dependency with no archive for the guest's release builds from source, though, and what it built with stays active for the target. check-268, of taisei once it declared gettext, shows the path: git, a dependency, had no archive for macOS 26, so it built, and its build ran msgfmt from gettext. CI installs git from its archive, so nothing of its build is there. The first check's logs are gone, so that gettext came this way for it is inferred.

## What changed

- **After its dependencies install, the guest deactivates what isn't the target's closure** (guest.tcl): its dependencies of every kind, and theirs other than for building, as `port rdeps --no-build` has them, port(1)'s own. The target's log says what went: "dockhand: deactivating what the dependencies built with, outside taisei's dependencies: gettext".
- **VerifierProtocol is 3,** since a target is judged otherwise: one that passed with another port's build tools may not pass without them, so Tart results recorded before aren't reused, and a check says why, "dockhand has begun to build each target with its own dependencies alone active, …". Each port is built once more on Tart; the dependency archives kept since batch 90 are still given to guests.
- The roadmap's item goes, done.
