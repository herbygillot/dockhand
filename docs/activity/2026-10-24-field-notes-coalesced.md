## Harm

None is harm by the release bar. The nearest is the exiv2 session's: a
main build's read-only `status -b` migrated the shared database from
schema 32 to 39, which locked the installed v0.4.0 out. Nothing was lost:
the migration said so and kept the schema 32 copy, and an older build
refusing a newer schema is the designed refusal. v0.5.0 is a release, so
its first command migrating a 0.4.0 database is the upgrade itself.
v0.5.0 needs only its notes to say that any command migrates it, and
that DOCKHAND_DB pointed at a copy tries a newer build without touching
it.

The bazel session's silent check is a regression from v0.4.0, but not
harm either. Part 5 moved a check's progress to `-v` off a terminal, so
a session reading dockhand's output saw nothing for 36 minutes while
bazel's server held `port`'s pipe open. Nothing was lost or sent wrong,
and `-v` prints every step, so it is a known-issues row in v0.5.0 and a
fix for main.
