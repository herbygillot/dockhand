# 2026-10-06: a kept Go module the new output has is listed once (batch 101)

From the v0.3.0-rc3 full run's A4, a blocker: `dockhand update go-reflex --new`, 0.3.1 to 0.3.2, said it kept github.com/kr/text, which go2port leaves out, and wrote it into go.vendors twice; update reported success, and the check failed at extract ("error renaming …/work/kr-text-v0.1.0/"). It comes after v0.3.0-rc3, and none of it is in that candidate.

## What changed

- **A module the new version's go2port output has is the output's.** An update tells a module a Portfile keeps by hand from what go2port leaves out of the current version's go.vendors. kr/text was missing from 0.3.1's output and present in 0.3.2's, and the kept row was added beside the generated one. Such a module is now taken off the kept list before its go.sum pin is asked after, so it's neither added again nor said to be kept (`portedit`).
- **KeepGoModules adds no second row** for a module the generated block has, whatever its caller asks (`depblock`), and `depblock.GoModules` says which modules a block declares.
