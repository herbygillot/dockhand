# Why three GitHub provider tests failed together under load

A full-suite run on 2026-09-19 failed `TestDriverProgressFollowsGitHubRun`, `TestIndependentJobsShareRunAndCancelSeparately`, and `TestDriverRecordsMissingRunGuidanceAndCancelsOffline` at once, with no usable output, and each passed alone and on a clean rerun. A side investigation found one mechanism.

The package's tests waited with testify's `Eventually` on a five-second wall-clock budget, and the condition ran a whole engine cycle whose first look does a real `git push` to the fixture remote plus SQLite transactions. Unloaded, the expected state is reached on the first call, so the whole budget is one invocation: a single call slower than five seconds fails the test although it would have succeeded. Under about five times CPU oversubscription those calls took two to three seconds; at the load of the reported run, every package in parallel plus the Tart guest tests' twelve `port-tclsh` processes, they crossed five. When `Eventually` times out it abandons its condition goroutine, which later finishes the cycle and calls `require.NoError` after the test has ended, which panics the binary and reports every parallel test in flight as failed. One slow cycle, three failures, no output.

A second, latent hazard was that the fixture never injected a clock into the engine, unlike the workflow fixture. Retry and wait deadlines back off exponentially toward a five-minute ceiling, so any test needing a dozen backed-off looks already needed more than four real seconds of a five-second budget.

The sixteen `Eventually` sites are now a fixture `settle` loop: the condition runs on the test goroutine, so a slow cycle cannot be cut short and an assertion inside it fails this test instead of panicking the binary; the engine reads the fixture's simulated clock, advanced between looks with a doubling step so each look lands past the engine's next backed-off deadline without any real waiting; and a bound of two hundred cycles is a stuck-workflow guard, not a timeout. Under three hundred CPU hogs the old binary failed three of four package runs; the new one passed six of six, plus `-race`. A residual failure at seventeen times oversubscription, `git rev-parse` killed by the git package's own exec wait delay, is the machine failing to schedule a subprocess and was left alone.
