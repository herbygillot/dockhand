# 2026-10-05: an edited description stays, and update's record sees all (batch 99)

Batch 99 of the [roadmap](../roadmap.md): the architecture re-synthesis's L1 and L2c, which the person chose for v0.3.0-rc3. It comes after v0.3.0-rc2, and none of it is in that candidate.

## What changed

- **An edited pull request description survives every re-submit (L1).** A re-submit merges what the person edited into the description dockhand writes, and stored the merged body as what dockhand last wrote. The next re-submit then compared the person's text with itself, found nothing kept, and wrote over it. Submit now stores what dockhand itself would have written, the sections the person kept holding dockhand's text there (`prdescription.Written`, `SubmitPlan.Written`), so a person's section reads as theirs on every later submit.
- **update's change record says what it changed where this Mac's evaluation doesn't look (L2c).** The record an update primes from its own evaluations had no Unseen or AllUnseen, which a record made from the base has had since batch 76, so a subport changed only under another Mac's platform dropped out of submit's ports and tidy's groups, and the record was never made again. Priming now reads the base's and the update's Portfiles and sets both (`portfile.UnseenChanges`). `fidelity.ChangePolicy` is 4, so records primed under 3 are made again.
- **The README's known issues** add L2a (update doesn't say an archive the new version no longer fetches), L2b (a fetch that fails during update holds the branch until a file is edited), and X2 (a fault in dockhand's own guest handling is retried three times, a VM cloned each time).
