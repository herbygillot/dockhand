# The mirror's index is named by kernel architecture

`DefaultMirrorURL` spelled the mirror's index directory from the platform record, `PortIndex_darwin_25_arm64`, and the mirror publishes `PortIndex_darwin_25_arm` and `PortIndex_darwin_25_i386`: MacPorts names these by the kernel architecture it reports as `os.arch`, arm or i386, not by the build architecture. The URL had never resolved for any platform dockhand models, and nothing noticed because staging does not use it, by the stance recorded beside it, that a mirrored index cannot prove which source tree it describes. It is recorded into a Tart provider's settings as bootstrap provenance, where it was recording a path that returns 404.

The function maps arm64 to arm, every Intel build to i386, and PowerPC to powerpc, and refuses an architecture the mirror does not publish rather than guessing a name. The test states the rule for both current architectures.

This came out of weighing whether the mirror's index could save the four minutes a full local generation costs. The cache on this machine records 63 generations, 7 built in full and 56 incrementally, and the full ones come mostly from separate registrations of the same repository building their own generations for commits another registration already indexed. So the queue takes seeding across registrations first, offline, and the mirror as a bootstrap seed behind it: the 25.7 MB index bracketed by its `Last-Modified` to a master commit, with the paths that changed since re-indexed through the incremental path that already exists, recorded as non-strict provenance, and gated to the commands that already fetch master, so `assess` stays offline by default.
