## The cause

A kept archive reaches a guest by two paths. A reused target's (`installs`) was read whole against its digest, and an altered one said as an `archive.altered` event; but check prints only progress, results, and execution events, so it was in the journal alone. A dependency's (batch 90's `dependencyInstalls`), which is what check-64 had, gettext-runtime and libiconv, was read against its digest too, and skipped in silence. `keptArchive`'s test compares only the size, which a flipped byte keeps; it's the cheap test reuse and cleanup make, and the digest is read where it counts, before a guest is given one, so that stays.

- **Both paths say an altered archive, once each** (`driver.altered`): "the archive kept of libiconv isn't the one it was kept as, sha256:…, so the guest gets it as MacPorts would, from its archives or a build", or "so the guest builds it instead" for a target's.
- **check prints it,** marked "!", and its `--json` result has each as `altered_archives`.
- **The altered file is set aside,** as `<file>.altered` beside it, so no later check meets it again, and what it was is there to look at; its record goes at cleanup, as a record's whose file is gone does. A later build of the port keeps its archive anew.

The row now alters only the library's newest kept archive, by its record, keeps its bytes first, and puts them back after the check and again in teardown, however act ended, whether the file is where it was or set aside; and assert fails unless every kept archive matches its digest.
