# 2026-09-30: what item 9 and batches 19 and 20 left (batch 21)

Batch 21 of the [roadmap](../roadmap.md): the loose ends item 9's revision assessment and batches 19 and 20 left, and what the dogfood runs found after them. Batch 20's three open ends are the agent's, merged separately.

## What changed

- **status names where to build again.** After `VerifierProtocol` 2, status said check-48's macOS 12 result "must be built there again" and gave `dockhand check --branch flatbuffers-25e2`. That builds where `check.on` says, macOS 26 only, so following it didn't clear the row. The row now carries the check's own environments, as `--on` names them: `dockhand check --branch flatbuffers-25e2 --on tart:12,26`. The "no check of these files built" row says the same. `engine.OnValues` renders environments as `--on` values: Tart's releases joined into one, others by provider. An environment no release names gives the bare command, as before.
- **An assessment stopped by the network is tried again.** An assessment recorded incomplete stood for its files. Now one whose failure was the network's is marked `Transient` and made again on the next collection:
  - a 429 or 5xx, a timeout or other `net.Error`, or a forge's rate limit;
  - a git.branch that couldn't be resolved.

  One the port caused, such as a 404 from upstream and from the mirror, still stands. `fetch.Transient` walks every cause of a joined error. `archives.Shipped` now keeps upstream's failure beside the mirror's, so a 404 upstream with a 502 at the mirror reads as the network's, not the port's.
- **serve says an uncertain port once.** A port with a permanently misspelled old tag, dolt's `v040.15`, is uncertain every day it's otherwise current, and serve named it every morning.
  - The daily look now records the tags each port was set aside for (`OutdatedLook.SetAside`). It names a port only where those changed since the last look, and counts the rest: "N more as before", or "N of yours may still have newer releases, as before".
  - `outdated` says, below its summary, that a tag set aside that's no release stays out once the port's livecheck leaves it out, the fix that settles it for good.
- **create asks a plain-HTTP homepage once.** `create` asked before writing the Portfile, and its checksum refresh asked again. The answers one command has had are now shared (`plainHTTP`'s `answered`, `UpdateRequest.answered`), and a URL already answered isn't asked again.
- **A vendored port's archives are compared** (the zola exercise). The revision assessment's fetch plan ran `archives.CheckPolicy`, which refuses a port that declares crates or Go modules. That made every Cargo or Go port's assessment "archives not compared", which holds unattended submission.
  - `ArchivePlan` now plans such a port's own archives from its Portfile with the declarations set aside, evaluated in a workspace overlay, as a checksum refresh sets them aside. The declarations are the lock file's, which the comparison reads in those archives. `archives.OwnArchives`, beside `CheckPolicy`, makes that Portfile, so the engine imports nothing new.
  - The port is still returned as it is, crates and all.
  - A Git-fetched port that declares crates now plans none, and is compared by its commits.
  - `diff --archive` gains the same.
  - `dependency.Declared` is the declared-crates reading that portedit's checksum refresh and the engine share.
  - `assess.Policy` is 2, so an assessment recorded under the refusal no longer stands; its doc now says it versions what's compared too.

## Decided along the way

- **Policy versions what's compared, not only the rules.** The design names one policy version in an assessment's fingerprint, and raising it is how earlier assessments stop standing. A change to what the engine gives the rules is the same kind of change for a recorded assessment, so it raises the same version rather than adding a second.
- **Only the network's failures are tried again.** A port's own failure, such as an archive gone from upstream and the mirror, gives the same answer on the next try, and trying it every collection would only repeat the fetch.
