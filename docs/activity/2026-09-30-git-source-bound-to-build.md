# 2026-09-30: a Git-fetched port's source bound to its build (batch 20)

The [update-workflow review](../reviews/2026-09-30-update-workflow.md)'s finding 5, and the [assessment design](../assessment-design.md)'s step 4: a port MacPorts fetches with Git names its source by `git.branch`, usually a tag, which binds nothing as an archive's checksums do. Preparation checked the tag around its own work, but the guest was told no commit and a result recorded none, so a tag moved after preparation built another source than the one recorded, and a later check reused the result anyway. Now a check expects a commit, the guest checks it fetched that commit, the result records what it fetched, and reuse and evidence require it. Portfiles keep their tags.

## How MacPorts fetches Git sources

Read from Base's `portfetch.tcl` in 2.11.6, 2.12.6 (installed), and master: `gitfetch` runs `git clone` of `git.url` into `${worksrcpath}`, shallow only without `git.branch`, then `git checkout -q ${git.branch}` there. Nothing is cached as a distfile, and `extract` has nothing to do for it. So the checkout, and the commit a build built, is at `worksrcpath` once `port fetch` has run.

What of that is documented: the Portfile reference's `git.url`, and `git.branch` as "the tag or other commit-ish that git should checkout"; the Guide's `worksrcpath`, "full path to extracted source code"; `port fetch`; and Git's `ls-remote`, `clone`, `checkout`, and `rev-parse`. That a Git fetch clones into `worksrcpath` is the one inference: it isn't said in so many words, but a build runs there, and 63 of the 147 Git-fetched Portfiles in the installed ports tree run `git submodule update` in `${worksrcpath}`, 57 of them in a `post-fetch`, so Base can't move the clone without breaking them. The guest reads `worksrcpath` itself through Base's Tcl interface (`mportopen`, the worker's `option`), as it already reads `test.run` and as the evaluator reads every option; that interface is the Base exception the project already takes, not a new one.

## What changed

- **`git.CloneCheckout`** says which commit a fresh clone checks out at a name, from `ls-remote --symref` of `HEAD`, `refs/heads/*`, and `refs/tags/*`, without cloning: a local branch first (only the default branch is one in a fresh clone), then gitrevisions(7)'s order, a tag before a branch, then checkout's guess of a remote branch. A whole commit is itself. A name no ref is that looks like an abbreviated commit is returned as that abbreviation, which only a clone expands; anything else is `ErrNoRef`.
- **`macports.PortInfo.GitSource`** and **`GitFetched`** read `fetch.type`, `git.url`, and `git.branch`, an unsettled one an error. `portedit`'s private `gitFetched` is gone in favour of it. So a Git-fetched port whose `git.url` or `git.branch` can't be evaluated leaves its check unresolved, as a `use_xcode` that can't be read does, where before it was planned and failed at fetch.
- **`model.GitSource`**, the assessment design's source record in its Git form: declared (`URL`, `Ref`) and observed (`Commit`, or `Abbreviation`, `ResolvedAt`, or `Unresolved` and why). `Expected`, `BuiltBy`, and `Moved` are its rules.
- **The plan.** `planning.Evaluate` reads the declared source; each `EnvironmentPlan` keeps it for the targets it builds (`Git`), and `Plan.GitIn` finds it. The engine resolves each repository and ref once per plan, with a minute's timeout, before the plan is validated, so every environment expects the same commit. One that can't be resolved is said to be; the check still runs, and its build records what it fetched. A plan validates that each source names a repository and is resolved or says why. `check --plan` shows a `Git` line for each target, and `--json` a `git` object per environment.
- **The contract.** `buildenv.Target.Git` gives a provider the expected source, and `Build.Fetched` takes the commit a fetch checked out.
- **Tart's guest**, after `port fetch`, reads the checkout's commit with `/usr/bin/git -c safe.directory=* rev-parse --verify HEAD^{commit}`, the checkout being MacPorts' user's and the guest root, as Base itself reads a port's files with Git, and reports it. Where it isn't the commit expected, or doesn't begin with the abbreviation, the target fails at fetch, "the source moved: git.branch v4 named … when the check was planned, and the fetch checked out …", nothing is built from it, and what needs it is blocked. A checkout it can't read is said in the target's log, and the build goes on. The provider refuses a reported commit that isn't one as trouble with the guest.
- **The verdict.** The runner judges every provider's result by the plan (`judgeSource`), as it judges tests: a build that fetched another commit fails at fetch, whatever the provider said. It is a verdict, not infrastructure: another attempt would expect the same commit and fetch the same other one, and nothing about the environment is wrong. A new check resolves the ref again and builds what it names then. A provider that doesn't say what it fetched leaves the result standing for its own check, and the check says so.
- **Inputs.** `TargetInputs.Fetched` records the commit, left out when empty, so every key recorded before is the same key. A provider that says what a build fetched but not which ports were active, as a person's command, now has its inputs kept too, with `Active` nil, which `Complete` now reads as unknown rather than none; every recorded input came through `Consumed` and has a list.
- **Reuse.** `reuse.Current` reuses a Git-fetched target's build only where it recorded the commit the plan expects; one recorded before, or by a provider that couldn't say, is never reused for a Git-fetched target, and archive ports are as they were. `reuse.Choose` also rebuilds what was built against an old build of a Git-fetched target: a target reuses its build only where the archive of the Git-fetched one active then was made by a build of the commit expected now, and what needs a target rebuilt for that reason rebuilds too.
- **Evidence.** `engine.Counts` lets an earlier check of the same files fill in a Git-fetched target only where its build recorded the commit the newest check expects. `dockhand logs` says under each Git-fetched result what it fetched, or that its provider didn't say, and `--json` gives `git` and `fetched`.
- **The command provider**'s request gives each Git-fetched target `git: {url, branch, commit}`, and its result may say `fetched`; the engine judges it as Tart's. [Command provider](../command-provider.md).
- **The GitHub provider** can't say what MacPorts' workflow fetched, so it never reports one; the check and `dockhand logs` say so, and such a result stands for its own check alone. [github provider](../github-provider.md).

The guest's `VerifierProtocol` stays 2, and its pin is updated with why: the change judges only Git-fetched ports otherwise, and what the program recorded of those before stands for no later check anyway, since it recorded no commit. Raising it would have ended reuse and evidence for every port.

## Not in this batch

- **Preparation's release and the plan's commit** aren't compared: an update prepared at a tag's old commit is checked at its new one, and the check records which. Saying that the two differ is the observed source's, in item 9's step 3.
- **A tag moved after a check and before `submit`** isn't caught: submit reads the check's evidence, which records the commit it built, without resolving the tag again. Binding publication to the source goes with step 3's fingerprint.
- **A target built against a Git-fetched one, filled from an earlier check** (`Counts`) is taken as before; only reuse follows the Git-fetched port's commit to what was built against it. A branch whose Git-fetched port needs checking again can't be submitted until it is, and that check rebuilds what was built against it.
- **Omitted targets.** A target `--only` left out has no expected commit in the newest plan, so an earlier result fills it in as before.

## Proven

- **Checks:** the full suite with `DOCKHAND_TEST_MACPORTS_TCLSH=/opt/local/bin/port-tclsh`, `go vet`, `make fmt-check`, `vendor-check`, `deadcode`, and `lint` pass.
- **New tests:**
  - `git.CloneCheckout` against Git itself: for thirteen names, what it resolves is what `git clone` and `git checkout -q` leave HEAD at, the default branch over a tag of its name, a tag over a branch of its name, annotated tags peeled; a whole commit asks nothing of the remote; an abbreviation; no ref; a remote that can't be read;
  - `model.GitSource`'s rules, the plan's validation of a source, and the inputs key unchanged without a commit;
  - `macports.PortInfo.GitSource`, and planning carrying it into each environment's plan;
  - the guest, under MacPorts' `port-tclsh` with a real checkout: the commit reported, an abbreviation met, a moved source not built and its dependent blocked, an unreadable checkout building as before;
  - the Tart provider passing the expected commit and reporting what the guest fetched, and refusing one that isn't a commit;
  - reuse: a moved tag, a result without a commit, an unresolved ref, an abbreviation, and what was built against the old build, directly or through another target;
  - the engine: a plan resolving the tag, again after it moves, and a missing tag; **the acceptance fixture**, a moved tag not letting earlier build evidence stand for the newly resolved commit; a build that fetched another commit failing at fetch; a provider that doesn't say, said and never reused; an earlier check filling in only for the commit expected;
  - the command provider's request and reported commit, end to end; and the plan's and logs' words and JSON.
- **Mutation testing:** 47 mutants, each flipping one decision and run against the tests that should catch it, the file restored from a copy after: the resolution's rules (a local branch first, tags peeled, checkout's guess, the default branch, abbreviations); `GitSource`'s rules and the plan's validation; `Complete` reading nil as unknown and `reuse.Inputs` keeping it; `Current`, `Choose`'s rebuilding, and `builtAgainst`'s archive and commit; the runner's judgment, what it keeps, and for which targets; `Counts`, `readFetched`, and `fill`; resolution in the plan and planning's carrying of it; `macports`' reading; the Tart provider's and the guest's check, report, and scope; the command provider's request, report, and refusal; and the logs. Four survived at first and are killed by tests added for them: `reuse.Inputs` reading no list as none, a blocked Git-fetched target being said not to have reported a commit, a commit a provider reports of a port fetched otherwise being kept among its inputs, and the engine taking what isn't a commit as one.
- **Not run live.** The guest's reading of a real MacPorts Git fetch in a Tart guest wasn't exercised here: its tests run the shipped program under `port-tclsh` with MacPorts' `worksrcpath` and `port` stood in for. A revbump of a small Git-fetched port checked with `--on tart`, `py-scikit-hep-hepunits` for a tag or `edid-decode` for an abbreviated commit, shows the plan's `Git` line and, in `dockhand logs`, the commit the guest read.
