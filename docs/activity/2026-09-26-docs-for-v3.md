# 2026-09-26: documentation for v3

Roadmap step 7. It waited for step 5's path to work end to end on real work. Five one-port updates had been submitted with v3 and merged, and a two-directory branch had been checked on two releases, so the documents that still described v2 were rewritten or retired.

## Rewritten

- **`README.md`** is v3's: what dockhand does, getting started (`init`, `providers setup tart`, `auth login`), an update from start to finish, where checks build, keeping up with your ports through `outdated` and `serve`, the other kinds of change, requirements, and installing. The banner saying v2 was the working tool is gone. v2 is mentioned once, with how to build its tag.
- **`docs/usage.md`** is the guide to v3's commands, written from their help and checked against the code where the help is terse. It covers branches and how a command finds one, each authoring command, `status`/`watch`/`diff`/`impact`, checks (what is captured, what is built, where, the `--on` forms, the results), the three providers, `tidy`, `submit` and the pull request body, `serve`, cleaning up, scripting (the JSON envelope and exit codes), and every setting and environment variable.
- **`docs/architecture.md`** is new for v3. It takes over from v2's architecture, component map, and state design: the layers, the records, a check from capture to evidence, authoring, submitting, serve and coordination, and where everything is on disk.
- **The main help** no longer says v3 is being rebuilt and that v2 is the working tool. It says how to begin, the four commands of an update, and where the guide is. Its test now checks for that, and that `v2-final` is gone.
- **`development.md`**: the acceptance test is v3's `provider/tart` `TestLiveCheckInATahoeGuest`, not v2's `verify/tart` one, and the section on state describes v3's store and its forward-only schema files.
- **`design-v3.md`** no longer says nothing in it is implemented. The roadmap's and the principles' opening links point to the v3 documents.

## Retired

`architecture.md`, `cli-design.md`, `components.md`, `state.md`, `operations.md`, `github-verification.md`, `human-corrections.md`, `target-workflow.md`, `output.md`, and the old `usage.md` moved to `docs/v2/`, with a README saying what they are. Every relative link to them, in activity notes and reviews too, was rewritten to their new place, and theirs to the rest of `docs/`. A check of every relative link in the repository's Markdown found none broken by the move. The links it did find broken were already broken: reviews that point at v2 source files deleted in step 4.

`output.md` was not in the roadmap's list, but it is v2's output contract, with `bump`, `-v`, and `--trace`. The one code comment that cited it, on `model.EventLevel`, now names its new place.

Left where they are: the design records for packages v3 kept (`bump-planner.md`, `bump-coverage.md`, `dependency-preparation.md`, `portindex.md`, `workspace-design.md`, `macports-compatibility.md`), which describe code still in use, and the provider documents, which were written for v3. `resolution-design.md` stays too for now: it is a v2 design that was never built, and the one comment citing it is in `workflow`, so it goes when that package does.

## Fixed on the way

`dockhand config` listed ten settings. It left out all of `[serve]`, `[providers.tart]`, and the two providers' `capacity`, so a person reading it couldn't learn they existed. It now lists every key the file takes. Two defaults it gave were wrong:

- **`check.on`** said "command, when [providers.command] is set up". Without a command provider the default is Tart on this Mac's release, and it now says so.
- **`worktrees`** said `~/src/macports-branches`, whatever the clone's location. The default is `macports-branches` beside the clone, wherever that is.

The config test checks the new keys, both defaulted and set.

## Found, not done

Seven v2 packages are still in the tree though nothing in the binary imports them: `state`, `workflow`, `verify` apart from `verify/staging`, `publish`, `assess`, `git/changeset`, and `macports/dependents`. `go list -deps ./cmd/dockhand` shows it. Removing them is the rest of step 5's replacement of v2's engine, and the roadmap now lists it under step 7.
