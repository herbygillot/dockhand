## What changed

- **lima's patches read as not applying, and built** (finding 4). golang's PortGroup sets worksrcdir to `gopath/src/<package>`, which no archive holds, and its post-extract moves the archive's top directory there; the patch check found no member under worksrcdir and patched nothing. A source directory no archive holds is now read as the archive's top directory, as extract.rename reads one. A patch that reads as not applying is no longer worded as "the build fails" beside a "·" that holds nothing: it says a check shows whether the patch phase fails.
- **garage's update was refused** (finding 1). `gitea.setup` wasn't a version input; it is now, with sourcehut, notabug, cgit, crossgcc, crossgdb, elpa, and luarocks's setup, every PortGroup setup that carries a version. garage's release then came from a livecheck listing, which names no tag, and regeneration's check required the PortGroup's composed `git.branch` to equal that empty tag; it's compared only where the release names one, and the refusal now says what moved, field by field. `dockhand update garage --new --plan` plans 2.4.1 with its crates.
- **fnox's post-fetch was refused** (finding 2). A Git-fetched port's post-fetch that only runs `system -W ${worksrcpath} "git submodule update --init"`, with `--recursive` or a `--depth`, is standard, said as a guard: "post-fetch checks out the Git submodules the commit pins". The evaluator now ships post-fetch hooks' bodies, as it ships pre-fetch ones, so they can be read; any other post-fetch is refused as before.
- **halloy's two crate revisions** (finding 3). The refusal read the current version's Cargo.lock, checking the existing block, and the update after it the new version's: both were right, and the refusal didn't say whose lock it read. It now says "checking the existing cargo.crates against <version>'s source, the version now".
- **A rate limit read as a login wanting** (finding 5). submit, review, and finding the fork say "submit waits on GitHub: GitHub's rate limit resets at …" where it was "submit needs your GitHub login". Remembering the login within a process was tried and dropped: the client checks the credential each time by design, which the tests hold.
- **configure.ac's change said what it asks** (finding 6). `project.ReadAutoconf` reads the options (`AC_ARG_ENABLE`, `AC_ARG_WITH`), pkg-config modules (`PKG_CHECK_MODULES`), and libraries (`AC_CHECK_LIB`, `AC_SEARCH_LIBS`) a configure.ac names, and the change says which were added or removed, or that none of them moved. It still holds.
- **Known issues, for after the release:** `checksums` doesn't regenerate a Rust or Go port's crates or modules after a hand edit of its version (finding 1's second ask), and a batch of submits with serve watching can spend the hour's GitHub requests (finding 5's second).
