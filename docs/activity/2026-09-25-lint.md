# 2026-09-25: golangci-lint in CI

Until now nothing linted `main`. CI ran test, format, vet, and build. The `.golangci.yml` that held v2's depguard layering and exhaustiveness kit exists only on the `v0` branch, and the container's golangci-lint was built with a Go older than 1.27, so it refused to run.

## What changed

- **`.golangci.yml`** turns on golangci-lint v2's standard set: errcheck, govet, ineffassign, staticcheck, and unused. Each exception says why it exists:
  - staticcheck checks for bugs and deprecations; its quick fixes (QF) and style checks (ST) are off;
  - govet's `inline` analyzer is off; it reports `//go:fix inline` directives it can't apply, which is a note for gopls;
  - the `std-error-handling` preset leaves Close, Flush, `os.Remove(All)`, and the print family unchecked;
  - errcheck also skips `coord.Session.End` and `Release`, both best effort (a lease expires, a dead pid is noticed), and quitting an FTP connection whose download is done;
  - test files are exempt from errcheck: their fake servers and helper processes drop errors, and the test fails on what the code does instead.
- **`make lint`** runs golangci-lint v2.14.0 by version, as `deadcode` runs its tool. It builds it with this module's Go through `GOTOOLCHAIN`. Otherwise `go run` builds it with Go 1.26, the version its own go.mod asks for, and it refuses a 1.27 module. CI runs `make lint` after vet.
- **What it found, fixed:**
  - two ineffectual assignments in `verbs_test.go` and one in `workflow/continuation.go`;
  - a field (`archivePlan.sources`) and a type (`portfile.checksumPair`) nothing used;
  - `assess` deferred a probe's Close before checking the error. Close is nil-safe, so this wasn't a crash, but it now defers only on success;
  - `config.Serve.Time` drops Sscanf's error on purpose, and says so: Load checked the form;
  - go-github's deprecated `Ptr` gave way to Go's `new(value)` in `verify/github`'s tests;
  - the `ripemd160` import carries a nolint: MacPorts checksums include rmd160, so the deprecation doesn't apply.

## Decisions

- **Not the v0 config.** Its depguard rules name v2's package layering (`verdict`, `record`, the analyses), which v3 is replacing. Porting them now would lint rules for packages on their way out. v3's layering, meaning `model` and `store` never import `engine`, and `engine` never imports `command`, can get its own depguard rules once step 5's packages settle.
