# 2026-10-02: the suite made fast first (batch 49)

Batch 49 of the [roadmap](../roadmap.md), the first of the order the person asked for re-synthesized ("Move the test-suite speed recommendations to be implemented along with the test plan"), so every batch after it runs a faster suite.

## Measured on the person's Mac

The test suite analysis measured on Linux and asked for three Mac measurements first. On this 18-core Mac, with MacPorts' tclsh:

- **Per package, the full suite:** engine 338 s and command 280 s, past twice Linux's 145 s and 110 s; every other package 30 s or less (editprep 30 s, buildenv/tart 26 s, portedit 15 s), where Linux had portedit and editprep at a minute.
- **Fixtures on a RAM disk,** engine and command alone: engine 314 s to 284 s, command 264 s to 238 s, about a tenth. `F_FULLFSYNC` isn't where the time goes; git processes are. So relaxed durability for fixtures goes last, as the analysis said it would unless the RAM disk halved them.
- **Engine in parallel:** below.

## What changed

- **Engine's tests run in parallel.** All 230 call `t.Parallel`. The eight that set `DOCKHAND_INDEX_CACHE` set the engine's new `Options.Indexes` instead, which the index stager and cleanup read before `IndexCache`'s default; no engine test writes the environment, the working directory, or a package variable. 338 s became 115 s, twice, and the package is clean under `-race` (218 s).
- **`make test` shards the command line's tests,** whose package-level seams and `HOME` keep them in one process each: `tools/shard-test.sh` builds the test binary once and runs `COMMAND_SHARDS` processes of it, six by default, each with every sixth test, beside the other packages' `go test`. 280 s became 61 s (55 s at eight). `make test-race` does the same with `-race`. A plain `go test ./...` is unchanged.
- **`command.Run` takes only the arguments it's given.** Cobra reads `os.Args` when given nil, so a bare `dockhand` in a test read the test binary's `-test.run`, and failed in a shard; `TestBareDockhandSaysHowToStart` and `TestStatusFollowsABranchThroughItsWork` both called it so. Run now passes an empty list, never nil; the binary always passed `os.Args[1:]`.
- **Two Linux-only failures,** found by the analysis: the replay test reads an author date as seconds, since git spells UTC `Z` or `+00:00` by version, and the guest channel's tests, which run a Mac guest's scripts with BSD `stat`, skip off a Mac.
- **Development.md** says how the suite runs, and that a new engine test calls `t.Parallel`.
