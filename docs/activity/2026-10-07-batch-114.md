# 2026-10-07: a new login after a rejected one, read (batch 114)

From the rc8 full stage's D-C3. With dockhand's authorization revoked, serve said the rejection once, as it should; after a fresh device login, `setup github` writing the Keychain at 20:05:06Z, the same serve never said it was logged in again. Not for rc8, whose run goes on.

## The cause

serve reads who its login is each minute, and a new token is asked of GitHub at once (`IdentityWatcher`); a test of the gate, rejected then the account, says "logged in again", and did before. What stood between serve and the new login is the credentials' renewal. A login renewed that the Keychain refused to save, as a launchd agent's save can be refused, is held in memory, since the refresh token it replaced is spent, and saved the next time the login is asked for (`pendingLogin`). It was read in front of the store: a login saved since, by `setup github` in a terminal, was never read, and once the Keychain took a save again, the held renewal, of the revoked login, was written over the new one. Prime-time's other reading, an error that isn't a rejection or no login, kept the state in silence too, which is the second fix.

## What changed

- **A login saved since a held renewal is the store's.** The held renewal remembers the refresh token of the login it renewed; a login in the store with another is one saved since, which is used, and the held one goes, never written over it.
- **serve says once when it can't read its login,** for any reason but no login or a rejected one: "serve: couldn't read who its GitHub login is (…); it goes on as it was, and reads it again each minute", said again when the reason changes. status says it after serve's state, "couldn't read its GitHub login: …", and `--json` has it as `serve_state.login_problem`; it clears once the login reads.

## On following a closed pull request

serve follows the pull requests of open and closed branches alike (`RefreshPullRequests`), since a closed pull request may be reopened, and a closed branch is kept until `clean --closed` takes it. #2's branch, closed in rc5, was never cleaned on the kept account, so serve still reads it; that's as meant.
