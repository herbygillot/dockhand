# 2026-10-02: the change record sees a port's code, and its readers (batch 62)

Batch 62 of the [roadmap](../roadmap.md): the rest of the implementation plan's step 1, the change record's other producers and readers, and the sweep that proves it.

## What the sweep found

The plan asks for a sweep of the tree's multi-subport families, comparing directory scope with record scope and reading every disagreement. It replayed the 222 commits since 2026-08-01 that touch any of the 575 directories with a `subport`, each as a revision against its parent, 336 directory changes in all.

With batch 61's record, which compared only the options dockhand reads, 24 of them found no subport changed where the commit plainly changed something: a phase's body (rust's bootstrap strip, kubectl-1.19's BSD date fix, llvm-21's `-nocomplain`), a variant's (python315-devel's `+experimental_jit`), an option dockhand doesn't read (`conflicts_build ccache` for py-pyarrow, `compiler.blacklist`), or a patch's contents (mysql8, mysql9, mysql-innovation, glib2, mlx). Readers would have said such a branch changed nothing. So:

- **The evaluator reports the port's code** (`dockhand.code`, `evaluator.tcl`'s `code_fingerprint`): a checksum of each hook's and variant's body, the `userproc-` and `variant-` procedures Base makes of them (portutil.tcl's `target_provides` and `variant`); one of every other procedure, the Portfile's and its PortGroups'; one of every option's value but those dockhand compares by name; and one of each patch the port applies, read from its files. Each is read with the evaluation's root and build directory written as placeholders, so two evaluations of the same files read alike. Tcl's own CRC-32 and Adler-32 make the checksum, so no package is needed.
- **`source_date_epoch` is unstable**, the Portfile's modification time, which is when the evaluation's files were written: it moved in every evaluation, so the sweep found it, and the record says it apart (`SubportChange.Unstable`) rather than as a change.
- **The code is a change record's alone.** `fidelity.Changes` compares it part by part, "code userproc-post-org.macports.destroot-destroot-1"; `ComparablePort` leaves it out, so an edit's fidelity, `Equivalent`, and `samePort` read as before, and the update path is unchanged. `ChangePolicy` is 2.
- **A record that finds nothing isn't "nothing changed".** What the sweep still couldn't attribute is a change only another context sees: openssh's block for macOS 27, py-tkinter's and qbs's for older releases. Such a directory keeps its text scope, and status says "(no change this Mac's evaluation sees)".

With these, the same 336 directory changes read: 202 records name every subport the text does, 128 name fewer, and 6 find nothing. The 128 were read where they could mislead, and they're right: assimp's revbump changes 2 or 4 of each qt family's 53 to 86 subports, kubectl-1.36's update changes kubectl-1.36 alone, and terraform-1.16.3's changes terraform-1.16 alone, where the stub's code read as moved until the build directory and `source_date_epoch` were dealt with. The 6 are each a block another context evaluates: openssh's and rust's for macOS 27, mysql9's for Sonoma, py-tkinter's and qbs's for older releases, and glib2's patch, applied only without its default `+dbus`. They keep their text scope.

## What else changed

- **update, checksums, and revbump prime the record** from their own evaluations, before and after the edit, where the branch was as its base, as their comparison primes the assessment; elsewhere the record is made from the base after the edit, and one that can't be made is said with `--verbose` and fails nothing.
- **Readers:**
  - `BranchesChanging`, which `bump`, `update --outdated`, and an authoring command choosing its branch use, and `-p` will, reads the record of a branch's files as they stand: a branch updating terraform-1.16 changes terraform-1.16, not terraform-1.17. It reads a branch's files for their tree only where a record might name the port.
  - `status` shows the subports a record names, else the directory's port marked "(not yet evaluated)"; `--json` adds `changed_ports` and `port_notes`. Status evaluates nothing.
  - `tidy` names a group by its record's subports, so a hand edit to zdemo-devel's block is "zdemo-devel: update to 2.1", where it found no subject before.
  - `submit`'s ports, its title, and its search for other pull requests read the records.
- **`SubportChanges` names the main port by its directory,** as MacPorts requires, rather than by the evaluated target.

## Verification

- With MacPorts' tclsh: the evaluator's code report, hooks, variants, procedures, options, and the unstable epoch; `BranchesChanging` before a record, with it, and after the files move on; tidy's subject for a hand edit in a subport block; revbump's record from its own evaluations.
- fidelity: code compared part by part, the unstable part no change, and an edit's fidelity unaffected.
- `make test` with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.

## Still open

- A procedure the Portfile defines is compared with every other procedure, as one part, so the record says a procedure moved without naming it.
