# v0.5.0 part 1, item 1: the review's small fixes

At the person's "Yes, start." (2026-10-17), while rc4 is vetted: v0.5.0's
part 1, items 1 to 3, none of which migrates; X1 and `clean --delete`
wait for v0.4.0's tag. From Codex's review of 832f059e, as the coalesced
roadmap (8ac426e2) placed them.

- **A Cargo reading that found no program counts none.**
  `Reading.CargoProgram` read a nil `Programs` as every package a program,
  for readings before `Programs` was kept, which ReaderVersion 7 no
  longer serves; a source whose programs are all `[[bin]]`s with paths of
  their own has none, and its libraries read as programs. Nil is none now.
  TestAReadingKnowsWhichCargoPackagesArePrograms.
- **A program added is a notice.** `cargoBinaries` says "new binaries"
  where nothing was removed, and the assessment says it, holding nothing:
  "the Portfile installs what it names". One that removes or renames
  holds as before. assess.Policy is 19, so stale assessments are made
  again. TestACargoProjectsChangedBinariesAreSaid,
  TestACargoProgramOnlyAddedHoldsNothing.
- **A guest that can't list its active ports doesn't report none.**
  guest.tcl's `consumed` reads `port -q installed active` through `known`,
  which errors where `fact` returned "", so the verdict stands with its
  inputs unknown (no `active`), and isn't reused. VerifierProtocol stays:
  nothing is built or judged otherwise, and only a failed list differs;
  guestPin is updated. TestAVerdictRecordsThePortsActiveAsItBuilt.
- **A renewed GitHub login is one per process** (CX-11's first half). The
  pending login a refused save leaves is the process's for each store and
  key (`pendingFor`), read lazily by `SystemCredentials.renewal`, so
  credentials made apart, as serve's identity watcher's, share it, where
  the watcher read the spent login. TestARenewalTheStoreRefusedIsTheProcesss.

The three found after rc3 are in v0.4.0 (rc4), so nothing of them is left

## A [[bin]] beside src/main.rs adds a program (field testing at beb6e7bc)

`bump ratty` held on 0.6.0 with "ratty-mcp added; ratty removed": its
Cargo.toml added `[[bin]] name = "ratty-mcp"` and kept src/main.rs, so
Cargo still builds `ratty` (the check's destroot installed it), but the
comparison took the [[bin]]s as all of the package's programs.
`CargoManifest.Programs` (project/cargo.go) is the owner's answer now: the
[[bin]]s, and the program Cargo infers from src/main.rs, named for the
package, beside them, unless `autobins = false` or a [[bin]] builds
src/main.rs itself (by its path, or by the package's name with none).
`cargoBinaries` reads it; assess.Policy is 21. Where the directory's
program is only a src/bin, Programs still counts the package's name, as
the reading keeps src/main.rs and src/bin alike (`Programs`); telling
them apart needs ReaderVersion 8. portcreate's `Binaries` is unchanged.
TestABinBesideMainAddsAProgram.
