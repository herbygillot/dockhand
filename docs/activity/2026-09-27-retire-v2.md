# 2026-09-27: retiring v2

Roadmap item 5. v2's orchestration is unused by the binary, but some of its packages are still live. Its first step is v2's recovery promises, as v3 tests, so nothing v2 guaranteed is lost with its code.

## v2's recovery promises, as v3 tests

**What v2 promised.** The publication and correction tests in `workflow` promise these of a publication:
- *PublicationRecoversLostPRResponseWithoutAnotherWrite*, and *ManualPublication…ResumesAfterLostPRResponse*: a reply lost after GitHub opened the pull request is recovered without writing it again.
- *UncertainPRRequestIsRepeatedOnceTheForgeShowsNoPullRequest*: a request whose outcome is unknown is made again only once GitHub shows no pull request.
- *PublicationPushesConfirmsAndRetainsAssociationAcrossRestart*: a pull request opened and not recorded is associated again after a restart.
- *CompetingPublicationDriversUseOneWrite*, and *ConcurrentEquivalentSubmissionsConverge*: two publications of one change make one pull request.
- *PublicationRejectsMovedSourceRemote…* and *ManualPublicationRejectsMovedBranchesBeforeRemoteEffects*: a branch or fork that moved is refused before anything is pushed.
- *ExistingPRRejectsUnexpectedRemoteHeadDuringPlanning*: someone else's push to the pull request stops the next one.
- *…PreservesHumanPRBody*: a person's edits to the description are kept.
- *ReassociatePreservesPRRemoteBranch*: a renamed branch keeps its pull request's remote branch.

The rest are the queue's own: cancellation, leases, admission, and rate-limit refusals. v3 runs a submit in one command and has no queue for them to apply to.

**What v3 already did, and tested.** The roadmap said v3's recovery was untested; three were tested:
- a push refused when the fork's branch moved, and the next plan blocked with "someone else pushed to #34901";
- a person's description kept (`TestSubmitUpdatesThePullRequestAndKeepsAPersonsDescription`);
- a renamed branch keeping its pull request (`TestARenamedBranchKeepsItsRecordAndItsPullRequest`).

**What v3 lacked, and now has.** When opening a pull request failed, v3 reported the error, and only a second `submit` found the pull request, by its head branch. Now `ApplySubmit` reads it back at once (`createdAnyway`), the rule item 3 applies to uncertain commits. After a failed create, it looks for an open pull request on the fork's branch:
- one found is the branch's, recorded, and not written again;
- with none, the failure stands, and says `dockhand submit again finishes it`.

That covers a reply lost after GitHub opened the pull request. It also covers two submits racing: GitHub refuses the second pull request from one head, and the second submit finds the first one's. The second's push is already a no-op, since `git.Push` treats a fork branch holding the commit as pushed.

**Where recording fails.** When recording the pull request fails after it is open, the error now says so: "#34901 is open with 1a2b3c4, but recording it failed: …; dockhand submit again finds it and records it". It used to be the store's error alone.

**Tests** (`engine/submit_recovery_test.go`), with a fake GitHub that can lose a reply, fail before sending, and refuses a second pull request from one head, as GitHub does:
- a lost reply read back at once, and the next submit writing nothing;
- a request that never reached GitHub, made again by the next submit without pushing again;
- a pull request opened but not recorded, found by the next submit and left as it is;
- two submits racing, ending with one pull request;
- a branch that moved after its plan, refused with nothing pushed.

The first and fourth fail with the read-back disabled, checked by hand once.

## The order, re-settled

The roadmap moved `record`'s live types first, then gave `verify/staging` a home, settled the tools, added a check against new imports, and deleted last. But only three things outside v2 import v2 packages other than `record`: the Tart provider (`verify/staging`), `tools/stateperf` (`state`, `workflow`, and `verify`), and `tools/survey` (`assess`). With those three settled, the v2 packages are imported only by each other and can go whole. `record` is then imported only by v3, and its live types move without aliases kept for v2. So:
1. `tools/stateperf` is retired;
2. `verify/staging` moves out of v2;
3. `assess` folds into `tools/survey`;
4. the v2 packages are deleted;
5. `record`'s live types move to their owners, and `record` goes.

The check against new imports of retired packages isn't needed: they won't exist.

## tools/stateperf is retired

It measured v2's SQLite state and workflow cycles, which the binary no longer has. v3's store is a different schema, measured where it matters by its own tests. The probe and its measurements stay in history: its last commit is the one before this, and `docs/performance` keeps what it found.

## Staging lives beside the providers

`verify/staging` is `buildenv/staging`: it prepares the indexed source archive a provider carries into a guest, which only the Tart provider does. It sits beside the providers, not among them, and `buildenv`'s boundary test holds it to their rules: no engine, command layer, store, or coordination. Its comment no longer says "verification providers", v2's term. v2's `verify/tart` takes the new path until it goes.

## assess folds into tools/survey

`assess` was about 400 lines: the assessment service and its journal. Only `tools/survey`, the oracle's whole-tree measurement, used it. Its files are now the tool's own (`tools/survey/assess.go`, `journal.go`), in package `main`.
- The tool has a function called `survey`, so the moved file imports `macports/survey` as `portsurvey`.
- Its dependency test named the packages `assess` could import. It now names what the whole tool must not import: the command line, the engine, the store, coordination, or a concrete forge client.

The survey runs as before; its journal and flags are unchanged.

## The v2 packages are deleted

With `tools/stateperf` retired, staging moved, and `assess` folded into the survey, nothing outside v2 imported its packages, tests included. They are deleted: `workflow` (with `choice`, `policy`, `retention`, and `view`), `state` and `state/sqlite`, `publish`, `verify` (with `github`, `tart`, and `ledger`), `git/changeset`, and `macports/dependents`. That is 35,477 lines. Their timing-sensitive tests, which failed under load earlier this session, went with them. Commit `1cbcdf8b65` is the last with their code.

What else went with them:
- **Functions only v2 called**, which `make deadcode` found once v2 was gone: `macos.LaunchdServicePlist`, `macports.TicketURL` and `TracURL`, `macports.StubOf`, and the survey's `Result.Tally`. The launchd plist writer lost the keep-alive switch only the removed function set. `record`'s own dead methods go with `record`.
- **A direct dependency.** `go.yaml.in/yaml/v3` was imported only by v2; it stays, as an indirect dependency of another.
- **v2's resolution design** moves to `docs/v2/resolution-design.md`, with the code it described. Its links, and the five documents that link to it, are fixed.

Nothing else in the tree is dead: every package is in the binary or a tool, but `testsupport`, which tests share.

**Links left as they were.** Reviews, activity notes, a performance note, and one v2 document linked into v2's code; 26 of those links lead nowhere now. That follows what the earlier deletions did, which left 27 such links. They are history, as written then. Pointing them at commit `1cbcdf8b65` on GitHub would keep them useful, if that's wanted.

## record's live types move to their owners, and record goes

With v2 deleted, `record` was imported only by v3: 110 files in 22 packages. Most of what they used was already `model`'s under another name. `record` aliased `Source`, `Target`, `Platform`, `ObjectID`, `DeveloperTools`, `RepositoryID`, `CompareTargets`, and `Digest`, and its own comment said the shared vocabulary lives in `model`. What `record` owned went to three places, each already imported by every user, so no neutral package was needed:
- **`model`**, as the vocabulary of a port update:
  - `Release`, and `ReleaseSelection`, which was `Selection`, renamed since a bare `Selection` in `model` would be ambiguous. It is embedded, so a release's JSON stays flat.
  - `ReleaseListing`, and the release scope: `ReleaseScope`, `ReleaseInput`, `ReleaseMember`, and `ReleaseState`.
  - `UpdateAction`, which was `Action`, with `Bump`, `BumpRevision`, and `RefreshChecksums`, and `EditIntent`.

  `macports` couldn't have them: it has its own `Selection` type and a `ReleaseState` function. `upstream` would have been the natural home for a release, but `portedit` and `fidelity` would then pull in the forge clients and network code for a value type.
- **`forge`**, beside its `PullRequestInput`: `PullRequest`, `PullRequestRef`, `PullRequestState` with its values, `PullRequestStatus`, `CheckSummary`, and `PullRequestContent`, which was `PublicationContent`. `model.PullRequest` is dockhand's own record of a branch's pull request, so the forge's view couldn't be in `model`.
- **`macports/commitmsg`**, which parses them: `Reference`, `ReferenceRelation`, and `ParseReferenceTrailer`.

**What didn't move:**
- `Action`'s `Verify`, `Publish`, `Rebase`, and `Amend` values.
- `PullRequest`'s `ID`, `ChangeID`, and `ObserveAfter`, and `PullRequestUnknown`.
- `forge.PullRequestInput`'s `ActionID` and `ExpectedRemoteHead`, which v3 never set.
- The release scope's `NeedsSharedRelease`, `BuildTargets`, `RequiredTargets`, `Valid`, and `SameMembership`, and its coverage intents. Three tests used two of them to assert; they assert the same things directly now.
- All of v2's records: changes, jobs, attempts, publications, leases, resources.

`record`, 1,867 lines, is deleted.

**Knock-ons:**
- `eval` had a local variable called `model`, which now shadowed the package; it is `platform`.
- The engine's and command layer's import lists lose `record`.
- `outdated`'s own dependency test allows `model` in its place, and no longer names v2's "app, workflow state".

**The check the roadmap planned is moot.** It was to refuse new imports of the retired packages, between moving `record` and deleting v2. With the order re-settled, nothing was left to import.
