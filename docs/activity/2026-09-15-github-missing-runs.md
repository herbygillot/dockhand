# Missing GitHub run observations and recovery

Missing-run progress now identifies the accepted fork, branch, commit, and durable submission timestamp, and distinguishes a confirmed push from an unexpected remote head. After a successful run lookup returns no match, the provider inspects the current workflow reference and reports active, disabled, replaced, or missing/inaccessible conditions with the SDK-supplied workflow URL when available. Temporary lookup errors retain their cause for normal workflow backoff.

A remote-head conflict keeps observation pending without replacing that head. Current settings never retarget the accepted workflow ID or prove the absence of an earlier event. Missing runs have no elapsed-time failure cutoff; delayed matches can still be adopted after restart. Progress and documentation explain exact-job wait/cancel recovery. Cancellation remains available offline and does not delete branches, cancel shared remote runs, or revive tracking when late evidence appears. Automatic reruns and managed branch replacement remain deferred.
