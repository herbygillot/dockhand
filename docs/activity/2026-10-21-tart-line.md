# setup's Tart line, a line for each release

Herby, 2026-10-21 21:50Z: setup's `tart` line was "one big run-on". On
his Mac it listed six base images behind this Mac's MacPorts, each with
a rebuild, though no check builds in a base image where its release has
an Xcode image.

- `tart.Status` records each image's MacPorts from its record
  (`MacPorts`, by image name), and says the image a release's checks
  build in (`CheckImage`: the Xcode image wherever there's one), an
  image's MacPorts (`ImageMacPorts`), and whether it's behind
  (`BehindOf`).
- `tartReadiness` returns lines: the heading "✓ ready for macOS 12, 13,
  14, 15, 26, and 27", then, aligned, each release's name, the image its
  checks build in, and that image's MacPorts. Where that image is behind,
  its line says "older than this Mac's", with `RemakeWords`' rebuild
  indented under it, the Xcode note on a line of its own so no line runs
  long. Base images behind under Xcode images get one line, with no
  rebuild. A release to restore, and no image for this Mac's release,
  keep their words, on lines of their own. The not-set-up, Xcode-only,
  and no-image cases are one line, as before.
- `providerLines` aligns the lines under the first; setup's `--json`
  `providers` carries each line.

Tested with the six-release case (`TestProviderLinesSayOnlyTheImagesChecksBuildIn`)
and each of the earlier cases rewritten to the layout. Not yet read on
Herby's Mac: the next `dockhand setup` there shows it.
