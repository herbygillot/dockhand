# 2026-09-28: updating duckdb with dockhand

duckdb 1.5.6 was out, and the person asked for the update as a chance to use dockhand as a maintainer would and see how it goes. It ran against the real checkout and database, with a build from main. Each problem it found is fixed in its own commit, below.

## The first steps

- `outdated duckdb` answered in 12 seconds: 1.5.5 → 1.5.6, "DOCKHAND CAN update", against master fetched just then.
- `update duckdb --new --plan` showed the edit, the version and the checksums of the new 101 MB archive, in 24 seconds.
- `update duckdb --new` started `dockhand/duckdb-oyb8` from fresh master, made the edit, and compared the archives: "! upstream's CMakeLists.txt changed; the build may need the Portfile to follow". The change makes the unity build include its sources by relative path, for compiler caches, and needs nothing of the Portfile.

## `diff --archive` couldn't read GitHub's tarballs

`diff --archive duckdb`, to see what the flagged change was, failed: "archive: source-… has a member outside it: duckdb-1.5.6/". Two bugs in `archive.Extract`:
- **Directory members.** A tarball names each directory as a member ending in `/`, as GitHub's do. `Member.Clean` refused any name `path.Clean` would change, so the directory `duckdb-1.5.6/` counted as outside the archive. A member for the root itself, `./`, as some tarballs have, did too. The update's own comparison skips what `Clean` refuses, so it worked; extraction refused.
- **GitHub's pax header.** GitHub's tarballs, `git archive`'s, begin with a `pax_global_header` member. The shared top directory was taken from the first member, which made it that header. So nothing was taken to share a top, and every file was reported added or removed: 29,133 of them.

`Clean` now takes a directory's trailing slash, and `Extract` skips a root member. The shared top is decided by the regular files alone, and a file at the root means there's none. A member that would leave the archive is still refused, a directory as a file.

The same comparison now reports 399 files: 168 changed, 83 added, 148 removed. `TestExtractTakesDirectoriesAsTarNamesThem` builds a tarball as GitHub lays one out, with the pax header, directory members, and a `./` root. It fails with either fix undone.

`git diff --no-index` labels a file only one side has with that side's prefix twice (`b/… b/…`). That's git's, and left as it is.

## A worktree didn't count as "here" under `MACPORTS_TREE`

Run inside the branch's own worktree, where `start` suggests going, `diff` answered "No tracked branch: master is not tracked … or run this in the branch's worktree". The person's shell sets `MACPORTS_TREE` to the checkout, as usage.md says to, and dockhand took that checkout, which has master out, for "here". So in a person's own setup, no command could find the branch from its worktree.

Without `--tree`, a command run in a worktree of the checkout `MACPORTS_TREE` names now works in that worktree (`engine.Here`), whose branch is the one checked out there. Anywhere else, the named checkout is still used, and `--tree` still wins. `serve --install` keeps the main checkout whichever worktree it's run from, since it installs `e.Clone()`.

`TestHereIsTheWorktreeACommandRunsIn` covers the engine's side:
- a worktree, and a directory inside it;
- a directory in no checkout, and one in another repository;
- the checkout named through a symlink, as `~/Source/ports` names `~/Source/macports-ports`.

`TestMacPortsTreeKeepsTheWorktreeYouAreIn` runs `path` with `MACPORTS_TREE` naming the checkout, in the worktree and outside it. It fails without the fix. Tests that set `MACPORTS_TREE` to a worktree, to get around this, still pass.

## A plan didn't say what upstream changed

`update duckdb --new --plan` showed the diff and nothing else. The update itself then flagged "! upstream's CMakeLists.txt changed". The engine compares the archives for a plan too; the command returned after the diff, before printing the comparison or the patches found not to apply.

A plan now prints both, as the update does: what a reviewer would ask about belongs in the look before. `TestAnUpdatesPlanSaysWhatUpstreamChanged` fails without it.

## Tidy, restore, and the check

- `tidy --plan` proposed one commit, "duckdb: update to 1.5.6", and `tidy` made it, with checkpoint tidy-5. Its `Generated-By` trailer ended in `+dirty`, since that dockhand was built with the fixes above not yet committed. `restore tidy-5` put the edit back uncommitted, the files unchanged, and `tidy` with a build from a commit made 9fa7e45 (tidy-6).
- `check --on tart` built it in a clone of the Tahoe Xcode image. check-5 passed in 6 minutes; duckdb declares no tests.
- `status` then said "passed for this commit", and named `submit` as what's next.

## The submit preview didn't say what upstream changed

`submit --plan` showed the title, the destination, the passed check, and no other open pull requests. It didn't show the CMakeLists.txt finding the update had flagged. `submit --passing` lists each branch's findings; a single `submit`'s preview, where a person looks at one before submitting it, didn't. And `--passing` left out archives that couldn't be compared, which D4 marks as a finding.

The plan now carries what each update's comparison found (`SubmitPlan.Upstream`). One reader of the edits gives it, and the holds too; `UpstreamFindings`, the command's own reader, is gone.
- The preview shows the findings on an `Upstream` line, each naming its port when the branch updated several. A branch whose archives showed nothing to look at says so.
- `--passing` shows the same lines, now including archives it couldn't compare.
- `submit --json` has `upstream`, by port.

A person's own submission still isn't held for them, as D4 has it. On the duckdb branch, the preview now reads "Upstream ! upstream's CMakeLists.txt changed; the build may need the Portfile to follow".

Tests, each failing with its part undone:
- `TestTheSubmitPreviewSaysWhatUpstreamFound`: the preview and its JSON;
- `TestTheSubmitPreviewGivesEachUpstreamFindingALine`: the lines, the ports, and nothing for a branch that compared no archives;
- `TestSubmitCheckPassingAndReady`: `--passing`'s line;
- serve's hold tests: the plan's comparisons.
