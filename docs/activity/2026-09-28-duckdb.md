# 2026-09-28: updating duckdb with dockhand

duckdb 1.5.6 was out, and the person asked for the update as a chance to use dockhand as a maintainer would and see how it goes. It ran against the real checkout and database, with a build from main. Each problem it found is fixed in its own commit, below.

## The first steps

- `outdated duckdb` answered in 12 seconds: 1.5.5 → 1.5.6, "DOCKHAND CAN update", against master fetched just then.
- `update duckdb --new --plan` showed the edit, the version and the checksums of the new 101 MB archive, in 24 seconds.
- `update duckdb --new` started `dockhand/duckdb-oyb8` from fresh master, made the edit, and compared the archives: "! upstream's CMakeLists.txt changed; the build may need the Portfile to follow". The change makes the unity build include its sources by relative path, for compiler caches, and needs nothing of the Portfile.

## `diff --archive` couldn't read GitHub's tarballs

`diff --archive duckdb`, to see what the flagged change was, failed: "archive: source-… has a member outside it: duckdb-1.5.6/". Two bugs in `archive.Extract`:
- **Directory members.** A tarball names each directory as a member ending in `/`, as GitHub's do. `Member.Clean` refused any name `path.Clean` would change, so the directory `duckdb-1.5.6/` counted as outside the archive. A member for the root itself, `./`, as some tarballs have, did too. The update's own comparison skips what `Clean` refuses, so it worked; extraction refused.
- **GitHub's pax header.** GitHub's tarballs, `git archive`'s, begin with a `pax_global_header` member. The shared top directory was taken from the first member, which made it that header. So nothing was taken to share a top, and every file was reported added or removed: 29,133 of them.

`Clean` now takes a directory's trailing slash, and `Extract` skips a root member. The shared top is decided by the regular files alone, and a file at the root means there's none. A member that would leave the archive is still refused, a directory as a file.

The same comparison now reports 399 files: 168 changed, 83 added, 148 removed. `TestExtractTakesDirectoriesAsTarNamesThem` builds a tarball as GitHub lays one out, with the pax header, directory members, and a `./` root. It fails with either fix undone.

`git diff --no-index` labels a file only one side has with that side's prefix twice (`b/… b/…`). That's git's, and left as it is.
