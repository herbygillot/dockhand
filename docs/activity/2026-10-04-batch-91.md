## What changed

- **What gathers uncommitted files abides by what Git ignores, and a test holds it.** The person asked that adopt, and any command that brings uncommitted files into source control, respect the tree's `.gitignore`, down to the subdirectory, as Git does. It already held: capture lists untracked files with `git ls-files --others --exclude-standard`, create stages with `git add` (never `-f`), and nothing else lists or stages working files. A fixture with a root `.gitignore`, one in a port's directory, and `.git/info/exclude` now checks that each ignored file stays out of a capture and its "Left out" line, out of `--include`, out of `git add --all` as create's move stages, and doesn't make a branch's worktree dirty for clean.
- **`--include` says why it refuses an ignored file**: "Git ignores it, so a check leaves it out as git add would; git check-ignore -v PATH names the rule", where it said only that the path wasn't untracked (`git.Repository.Ignored`, by `git check-ignore --stdin`).
- **Only `internal/git` asks Git for untracked files or stages them.** A guard test parses the module's code, outside `internal/git` and the test helpers, and fails on `ls-files`, `--others`, `--exclude-standard`, `check-ignore`, or `update-index` named anywhere else, or `git` run by `exec` directly. A command can't gather files around Git's ignore rules without it failing.
- **An editor's swap and backup files aren't listed as left out**: `.Portfile.swp`, `Portfile~`, `.#Portfile`, and `*.orig` (field testing's note 4: `office/tasksh/.Portfile.swp` was listed). A `.gitignore` that names them keeps them out of `git add` as well.
- **A plan requiring tests says which ports declare them**, "Tests jq, which must pass", beside "No tests" for those that don't, so "asks nothing" of a python stub isn't read as of the port (note 3).
- **review names the commits its upstream findings read MacPorts' ports at**: "Upstream, against MacPorts' ports at the pull request's bbbbbbb, off master at aaaaaaa". A dependency's version is read at the pull request's commits, so an older or merged one reads what master had then, transformers 5.3.0 where master had 5.18.0 by the time of #35088's review (note 1).
