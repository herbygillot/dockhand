# 2026-09-22: one transient root per process, swept when its process dies

## What was decided

The overlay examination left one gap: nothing swept what a process that
died without cleaning up left in the temporary directory, and a thousand
full-tree overlays from stopped runs proved it. The user chose the model:
one temporary root per process, every other transient directory created
inside it, and a clear line between that and the directories a person
comes back to.

## The split

Persistent, under configured homes and touched only by retention: the
state database and its backups, verification artifacts and logs beside
the database, the Tart pool, the GitHub verification log cache, and the
PortIndex cache in the user cache directory. Transient, under the run
root: workspaces and their overlays, materialized sources, the git index
and rebase directories of corrections, the go2port, cargo2port, and patch
check sandboxes, and the editor's message buffer. Eleven sites made these
with `os.MkdirTemp("")` before; each now asks the `scratch` package for a
directory under the process's root. Overlays were already made beside
their base and follow it in.

## How a dead root is told from a live one

The root is created hidden, a lock file inside it is taken with `flock`,
and only then is it renamed into view, so no sweeper can find a root
before its lock is held. The lock is released by the kernel on any exit,
SIGKILL included. A sweeper tries each root's lock without waiting: held
means a live process, taken means a dead one, and the root is removed
under that lock so two sweepers never remove the same root. A hidden root
without a lock is one being made this moment, or one abandoned in the
window before locking; it is removed only when older than ten minutes.

The first draft let a sweeper try the lock of a hidden root too, and
the full test suite, forty binaries starting together, showed why that is
wrong: the lock file exists for a moment before it is locked, a sweeper
took it in that moment, removed the file, and the process went on with a
root that was published lockless, twenty of them in one run. A hidden root
is now judged by age alone, and a test starts two dozen processes at once
and checks that every root they leave still holds its lock.

The first root a process opens sweeps first, so an ordinary command clears
what the last crash left, and `gc` lists stale roots, previews them under
`--dry-run`, and removes them. The command ends with the root removed, on
an interrupt as well, since the context's cancellation unwinds every
deferred close before the root goes.

## Legacy directories

Directories that builds before this one made directly in the temporary
directory carry no lock, so nothing but their age says a process is not
using them. `gc` removes them once they are an hour old, which outlives
any one operation of an earlier build; `--older-than` governs retained
evidence, VMs and diagnostics, and `--older-than 0` must not be the price
of clearing scratch. The thousand overlays from today's stopped runs went
that way.

## Checked

A dry run killed with SIGKILL one second in left its run root;
`gc --dry-run` listed it as a preview and `gc` removed it. The suite's
test binaries each leave a root that the next process sweeps, which is
the mechanism working as designed rather than a leak.
