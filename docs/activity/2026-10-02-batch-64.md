# 2026-10-02: naming a branch as the person decided it (batch 64)

Batch 64 of the [roadmap](../roadmap.md) corrects batch 63, which built the command-line UX review's §1 as its first draft. That draft is in docs/reviews/2026-10-02-command-ux.md, the review as written at 3c80520. The person had revised it in the review's thread before it was queued, and the revision is in the project's ux-review/command-ux-proposal.md. The coordinator caught the difference.

## What the revision decided, and what batch 63 had instead

- **`-b` takes an exact name, with shell completion.** Batch 63's `-b` also matched the start of a name, `#34901`, and `check-42`. The revision drops prefixes, since `<port>-<ID>` names collide by construction (`libuv` is a prefix of `libuv-devel-9x2m`). It drops `#` because the shell reads it as a comment, so `submit #34901` would submit the branch you're standing in. It drops check IDs because a branch may have moved since the check.
- **`-p/--port` picks the branch that changes a port, and `--pr <number>` picks the one tracking a pull request.** Batch 63 had folded both into `-b`.
- **No bare argument names a branch.** Batch 63 had made `check jq` mean `check -b jq`. That's gone: `check`, `tidy`, `submit`, and `rebase` take no argument again, and `status <branch>` reads an exact name, as before.

Kept from batch 63, as the revision has it: an authoring command on master starts the branch where none changes the port, and works in the one that does. The person's answer to the `-p`-in-scripts question, that one match acts alone, is in the thread.

## What changed

- `branchFlags` in the command line: `-b`, `-p`, and `--pr` on `check`, `tidy`, `submit`, `rebase`, `diff`, and `impact`, one at a time. `-b` completes open branches' names, each described by its pull request and title (`engine.OpenBranches`).
  - `-p` with one branch says "Working in jq-4k2p, the one open branch changing jq.". With several, a terminal is asked to choose, each listed by name, pull request, title, and "(revision only)". A script is refused with `engine.AmbiguousError`, naming them.
  - Any of the three beats the worktree, and says "jq-4k2p (not uxprobe, checked out here)" where the two differ.
- `engine.PortBranches` lists the branches changing a port, substantive ones first. A branch is revision-only where its change record moves only the subport's revision (`ChangeRecord.RevisionOnly`), as `--revbump-dependents` does. `BranchesChanging` is built on it.
- `engine.PullRequestBranch` replaces batch 63's `Select`, and the error names `adopt --pr`.
- The authoring commands' `-b`, and `revbump`'s, `create`'s, and `watch`'s branch lookups, are exact again.
- usage and design-v3 say it.

## Verification

- The engine: a branch found by the port it changes and by its pull request; a port no branch changes; a pull request none tracks; two branches changing jq, refused with both; a revision-only record.
- The command line: `diff -p jq`, `-b` exact, `-b jq` refused as no branch's name, `-p` for a port none changes, `--pr` for a pull request none tracks, two flags at once refused, completion of `-b`, and a flag beating the worktree, said.
- `make test` with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.
