# The README, for a contributor meeting the tool

A correctness scan found the README accurate in every flag and command it named and wrong in what it taught: its hand-edit recipe was the workflow `amend` replaced, it never mentioned `amend`, `rebase`, or `outdated`, and its Features inventory was where each week's stale sentence came from. It was organized as a manual, from installation through housekeeping.

It is now organized by what a MacPorts contributor is trying to do, at 112 lines instead of 248. It opens with the two facts such a reader wants first, that Dockhand works only through their fork and that it builds by the MacPorts workflow's rule where tests are reported but not fatal, then gives the thirty-second path of `auth login` and `bump jq` before any setup they might not need. Then where builds happen, with the honest condition for the GitHub fallback; the everyday loop of `outdated`, `bump --diff`, `bump`, `status`, and `refresh`; what to do when a build fails, which introduces `amend`, `rebase`, and `abandon` where a person needs them; the four-row table of stop-early flags; and requirements and installing at the end. Housekeeping is two sentences under the closing pointers. Cut: the Features section, the manual recipe, the exit codes, retention and migration detail, and the design-document list.
