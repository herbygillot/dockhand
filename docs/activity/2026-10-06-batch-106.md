# 2026-10-06: serve after port uninstall (batch 106)

From the v0.3.0-rc6 full stage's A8. It comes after v0.3.0-rc6, for the release candidate after the run.

## What changed

- **serve's agent is kept alive only while dockhand is installed.** Its plist said `KeepAlive true`, so after `port uninstall dockhand` launchd went on spawning the missing program, exit 78 (EX_CONFIG), in a loop. It now says `KeepAlive` with `PathState` on the executable, as launchd.plist documents: kept alive while that file exists, so an upgrade, which replaces it, still restarts serve, and an uninstall doesn't (`macos.LaunchdJob.KeepAliveWhile`). An agent installed before this keeps its old plist until `serve --install` runs again.
- **serve stops when its executable is gone.** Missing for a minute, past an upgrade's moment between its old and new files, it says "serve: dockhand was uninstalled; stopping once its checks end. serve --uninstall removes the agent", finishes its checks, and stops. It had run on from the deleted file.
- **The port's notes say to run `serve --uninstall` before uninstalling** (the harness's Portfile.in; macports/macports-ports#34756 is unchanged, as the person asked).
- **A8** keeps its uninstall's output through the host's shared folder (batch 105), reinstalls the candidate, and now uninstalls serve's agent in its teardown, which a later row's checks would otherwise have been taken by.

- **A10 counts an example that needs a Tart image the stage hasn't made as not run.** `check --on sequoia --on tahoe` and `check --on tahoe` were refused with "no Tart image for macOS 15 (Sequoia): dockhand setup tart sequoia makes …", the refusal they should give, and A10 had called them failures; `setup tart`'s own examples it already doesn't run. The docs and `check --plan` are unchanged: a plan for a release with no image names the setup that makes it.
