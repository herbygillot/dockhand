# 2026-10-04: A12, an Xcode image in the full stage

The Prime-time thread found that `provision-host.sh --run` stopped at "WAITING: download each release's Xcode", though no row made or used an Xcode image: the plan's full stage builds each release's image and its Xcode image, and no row did the second. `setup tart --xcode` is in the release's scope, in the README's Providers section, so the full stage should show it.

## What changed

- **A12** makes this Mac's release's Xcode image with `providers setup tart --xcode` from the folder the host's `xcode` directory names, revbumps `ACCEPT_XCODE_PORT`, a small port whose Portfile sets `use_xcode yes`, and checks it, passing where the image was made and the port built there rather than being reported not built. One release's Xcode shows it; the other releases' Xcode images are made the same way. With no .xip staged, or no `ACCEPT_XCODE_PORT`, it isn't run, saying why.
- **provision-host.sh no longer waits for Xcode.** Its fifth step checks the signature of whatever .xip is staged, and with none says it's optional, for A12, and goes on to the overlay and the test-host marker.
