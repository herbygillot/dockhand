# The parser reads expressions

`internal/tcl/syntax` read scripts and lists but not expressions, so every reader that had to look inside an `if` condition improvised: `pureCondition` scanned brackets byte by byte, the Darwin profile scanner matched comparisons with five regexes and a heuristic about what follows an operand, and the host-state analysis spotted variable reads with a regex over raw text. Each worked on the shapes the tree mostly has and none could be right by construction, because none knew that `[vercmp ${os.major} >= 18]` is an argument list rather than a comparison, or that `${os.version}` inside a braced operand is text Tcl never substitutes.

`ParseExpr` is scannerless recursive descent over a condition's bytes. It reuses the script parser's own routines for `$`, `[`, `"`, and `{`, so there is one lexer for those, and models the operators the tree uses in Tcl's precedence: `||`, `&&`, the equality operators with `eq`, `ne`, `in`, and `ni`, the relational ones, additive and multiplicative arithmetic, unary `!`, `-`, and `+`, parentheses, numbers, and the six boolean barewords. The forms it does not model, the ternary, the bitwise and shift operators, exponentiation, and function calls, are refused with `ExprUnsupported`, so a reader refuses them rather than misreading them, which is the posture every reader already takes. The tree carries spans throughout; `ExprVariables` lists what an expression reads, reaching into quoted operands and command substitutions and not into braced text.

The acceptance test was the tree. Every `if`, `elseif`, `while`, and `for` condition and every `expr` argument in all 20,098 Portfiles, found through `Command.Control`, was parsed: 15,964 expressions, one refused. The one is `$build_arch eq "x86_64" | $build_arch eq "arm64"` in `science/ncarg`, a bitwise `|` where the author meant `||`, which Tcl evaluates as a string-to-integer error at run time and which this parser declines exactly as intended. The three readers are ported in the change that follows; this one adds the parser and changes no behavior.
