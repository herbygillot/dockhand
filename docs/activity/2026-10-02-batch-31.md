# 2026-10-02: cleaning one branch (batch 31)

Batch 31 of the [roadmap](../roadmap.md), at the person's request through the sand-runner session: macports/macports-ports#35090 merged, and the person asked for its branch cleaned up. `clean` took no branch, and would have swept every merged one, so the session did it by hand.

## What changed

- **`clean <branch>...` cleans the branches named, and nothing else** (`Engine.PlanCleanBranches`). Each is found as status finds it, a merged branch's record included (`ResolveRecord`), and cleaned as its state has it: a merged one's worktree, branch, and fork branch, a closed or archived one's worktree. What checks left in providers, and branches from before v3, are left for a clean that names none. An open branch has nothing to clean, and is refused with `archive` named.
- **A branch gone with a pull request says it may have merged.** After the hand cleanup, status said "its Git branch is gone … dockhand adopt <new name>, if you renamed it", which read as trouble until `status --refresh` read the merge. Status never reads the network, by design; where a pull request is recorded, it now says it may have merged and that `status --refresh` reads it, before adopt.

## Not taken

- The session's report that `clean` and `submit` reach your fork differently. Both go through the remote's push URL with git; the session's shell had lost its SSH identities between them. Reading and deleting the fork's branch through GitHub's API would free both from SSH, a choice for another time.
