# 2026-10-02: an outcome for the ports with nothing to fetch (batch 37)

Batch 37 of the [roadmap](../roadmap.md), item 7's rest: the ports that fetch nothing, metaports and `_select` ports, counted as covered, at the person's word: "covered, and `update` edits a version only where the port declares a livecheck". Composed versions, its other part, landed first ([note](2026-10-02-composed-versions.md)).

## What changed

- **Two facts of a port, and their conjunction, in `macports`.** `FetchesNothing`: no distfiles, `distfiles {}`'s one empty name among them, and no Git clone. `LivecheckReadsVersion`: the livecheck MacPorts resolves is regex or regexm, which the tree's checkers resolve a PortGroup's type to; none reads nothing, git a branch's commit, and fallback, md5, and moddate only whether a page changed. `OwnVersion` is both: a port with no release upstream to follow, whose version is MacPorts' own. An unread fact is no own version, so such a port is taken as any other.
- **`outdated` says so, rather than "couldn't check".** Discovery's `OwnVersion` assessment comes before any livecheck is read; `outdated --all` lists such a port as "nothing; it fetches nothing here, and no livecheck reads its version", the closing line counts those with no release to look for apart from those that couldn't be checked, and `--json` carries `own_version`. Discovery reads this Mac's evaluation only, so it says "here": libcxx fetches nothing on this Mac, and its source on Mac OS X 10.4 to 10.6. A subport that fetches nothing beside a checked sibling of its release, as mysql8-server beside mysql8, takes the sibling's result, as batch 30's python subports do; its version is its own only where no sibling shares it. `update --outdated` neither plans nor skips one, and resolving one without a version named says there's no release to look for.
- **`update` edits a version alone where a livecheck reads it.** A context where the port fetches nothing, before and after, adds no archive to the plan; a port that fetches nothing in any context downloads nothing, and its update is the version edit, checked in every context as any other. Where it fetches nothing in every context, and no livecheck reads its version, its version is MacPorts' own, and it's refused, named or not: "fetches nothing, and no livecheck reads its version: its version is MacPorts' own, which update leaves; dockhand edit <port> changes it by hand". `checksums` of such a port still says it has no archives.
- **A sibling with no source moves with its release.** The release scope required a sibling that builds anything to name the same distfiles, sites, and checksums as the selected port; one that fetches nothing, as libgcc14 beside gcc14, has no source to get wrong, as one that builds nothing hasn't, and owns none of the selected port's archives.
- **The assessment counts them as covered.** A context with no distfiles is marked `FetchesNothing` and adds no archive to cover; where none fetches anything, fetch and checksums pass, saying whether an update edits the version or leaves it. A port whose version is MacPorts' own, read across every context as update reads it, has a new outcome, `own-version`, with no version input looked for, since update edits none; `tools/survey` counts it as covered, beside `input-found`.
- **"Updated version"** where nothing was downloaded, a Git clone or a port that fetches nothing, rather than "Updated version and checksums" (the field-testing thread's semgrep finding).

## Measured

The whole tree was surveyed again first, as the plan asked, with pushed main at 7a1fa6e6 (composed versions included) on efde56cae1f, 41,811 ports in 72 minutes: 39,914 input-found, 863 unknown, 1,034 unsupported. Against September's last survey (2026-09-26, abd9fff): 156 improvements, the composed llvm and clang ports most of them (version-input/probe-inconclusive 161 to 13), and 2,878 ports whose discovery is now supported.

Then the 462 ports that stopped at "no source archives" there, with this batch's build: all 462 are covered, none regressed. 383 have a version that's MacPorts' own, 203 of them `_select` ports; 79 are input-found, a metaport or subport whose livecheck reads its release (the gcc libcxx subports, exiftool, gimp), or one that fetches its source on other platforms (libcxx, the mpich and openmpi clang ports, some qt5 subports). The 311 Portfiles they come from are fully covered. Over the tree that's 40,376 of 41,811 ports covered, leaving 863 unknown and 572 unsupported.

Two things the September comparison shows that this batch didn't touch, for a look: alcom moved from input-found to unsupported ("calculated or overridden cargo.crates requires manual preparation"), and 70 ports lost a fetch guard, among them gcc8, whose pre-fetch rejection on Darwin 25 depends on the Xcode version; that's likely the Xcode each environment now models, not checked.

## Decided along the way

- **The livecheck rule is for these ports only.** llvm declares `livecheck.type none` and fetches archives; a named version updates it as before.
- **The fallback livecheck reads no version.** A port with no master_sites and no livecheck of its own gets MacPorts' fallback, which compares a page's checksum: it can't say a release, so such a port's version is its own.
