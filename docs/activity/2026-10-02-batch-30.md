# 2026-10-02: the ports outdated can't check (batch 30)

Batch 30 of the [roadmap](../roadmap.md), item 7's first part. `outdated --mine --all` over the person's 1,079 ports, run again with 835d5447, couldn't check 143. September's sizing had them as custom livecheck hooks and git livechecks; read port by port, they were other things.

## What changed

- **A subport is checked with its sibling** (`outdated.WithSiblings`). 65 were Python subports, py310-cbor2 to py314-cbor2 and their like, whose livecheck the python PortGroup turns off, read as "require standard regex livecheck" beside py-cbor2, checked and outdated. A subport whose source convention discovery doesn't take (`upstream.ErrAutomaticUnsupported`, now exported) takes the result of a sibling of the same Portfile and release that was checked, as dockhand edits subports that share the main version as one release: "py310-cbor2 5.7.1 6.1.5 update with py-cbor2". `update --outdated` skips it, as moving with that sibling, and `--json` names it as `with`. A select subport, of another version, stays as it was.
- **A port that tracks a branch is checked as Base checks it.** 19 have `livecheck.type git`, each pinned to a commit with a version a person named, as `github.setup aligrudi neatroff 42ffa05…` at 20231125. Base's git livecheck reads no tags: it runs `git ls-remote <livecheck.url> <livecheck.branch>`, HEAD by default, and compares the commit with `livecheck.version`; so does dockhand now (`portsource.GitHead`, `git.RemoteBranchCommit`, `upstream.Moved`), the evaluator reading `livecheck.branch`. One whose branch names a newer commit is listed for an edit by hand, "its HEAD names a newer commit than the one it pins", since the version to give it is a person's and `update` takes a version, not a commit; `--json` gives the branch and commit as `moved`. Five of a sample of seven had moved; contacts-cli hadn't.
- **A default livecheck from a master site resolves.** About 12, libt3config and its siblings, tilde, termdebug, wget2, lzlib, parallel, sent, read as type default with no regex. The evaluator already resolved a default livecheck through the tree's `_resources/port1.0/livecheck/` definitions, as Base does, but declared too few of Base's globals: master-sites.tcl reads `livecheck.distname`, so the resolution failed and was passed over. With Base's own list, all twelve resolve: nine current, oilshell and parallel outdated, peg's site not answering.
- **A livecheck that matches nothing says so:** "nothing upstream lists matches the port's livecheck, so there's no release to compare with", where it said "requested release was not found in the supplied evidence". The 19 kubectl subports, 1.10 to 1.28, read the newest 100 of Kubernetes' releases, none of their series; Base's livecheck finds nothing for them either.
- **A GitHub run ended for its time isn't run again** by a driver that restarted (batch 26's leftover): a completed, cancelled run one of whose jobs ran for the bound, but a minute, is read as ended for its time (`ranFor`), where it was rerun for another 6 hours.

## Decided along the way

- **A moved branch is neither outdated nor planned.** `update` names a version, and a commit-pinned port's version is the person's to give; dockhand says the branch moved and leaves the edit.
- **Base's resolution of a default livecheck stays the evaluator's,** as it was, sourcing the tree's livecheck definitions, the interface those ports rely on; nothing reads `port livecheck`'s output, which isn't one.
