# Subjects and references

The last of the flag review's small items, with one correction to what was said while proposing them.

**`assess --at`.** `--version` named the value's type; `--at` is how the sentence reads, `assess jq --at 1.8.1`, and it no longer shares a spelling with `dockhand --version`. The assess request field keeps its name; only the flag changed.

**`--subject`.** `bump-revision --reason` became the commit body under a generated bare subject, `jq: revbump`, and `amend --title` replaced the whole first line, port name included. Of the last 6,000 upstream subjects, 93 are revision bumps and 91 carry the reason in the subject, so dockhand wrote the shape maintainers almost never write, in the one place GitHub's pull request list never shows. Now `--subject` on bump, bump-revision, checksums, amend, and rebase is what follows the port name; dockhand supplies the name, from the stub when there is one, and refuses a subject that already begins with it rather than doubling it. bump and checksums keep their defaults; a revision bump requires one, refused at the CLI before anything is read, at intake, and by the editor. On amend the name the subject already carries stays, which keeps a stub's name over its carrying subport's. `Subject` replaces `Reason` on the job spec, the stored job options, and every request type between, since the meaning changed, unlike `RefreshBody`, where only the flag did; `cancel --reason` is untouched, being a why on a job rather than a commit line. There is no body flag: the body was only ever the reason plus the trailer.

**`--closes` and `--see`.** Over the last 8,000 upstream commits the reference trailers are `Closes:` 274, `See:` 121, `Fixes:` 59, and `References:` 3, with 427 of the values being full Trac URLs, which is what the pull request template asks for. So the flags are named for the two trailers they write, each repeatable, each taking a ticket number, with or without `#`, which becomes `https://trac.macports.org/ticket/N`, or a URL, which passes through as given. They are recorded on the spec as `References`, part of what makes two requests equivalent, and the editor writes them in the trailer block ahead of `Generated-By:`. The pull request body needed no work: its Description already prints the commit body, and GitHub links the URLs. On amend and rebase they join the existing message's trailers, before dockhand's attribution or as a final paragraph when a person's commit has none, and a ticket already cited is not cited twice; nothing else in the message changes. `Compose` and `Rewrite` in `portedit` are the two composers, one for a generated commit and one for a rewrite of an existing one, and `Subject` is the one place the port name is prefixed.

**The no-rebuild amend already existed.** It was proposed as a build; `TestCorrectionPreservesChangeAndReusesSameTree` shows the verification phase already selects evidence by tree, so a message-only amend completes with a reused attempt and no build. The new correction test cites two tickets, checks the message, and asserts the reuse. The README's description of `status` still said it was live and processed work; it now says that of `console`.
