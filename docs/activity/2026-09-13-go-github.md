# GitHub client migration

The [SDK defaults follow-up](2026-09-13-github-defaults.md) removes the intermediate adapter limits described in this report.

Replaced the handwritten GitHub request/JSON implementation with `github.com/google/go-github/v91` v91.0.0. Its runtime dependency on `go-querystring` is also recorded in the module files. Both are Go libraries; no C bindings or external GitHub executable were added.

## Boundaries and behavior

- `forge/github` remains the concrete adapter. Exact references and annotated tags, tag and release catalogs, repository metadata, and PR lookup/observation/create/update now call typed SDK services. SDK objects are converted to existing `forge` observations inside that package. Workflow, state records, and the public CLI retain their contracts.
- A configured adapter initializes one shared SDK client lazily and safely across concurrent callers. Repository binding still performs no HTTP. Request encoding, authentication, API headers/version selection, JSON decoding, and pagination metadata now belong to the SDK. The SDK currently selects API version `2022-11-28`; the previous handwritten header selected `2026-03-10`.
- Removed the custom HTTP error type. Wrapped SDK errors retain structured status and rate-limit information. An exact-ref 404 alone means an absent tag; a missing annotation or catalog remains an operation failure. Definitive PR rejection remains distinct from an uncertain write. No automatic PR retry or redirect was introduced.
- Retained same-origin GET redirects and bounded response bodies. The shared response bound is 32 MiB, with errors identifying the method, URL, and byte limit. SDK decoding closes the body on failure as well as success.
- Pagination follows SDK `NextPage` metadata. Tag pages contain up to 100 entries; release pages contain up to 25 to reduce asset-metadata payloads. Catalogs retain the 2,000-record budget, with a 100-request and 90-second ceiling. Full final pages are accepted when no next page exists; partial or repeated observations fail explicitly. Release pages are converted before another page is fetched, so accumulated observations do not retain asset metadata.
- Automatic discovery uses upstream repository tags for unset, `archive`, and `tarball` modes, without any release queries or release-based veto. These Git tags are accessed through the GitHub tags API. Only `github.tarball_from releases` reads release eligibility. Unknown modes remain unsupported. Port livecheck filtering and MacPorts version comparison remain in `upstream`.

## Validation

Focused adapter and upstream tests passed. Regression coverage includes a release response above the former 8 MiB bound, short pages with next links, full final pages, all 2,000 records with smaller release pages, malformed/incomplete evidence, response closure/limits, rate-limit details, concurrent initialization, cancellation, and PR write outcome classification. The CLI error assertion now checks the SDK diagnostic's status and failing resource.

`CGO_ENABLED=0 make build` succeeded and rebuilt `./dockhand`; its help command succeeded. Dependency inspection found no CgoFiles in go-github or its module dependencies.

A temporary read-only live probe against `twpayne/chezmoi` succeeded: 265 tags in three tag requests, zero release requests during tag listing, and 258 releases in 11 separate release requests. Exact tag resolution returned `v2.72.2` at `125d00fe730fc9abf456ec312ba85b18c859bc50`. The probe source was removed afterward.

The rebuilt `dockhand bump chezmoi --diff` passed discovery and reached the existing editor limitation: `no supported version declaration`. The Portfile uses `go.setup`, which remains outside this migration. The preview created no workflow job and started no build; no real PR was written or branch pushed. The earlier failed job was not altered.

`make test-race`, `make vet`, and `git diff --check` passed. Native MacPorts-backed tests ran; the opt-in VM acceptance test was not enabled.

## Authorship

The SDK integration, transport bounds, pagination adaptation, discovery changes, regression tests, and documentation were authored for this migration using the existing v2 adapter as the starting point. No code, comments, or tests were copied from dockhand v1 or from the SDK. No new package, database migration, or driver path was introduced. Changes remain uncommitted.
