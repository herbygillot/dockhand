# 2026-10-02: branches named for what they do, and start --port (batch 65)

Batch 65 of the [roadmap](../roadmap.md): the rest of the command-line UX review's §1, as revised, the person's decision of 2026-10-02 in the review's thread: "meaningful branch names make sense, leaving the unique ID as fallback where necessary."

## What changed

- **`engine.NameFor(port, what)`** names a branch `<port>-<what>`, adding decision 37's short ID only where that name is taken now. It's taken by a tracked branch that isn't merged, a Git branch, or a worktree directory, as `FreeName` already checked. A merged branch frees its name once `clean` removes its Git branch. What Git refuses in a ref becomes `-`.
  - **An update** is named for its port and new version, `jq-1.8.1` or `terraform-1.16-1.16.5`. Its branch is started once the update knows the version. That covers `--new`, and an update on master with no branch changing the port, whose first line now says "starts one for it, named for the version it moves to". An update refused before it found a version keeps the port and an ID.
  - **`update --outdated`, `bump`, and serve** name each branch for the version their look found. So the names a preview prints are the names the run uses, field testing's batch-preview note, unless one is taken between the two.
  - **Other commands:** `revbump` is `gdal-rebuild`, `create` is `mods-new`, and `checksums` started on master is `jq-checksums`. An edit, with nothing more to say, keeps `jq-4k2p`.
- **`start [<name>] --port <port>`**, more than once if need be, brings those ports' directories into the new worktree, so a script needn't run `edit` just for the files. With no name, the branch is named for the first port and an ID.
- usage and design-v3 say it.

## Verification

- The engine:
  - a name free, then taken and given an ID;
  - a version with characters Git refuses;
  - an edit's name;
  - an outdated plan naming its branch for the new version.
- The command line:
  - update, `--new`, bump, serve, and `update --outdated` naming branches for the version;
  - revbump's `jq-rebuild` and create's `rift-new`;
  - `start --port` with and without a name.
- `make test` with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.

## Still open

- **A branch whose version moves before its pull request exists** should be renamed, so `jq-1.8.1` moved to 1.8.2 becomes `jq-1.8.2`, keeping its record as `adopt` does for a rename. There's no rename of a branch, its worktree, and its record in the engine yet. It's on the roadmap, and until then the name stays as started.
