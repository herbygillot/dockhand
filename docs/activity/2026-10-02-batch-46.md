# 2026-10-02: what the person sees of the renewing login (batch 46)

Batch 46 of the [roadmap](../roadmap.md), step 4 of the "GitHub auth flow review" thread's plan, after batch 45 made dockhand's GitHub login renew itself.

## What changed

- **auth login** opens, or prints, the device flow's address only where it's https with a host, and says how the login lasts: "It renews itself while dockhand is used at least once every six months."
- **auth status**, for dockhand's own login, says the date it renews itself until, six months from its last use (`github.SavedLogin`, which asks GitHub nothing).
- **auth logout** names GitHub's page for revoking dockhand's authorization, `https://github.com/settings/connections/applications/<client ID>`, the login's own client ID where it kept one; it revokes nothing itself, and its help says so.
- **The setup line** (`init`'s Publishing) reads the login: "✓ GitHub login in the Keychain, renewing itself until …", or "! the saved GitHub login is from an earlier dockhand; run dockhand auth login", or "! the GitHub login expired after six months unused; …".
- **serve says an ended login once.** A login that can't renew itself, from an earlier dockhand, expired, or refused by GitHub, is `github.ErrLoginEnded`; serve says it as one problem, not each pull request it couldn't read, and notifies it once a process. After batch 44, a new `auth login` reaches it without a restart.
- **Docs:** usage.md's GitHub login, and limits.md's new table of the login's lifetimes and waits.

The plan's last step is the person's, and optional now: batch 45 found that GitHub gives this OAuth app a renewing login for `offline_access` without changing its settings; forcing expiration there would only make a login from an older dockhand expire too.
