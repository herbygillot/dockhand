# v0.4.0 part 2, item 5: the rest of the command surface

## SQL-O1: a branch's latest check, defined once

- `store.RunFilter` gains `Tree`, the runs of revisions with that tree,
  joined in SQL, and `NoBaselines`. `runsOfTree` is now one `Runs` call,
  where it read every revision and run of the branch to join them in Go;
  status's two `treeRuns` calls take it.
- Pushed back on the study's shape: it had `Baselines` (include them,
  default false). Defaulting to leave baselines out would have dropped
  them from serve's queue (`Candidates`), queue, and the one-check-at-a-
  time reads, which all call `Runs` without saying; `NoBaselines` opts out
  instead, and every caller keeps what it read.
- `engine.LatestCheck(branch)`: the newest check in any state, a baseline
  aside. The product question the study left open, answered once: logs,
  retry, wait, and watch's `l` land on the branch's newest check, queued or
  running included (a branch has one at a time), canceled included (its
  logs and a retry are what's wanted), and never a baseline, which is
  named by its own name. `latestCheckHere` counted baselines before, and
  watch's `l` read every run of the branch, or of the repository.
- Kept apart on purpose: status's verdict, the newest finished run not
  canceled, until layer 1's branchstate takes it (the study's slot); the
  baseline's `latestCheck`, the newest finished check, now one limited
  query; retention's newest per branch, which keeps logs.
- Found by lint on the way: watch's `l` with a branch named lost
  LatestCheck's error to a shadowed variable; fixed before it shipped.
