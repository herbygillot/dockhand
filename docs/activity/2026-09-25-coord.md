# 2026-09-25: coordination, as sessions, fenced leases, and a journal

Roadmap step 5, part 2: `internal/coord`, the coordination design settled in Design v3 §11, built on the new store. This replaces v2's anonymous per-cycle claims, whose problems the [coordination note](../instance-coordination.md) recorded. Those problems were that a dead driver's claims waited out a 10–15 minute step deadline, a cancel sat unapplied with no driver, and another terminal saw less than the one doing the work.

## What it does

- **Sessions.**
  - `Coordinator.Start` records a session for the running process: its kind (serve, foreground, or observer), its PID, and the operating system's record of when that process started.
  - `Beat` and `KeepAlive` write a heartbeat, and `End` closes the session cleanly.
- **Judging a peer.** `Session.Judge` decides whether another session is dead:
  - it has ended;
  - its PID no longer exists, or now names a process that started at another time;
  - it has been silent for longer than `HungAfter` (two minutes), judged only by a session that is itself awake: one that has beaten within two heartbeat intervals by its own clock.

  The awake rule stops a laptop that has just woken, with all its processes, from declaring every peer dead.
- **Fenced leases.**
  - `Acquire` takes a resource's lease. It takes it from a dead holder under a new generation and records why in the journal. A live holder is a `HeldError`, which names the session and PID.
  - `Fenced` runs a write only while the lease is current, so a holder that resumes after losing its claim gets `store.ErrStale` and writes nothing.
  - External calls a resumed holder makes are still guarded by the providers' idempotency and reconciliation. Leases can't stop a paused process from making a late call, and the package says so.
- **Leadership.** `Lead` takes the repository's `leader` lease or reports the live leader, and a standby calls it again until it leads.
- **Controls.** `TakeIfUnattended` takes a resource's lease only when no live session holds it. A cancel for a run with a live holder is left to that holder; for a run whose holder is dead, the cancelling command applies it itself.
- **The journal.** `Emit` appends an event stamped with the session and time. `Coordinator.Tail` delivers events after a sequence number, in order, until the context ends.

## Process identity

On Linux, the start time is field 22 of `/proc/<pid>/stat`, read after the command name's closing parenthesis, since names can contain spaces. It is qualified by `/proc/sys/kernel/random/boot_id`, so a reboot can't make an old record match. On macOS it is `kern.proc.pid`'s `p_starttime`, which is wall-clock time and so differs across reboots. For a PID with no process, that sysctl returns no data, which `x/sys` reports as `EIO`; this is read as "no such process". Other platforms report `ErrUnsupported`.

**Not yet proven:** the macOS reader compiles (`GOOS=darwin go vet`), but this session ran on Linux. Its test, `TestSystemLivenessKnowsAReplacedOrExitedProcess`, runs on macOS and should be run there.

## Tests

The tests use the real SQLite store, with a process table and clock the test controls. They cover:

- a live holder keeping its lease;
- a dead holder's lease taken at once, with its later writes fenced;
- a hung holder judged only by an awake session;
- a fresh heartbeat protecting a holder;
- an ended session holding nothing, and a standby then leading;
- a cancel left to a live holder, or applied when unattended;
- the journal tailed in order, with a callback error stopping the tail;
- `KeepAlive` beating.

On Linux they also check real liveness: this process, the same PID with another start time, and a child process before and after it exits. `go test -race -count=2`, `go vet ./...`, and the full suite pass. The first commit (`e842afb`) left `go.mod` listing `golang.org/x/sys` as indirect, though `coord` now imports it directly, so `make vendor-check` failed; the follow-up commit fixes `go.mod`, and `vendor-check` now passes.
