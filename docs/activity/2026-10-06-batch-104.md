# 2026-10-06: a new pull request beside an earlier one of the same name (batch 104)

From the v0.3.0-rc5 full stage's A4, and the person's "pause for rc6". It comes after v0.3.0-rc5.

## What changed

- **submit opens a new pull request beside a closed or merged one of the same head name.** With no pull request recorded, submit looked one up by its head branch's name, found rc3's closed test pull request, #1, from an earlier dockhand/go-reflex-0.3.2, and refused: "#1 is closed; start a new branch". `update --new` names every update of a port to a version alike, and `start` doesn't change it, so that port and version were dead-ended, and A4, B4, B9, and F1 with them. Such a pull request is now an earlier one, not the branch's: a new one opens, and the preview says "opens a new one; #1, closed, came from a branch of this name before" (`SubmitPlan.Earlier`). A branch whose own recorded pull request closed is still refused.
- **GitHub's lookup by head name prefers the open pull request,** else the latest; it had refused any name with two, which an earlier closed one and a new open one are. Two open is still ambiguous. The test forge does the same.
- **A VM whose `tart run` ended is said at once.** dockhand waited out `tart ip --wait 300` before reporting it; the wait now ends with the run, as "tart run ended before <vm> took an address: <why>".
- **A command run on your checkout's master says how to name a branch,** "this is your checkout's master, not one of dockhand's branches; name one with -b <branch>, …, or cd …", rather than "dockhand adopt tracks it"; the README no longer calls the `cd` into the worktree optional.
- **serve notes its executable before it says it leads.** It noted it just after, so a file replaced in between passed for the build it started from: a race the suite's upgrade test lost once under load. An upgrade that close to serve's start is the test's, not a person's.
- **reset-user.sh seeds dhtest's known_hosts** from the SSH keys GitHub publishes at api.github.com/meta, so a push over SSH with no terminal finds github.com's key.
