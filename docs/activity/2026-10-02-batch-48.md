# 2026-10-02: shared test support (batch 48)

Batch 48 of the [roadmap](../roadmap.md), steps 0 and 1 of the test plan the person agreed to ("Agreed"), from the "Test suite cruft audit" thread. Tests change here, not dockhand.

## What changed

- **Step 0's rule is written down,** in [development.md](../development.md): a new engine test could run beside any other (no `t.Setenv`, `t.Chdir`, or package-level writes), a new command-line test adds no package-level seam of its own, and tests share their stand-ins rather than write their own, with no mock generators.
- **One GitHub fake,** `forgetest.GitHub` in the new `internal/forge/forgetest`, in place of engine's `fakeForge` and the command line's `fakeGitHub`. The two had drifted: the command line's never found a pull request by its branch, numbered them by slice position, and had no notion of other people's repositories, so its tests could not reach what engine's could. The shared one is engine's, stateful, its fork a local bare repository and its pull requests in memory by number; tests set it up and read its state, by exported fields, and `ForkHead` is the fork's branch where engine's tests read it. The command line's tests passed on it unchanged in what they assert.
- **One git fixture helper,** `testsupport.Git`, in place of six (engine's `run`, the command line's `gitRun`, editprep's `fixtureGit`, history's and git's `gitIn`, and buildenv/script's `git`). It is editprep's, the strictest: a fixed author, master the first branch, and none of the person's git configuration, hooks, signing, or `GIT_` variables, which the other five let in. **`testsupport.HTTPSAnswers`** replaces engine's and the command line's copies of `httpsAnswers`.
- **Imports regrouped,** separately: 70 files, most of them not tests, had one of dockhand's own packages among the standard library's, which `gofmt` keeps and the lint doesn't flag. They are with dockhand's packages now; nothing else in those files changed.

## Not changed

- Engine's and the command line's tests still run one at a time; making them parallel is among the speed recommendations, which aren't part of the plan.

## Verification

- The full suite with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.
