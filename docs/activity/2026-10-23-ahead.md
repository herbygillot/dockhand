# 2026-10-23: A port ahead of every upstream tag is held, not current

Field testing's mergestat: `outdated` said "0.5.4 → 0.1.0, nothing; it is
current". github.com/mergestat/mergestat's tags are now the server's
v2.x-beta prereleases, which a stable port doesn't follow, and stable tags
v0.0.1 to v0.1.0. The CLI's tags, v0.5.x and later, moved to
mergestat-lite, with no redirect. Discovery picked v0.1.0, compared it as
older than 0.5.4, set NoUpdate, and `finish` called the port current. The
placement is the architecture thread's, and prioritization put it in Next.

## The rule

The rule is upstream's, so update, serve, outdated and status read one
answer. Discovery's newest compares older than the port's version, and the
port's own tag, named as discovery names tags (`spec.Pattern.Tag`, prefix
included), isn't among those listed. Such a port gets a kind of its own,
`upstream.Ahead`: checked, but not current. Its CandidateVersion and
NewestTag are the newest listed, and its Detail is the reason. Where the
port's own tag is listed, it's current, as before: the livecheck filter
leaves the newer tags out.

## What reads it

- **update:** `Resolve` returns `upstream.AheadError`, and engine's
  `aheadRelease` refuses with exit 3: "can't tell whether mergestat is
  current, so nothing was changed: its 0.5.4 isn't among upstream's tags;
  the newest is v0.1.0; the repository may have moved". The Next line is
  `dockhand update mergestat <version>`. An explicit version still updates.
- **outdated:** the port is a Held row: "update mergestat <version> after
  a look: …". It counts in the summary's "may have one, for a look", and in
  the rest's words as "ahead of every version upstream lists". --json
  carries class "ahead" and the newest tag as `ahead`.
- **serve:** the port joins the day's look as one for review, as an
  uncertain one does, and is never prepared. Serve acts only on
  UpdateAvailable.
- **siblings:** outdated.WithSiblings already folds every checked kind
  except Unknown and OwnVersion, so a Portfile's subports read Ahead once.

## The designed behaviour that changes

TestAutomaticSelectionAppliesMaintainerFilterAndReportsCurrentOrAhead's
second half, a port at 1.1 with no v1.1 tag and a newest of 1.0, called
the port current. It now expects Ahead. TestAPortAheadOfEveryStableTagIsAhead
is mergestat's shape. TestAPortAheadOfUpstreamIsNamedNotChosen covers
update's refusal and an explicit version.

## The count, on a real outdated --mine

`outdated --mine --current` ran with this build on 1106 of the person's
ports, at ee76ef2c, in a scratch HOME and database. Results: 932 current,
121 newer, 27 not checked, 13 moved, 6 own-version, 3 uncertain, and 4
ahead. Each of the four is a port whose upstream moved:

- **mergestat** 0.5.4: the newest stable tag is v0.1.0. Its CLI moved to
  mergestat-lite.
- **carl** 0.6.0: b1rger/carl's tags on GitHub stop at v0.4.0.
- **zed** 1.18.0, and its subport **zq**: brimdata/zed is now
  superdb/super, whose tags start again at v0.1.0. Its newest is v0.3.0.

The rule isn't too broad, so the Held group stands.
