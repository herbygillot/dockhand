# 2026-09-28: dead code

This is roadmap item 1c, the last of the block before item 6: code nothing calls, left by v2's retirement and by features that moved on. The numbers are the code-organization review's findings. Removing it changes no behavior, except finding 38's error, below. About 1,080 lines of production Go and 430 of tests are gone, net.

**How it was found.**
- `deadcode` without `-test`. `make deadcode` passes `-test`, which counts code only tests reach as live, and most of what went was that.
- A references check: an exported method whose name appears nowhere else in the code. `deadcode` can't see one, since it counts every exported method live once its type reaches an interface or reflection, and a type that reaches fmt or JSON does. The `git` methods and the composer were found this way.
- Each candidate was then read, and its history checked for when it lost its callers: mostly when v2's packages went (`df281067`).

**What went.**
- **`git`, about 520 lines (finding 18).**
  - Taken out:
    - v2's checkout capture: `CaptureCheckout` and its helpers, and the `Checkout` type;
    - `Transplant` and `ReplaceContribution`;
    - `RequireCleanBranch`, `CheckContributionBase`, `FirstCommitAbove`, and `AddedOrModifiedPaths`;
    - `UnstagedPaths`, `CommitMessage`, `SingleParent`, the push locks, and the checkout-based `Rebase`, since the engine replays.
  - What stays:
    - `checkoutHead` moved beside `MoveCheckout`, its one caller, and says "the checkout has no commit" rather than naming v2's working-tree verification;
    - `Checkouts` moved into `branch.go`;
    - the package doc no longer promises source capture.
  - Tests: `MoveCheckout` gains a detached checkout's case, which fails without its check. The deleted `AddedOrModifiedPaths` test also covered `ChangedPaths`' deletions and type changes, which no other test did, so that half stays as a `ChangedPaths` test.
- **`commitmsg`'s composer (finding 9).**
  - `Compose`, `Rewrite`, and their helpers, the ticket references, and `portedit`'s `CommitIntent.Message`, which nothing called, all went.
  - `CommitIntent` keeps only its `Subject`: the update reads that and nothing else. So its `Body`, `References`, and `Paths` went, and so did `Request.References`, which nothing set.
  - Tidy composes its own messages. `architecture.md` said they came from `commitmsg`, and now says what they take from it: the attribution line. Its list of where `record`'s types went now says the references were deleted.
  - Nothing tested `IsAttribution`'s earlier forms, and only the composer's tests reached its current one. `TestIsAttributionKnowsEveryFormDockhandWrote` covers both, and that another tool's `Assisted-By:` is the person's.
- **`macports`' constants (finding 13).** `PortsRepository`, `PortsRepositoryURL`, and `PortsBranch` had no callers, and nor did `PortsWorkflowPath`, since `ghactions` names its workflow itself.
- **`outdated`'s helpers (finding 20).** `Headline`, `Incomplete`, `OutOfDate`, `Hidden`, and `Note` went, since `outdated`'s output counts for itself. The `Selection` alias stays: it's used. Comments naming "v2's survey", "workflow state", and "workflow jobs" say what's there now.
- **The review's other uncalled pieces (finding 18).**
  - `Engine.Next`: serve takes `Candidates`, and the two ordering tests now do too.
  - `coord.Tail`: `watch`, `wait`, and a following `check` read the journal themselves, by sequence.
  - `store.Reader.Sessions`, which listed live sessions for tests alone. Those tests now read each session by its ID. The pruning test's check that an ended session went could never fail through a list of live ones, though its count caught the same mistake.
- **An unreachable error (finding 38).**
  - GitHub's `Observe` passed a 404 through as a plain error, and never reported a pull request as not found, so `refresh`'s "#N was not found" was dead.
  - It now maps a 404 to `forge.ErrNotFound`, as GitHub's commit, file, and tag reads do and the engine's test forge already did, and `refresh` says "#N was not found" for it.
  - The `PullRequests` interface now says what each read reports for a pull request that isn't there.
  - A pull request that disappears is rare. Adopting or reviewing a missing one still fails, its message now beginning with the forge's not-found.
- **`scratch`'s v2 sweep (finding 42).**
  - `Stale` and `Sweep` were `gc`'s, and nothing called them. They went, and so did the branch that swept directories an earlier build made outside a run root.
  - A new root still sweeps dead ones, as before. The package doc no longer names `gc`.
- **What `deadcode` without `-test` found beside the review.**
  - `archive.Change.String`: its marks now live in the test helper that used it.
  - `macports.ValidHostPrograms`: it checked the host-program table for a test alone, and moved into that test.
  - `portindex.DefaultMirrorURL`: `MirrorURL` with no base is the same, and has its test and its note on architecture names.
  - `tart.PreparedReleases` and `host.CheckGuestTransport`.
  - `progress.WithScope`: nothing set a scope, so `Update.Scope` went with it.
- **What the references check found.**
  - `portindex`'s `DependencyClosure`, v2's, went, with its `Closure` and the four dependency fields only it read. `ReverseDependencies` stays: it's used.
  - `channel.Guest.Range`, which followed a growing guest file. v2's verification read logs with it, and design v3 keeps build logs as files.
  - `rpc.Session.Noise`. It was the only reader of a buffer every call filled with what the interpreter printed outside a frame, so the buffer went too. Such output is skipped, as before, and `TestStrayOutputIsNotTheReply` keeps that.
  - `syntax.Braced.ListLens`, a wrapper of `SplitList`, which its test now calls, and `tools/survey`'s `Headline`.

**What the review got wrong.** `engine.PortIndex()` is used: Tart's provider takes it as a method value (`Index: e.PortIndex`).

**Kept, as test support.** `deadcode` without `-test` still lists these, each documented as for tests:
- `github.TokenSourceFunc`;
- `macports.NewTree`;
- `workspace.Adopt`, with `Rescan`, which the references check lists;
- the Tcl session's and shell's options;
- `testsupport`.

**Tests.** Each new check fails with the code it covers broken:
- `MoveCheckout` on a detached checkout;
- `ChangedPaths`' deletions and type changes;
- `IsAttribution`'s forms;
- the 404 in `forge/github` and in `refresh`;
- the pruning test's per-session reads;
- `scratch`'s rule that only run roots are swept;
- stray interpreter output skipped.

`make deadcode` reports nothing, and `lint`, `vet`, `fmt-check`, `vendor-check`, and the suite pass.

**Left for later.** The review's other remedy for finding 9, tidy's composer in `commitmsg`, beside the rules it uses, was placed nowhere. It is a smaller item now.

**Finding 42's remainder, in its own commit.** The roadmap took finding 42 whole before item 6, but only its process group had been done, and now `scratch`'s sweep.
- **Every short-lived directory in the run root.** `scratch` promises that, edit buffers among them. Two were made beside the root, where nothing sweeps them if the process dies: Tart's bootstrap askpass helper, and `submit`'s description buffer, which the review didn't name. Both are in the run root now. Their tests fail with the old directories.
- **When `os/exec` is used directly.** `subprocess`' doc now says it: a command run to completion, for its output or its exit, goes through `Run`. `os/exec` is for one that holds the terminal, runs as long as its caller, streams, or outlives the process.
- **What that rule finds.** Seven one-shots call `os/exec` where `Run` would bound their wait and name their failure: `security`, `pkgutil`, `gh auth token`, `open`, `osascript`, `launchctl`, and `port version`. They are a smaller item.
