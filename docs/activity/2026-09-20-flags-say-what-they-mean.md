# Flags that say what they mean

A review of the flags across `bump`, the corrections, `verify`, and `publish` found the workflow's bones sound, prepare then verify then publish with one attachment model, and three places where the flags misdescribed it. This note records the three changes; the review's other findings, the three names called refresh, two words for preview, `status` driving work, and a flat list of twenty-seven flags, are recorded on the roadmap and not done here.

**The destination.** Where a bump stops was two negatives, `-P` and `-V`, whose four combinations needed a table in the help, and whose oddest cell, `-V` alone, made the unverified pull request the shortest spelling. It is one destination and one modifier now: `--to branch|verified|pr`, with `pr` the default, and `--unverified`, which opens or updates the PR without a build and only with `--to pr`. The old spellings remain as deprecated aliases; their combinations map onto the same three destinations inside `resolve`, so the table exists in one function rather than in the reader's head. `publish --skip-verify` is `publish --unverified` the same way. The PR body's disclosure names the new flag.

**The provider.** `--provider auto` became `tart` when any Tart flag was passed and `github` when `--tests workflow` was, so a test policy chose the provider; and `verify` alone said its default was `tart` while the code used the contribution's recorded settings. Every build command now takes `auto|tart|github` and defaults to `auto`; a Tart option still selects Tart, since `--image` is an unambiguous choice of Tart and refusing it would be pedantry, but nothing selects GitHub except `--provider github` or the absence of a usable image. `workflow` is gone from `--tests`: it is GitHub's policy, recorded as such by the provider, and `--tests` with `--provider github` is refused as the Tart option it is. `verify` accepts `auto`; `--working-tree` and `--fresh` are Tart options and select it.

**The branch.** `--branch` was an input on `verify` and `publish`, adopt this branch dockhand did not make, and a selector on every other command. Adoption is the moment dockhand takes responsibility for someone else's commit and deserves its own name: `--adopt <branch>`. `--branch` selects a tracked contribution everywhere, and a branch that is not tracked is refused with the `--adopt` spelling in the message rather than adopted silently; a bare `publish` on an untracked current branch is refused the same way, where it used to adopt. `amend` and `rebase` take a target, as every other workflow command does.

What the suite caught: the `adopt` exclusions on `verify` were registered before `--change` existed and cobra panicked at startup, masking every CLI test until the ordering was fixed; and three test helpers adopted branches by binding a bare `Branch`, which is exactly the silent adoption the change removes. The deprecated aliases print a notice on stderr, so the tests speak the new spellings.
