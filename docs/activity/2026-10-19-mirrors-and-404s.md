# Mirrors behind a new release, and what a 404 means where

Field testing at 6dd7745c.

- **Every SourceForge mirror's HTML page.** libpng, scons, e2fsprogs,
  GraphicsMagick and net-snmp bumps failed, "the server sent an HTML page
  instead of the file" from zenlayer.dl.sourceforge.net, and minutes later
  the same address served the file. zenlayer is the last of the twenty
  mirrors MacPorts lists for sourceforge (_resources/port1.0/fetch/
  mirror_sites.tcl), so the update had tried every one, each serving the
  page a mirror gives for a file it doesn't carry yet, and named only the
  last. `Store.FetchFirst` now says so where every site sent a page
  (`MirrorsBehind`: "every one of its N sites sent an HTML page … try again
  later"), and `fetch.Transient` reads a failure that says it's transient,
  so a later look fetches it again. downloads.sourceforge.net isn't one of
  MacPorts' sites, and a check fetches as MacPorts does, so dockhand
  doesn't go around them. TestEveryMirrorsHTMLPageIsAReleaseNotThereYet.
- **A 404 by where it was asked.** libxkbcommon's `${homepage}/download/`
  was gone whole, and "no archive is published at that location yet, and a
  release tag alone does not publish its assets", a GitHub release's words,
  read as wait for upstream. `notFoundWords` keeps them for a GitHub
  release asset; on a port of the github PortGroup elsewhere it says
  `github.tarball_from archive` fetches GitHub's archive of the tag
  instead, the fix the Portfile's own comment named; otherwise, the site
  has no file there, not yet or moved. TestA404SaysWhatItMeansWhereItWasAsked.
- **xapian-core's family of archives** is v0.5.0's step 3 (the roadmap):
  each subport's archive fetched and its block written at the one version,
  where the update refuses today.

## The cause: a Referer on the redirect (2026-10-19)

c3c12d28 read the HTML pages as mirrors not yet carrying the release;
field testing then found the cause on the person's Mac. Go's http.Client
sets a Referer, the address it was redirected from, when it follows a
redirect, and SourceForge answers a request carrying one with its HTML
download page instead of the mirror's redirect to the file: curl without
`-e` gets the file, and with it, the page. curl and MacPorts' fetch send no
Referer on a redirect, and `fetch.redirecting` now drops the one Go adds.
TestARedirectSendsNoReferer. MirrorsBehind stays, for an archive every
site really answers with a page; libpng, scons, e2fsprogs, GraphicsMagick,
net-snmp, and freetype were blocked on the Referer.
