# 2026-09-25: `submit`

Roadmap step 5, part 7: opening or updating a branch's pull request (Design v3 §6.2, §6.10, §9, §13), ahead of `check`.

## The command

- **Every push goes to your fork, never to `macports/macports-ports`.**
  - The fork is the one Git remote that pushes to a repository your GitHub login owns. `--remote` chooses when several could be.
  - GitHub must report the repository as a fork of `macports/macports-ports`.
  - The PR is opened against `master`.
- **The committed head is what gets submitted.** Edits not yet committed stop `submit` with their names and the two ways forward: commit them with `dockhand tidy`, or submit only what is committed with `--head`, which lists what it leaves out.
- **The publication rule (§3).** `submit` reads the newest finished check whose revision has exactly the committed tree. A check builds files, not history, so a check of snapshot 1 still counts after `tidy` commits those same files.
  - Every changed port must pass in every environment.
  - A failed revision-only port, or a failed extra from `--also`, can be acknowledged with `--accept <port>`. The acceptance is recorded for that exact commit, and the PR shows "cause not established".
  - A changed port that failed can't be accepted; it goes out as a draft (`--draft`).
  - With no finished check, `--draft` or `--no-check` is needed, and the PR says which.
  - `check` doesn't exist yet, so today those two are the only ways through. The rule itself is tested with check records written straight into the store.
- **The push is conditional:**
  - It happens only while the fork's branch is where `submit` saw it, a force-with-lease on that exact commit. Anything else stops with nothing pushed.
  - When dockhand pushed to the PR before and its head is now some other commit, `submit` refuses up front, names both commits, and says how to fetch and compare.
  - The preview says whether the push creates the branch, adds commits, or replaces the history.
- **The title:**
  - A `--title` is kept for the branch.
  - Otherwise an existing PR keeps its own title, the branch's recorded title is used, or the single commit's subject, or the subject of the only port's first commit.
  - Dockhand never composes a title. A branch touching several ports needs `--title`.
- **The description** follows the template's own sections, read from the template itself:
  - Description: a single commit's body, or a table of commit, port, and change.
  - Type(s): what `--type` says, with `security fix` ticked by itself when a commit cites a CVE.
  - Tested on: each release built, the provider and what it establishes, and a grid of ports by environment. With `--no-check`, it says MacPorts CI is the only check.
  - Verification: every item ticked only from evidence.
    - The commit-guidelines and squashed items come from the commit rules.
    - The other-PRs item is ticked when dockhand searched and found none; otherwise it lists the numbers it found.
    - The ticket item is ticked when a commit cites a Trac URL.
    - `port lint`, `sudo port test`, and install come from results. The install item states that dockhand builds without trace mode. The test item is dropped when no port declares tests.
    - The two items only the person can state are asked on a terminal, or given as `--tested-binaries` and `--tested-variants`.
  - `--skip-notification` adds `[skip notification]`.
- **Your edits on GitHub are kept.** On an update, dockhand rewrites only its own part (Tested on through the end), and only while that part is still exactly what dockhand last wrote. Anything else keeps your description, and the preview says so.
- **The preview:**
  - It shows the title, from, to, commits and rule findings, the push, the checks, other open PRs for the same ports (from a GitHub search), and whether it opens or updates a PR.
  - On a terminal, the prompt is `Preview [p] · Edit description [e] · Submit [s] · Cancel [q]`. `[e]` opens `$VISUAL` or `$EDITOR`.
  - In a script, nothing is submitted without `--yes`.

## Changes by package

- **`engine`:**
  - `PlanSubmit` and `ApplySubmit`.
  - `EvidenceFor` and the publication rule.
  - The PR body.
  - A `Forge` interface, filled by GitHub with the same credentials v2 used: GH_TOKEN, GITHUB_TOKEN, the keychain entry `dockhand-v2 auth login` saved, or `gh`.
  - `PlanSubmit` reads the branch from the store rather than trusting the caller's copy. A stale copy carried an old "last pushed" commit and made the someone-else-pushed check misfire; a test found it.
- **`forge/github`:** `Create` passes `draft`, and `OpenPullRequests` searches a repository's open pull requests whose titles name a port the way a MacPorts subject does (`jq:` or `gojq, jq:`).
- **`command`:** `submit`, and a forge hook for tests.

## Found along the way

- **CI has been failing on macOS since `a425b18`.**
  - The cause: `/var` is a link to `/private/var` there, Git reports resolved paths, and six engine and command tests compared those with unresolved temporary directories.
  - The earlier notes' claims that the tests passed held on Linux only. They are corrected in place.
  - The failure was reproduced here by making `TMPDIR` a link; the tests now build their fixtures under resolved paths.
  - `tilde` now also matches the resolved form of the home directory, so a home reached through a link still shows as `~`.
  - Fixed in `dd3fbd7`.
- **`make fmt-check` skipped new files.** It listed only files Git already tracked, so `tidy.go` reached `main` unformatted. It now lists untracked files too.

## Tests

- **Engine tests**, against a fake GitHub whose fork is a local bare repository, so pushes and leases are real Git:
  - no check refused, and `--no-check` opening the PR;
  - a tidied amendment replacing history;
  - `--title` retitling;
  - a person's edited description kept;
  - a push by someone else stopping the apply as stale and the next plan outright;
  - an extra's failure needing `--accept`, then recorded;
  - a changed port's failure refused as an acceptance and allowed as a draft;
  - the description merge rules.
- **Command tests** cover the preview wording, the script refusal without `--yes`, and the terminal flow with its questions, preview, and draft.
- **GitHub client tests** cover the search's title matching and the draft flag.
- `go test ./...` passes here with `TMPDIR` behind a link, as on macOS, except for two v2 tart tests. Those reject any argument containing `-f`, which the scratch path used here happens to contain; they pass under another linked path. The race runs, `go vet` (Linux and `GOOS=darwin`), `make vendor-check`, and `make fmt-check` also pass.

**Not proven here:** a real submission to GitHub. The first one is worth doing as a draft from a throwaway branch.
