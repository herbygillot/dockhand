# Separate Tart VM mechanics from verification policy

## Boundaries

- `internal/tart` retains runtime resolution, CLI invocation/environment, image metadata/naming, and image locks.
- New `internal/tart/host` owns concrete VM enumeration, guarded cloning, confirmed deletion, launchd VM lifetime, foreground process startup, guest argv/stdin transport, and transport probes. It does not import workflow, state, or verification.
- `internal/tart/provision` retains recipes, SSH bootstrap, local/remote clone choices, image adoption, foreground-process bookkeeping, readiness deadlines, and toolchain/installation validation. It now consumes shared foreground startup, guest transport/probes, and confirmed deletion.
- `internal/verify/tart` retains provider state/capacity/recovery, image identity and capability evidence, staging, the build runner's request/result protocol, and evidence/log handling. Its native adapter composes `host.Machine`; it no longer implements host launchd or basic VM control.
- `macos.LaunchdPlist` renders the shared host/guest launchd representation, including deterministic environment ordering.
- New `atomicfile.Write` provides the existing synced temporary-file, rename, and parent-sync sequence for VM plists and retained verification results. Naming and lifecycle remain with the callers.

The verification native adapter now contains composition and build-protocol operations. No generic VM/executor framework was introduced. Git capture and archive staging remain at their existing boundaries. Recovery-partition storage code remains in macos; no speculative disk-image abstraction was added.

## Behavior and provenance

Moved existing v2 mechanics and their relevant tests; no v1 code/comments/tests were imported. Authored composition glue, shared environment access, and regression coverage. Provisioning now uses the verification transport's descriptor cleanup while preserving combined capture, streaming, stdin, arguments, and errors. Provisioning deletion now confirms absence and reports incomplete/unlisted VM directories instead of treating them as already gone.

Kept verification's launchd lifetime and provisioning's foreground lifetime distinct. Kept the accepted guest protocol digest unchanged, checked against HEAD's prior implementation with a temporary comparison test that was removed afterward.

## Validation

- `go test ./...` passed.
- `go test -race ./internal/tart/... ./internal/verify/tart ./internal/macos ./internal/atomicfile` passed.
- `go vet ./...` passed.
- `gmake build` produced `dockhand`.
- Focused regressions cover lock-descriptor inheritance during cloning, refusal to overwrite listed/incomplete VMs, running-image deletion refusal, confirmed deletion, foreground boot errors, guest argument/stdin/descriptor behavior, provisioning streaming/error propagation, launchd XML values, and atomic replacement/cleanup.

No live VM provisioning or PR exercise was performed in this refactor. Existing lifecycle/recovery suites and shared transport tests were used; the previous live provisioning matrix remains historical evidence.
