# A GitHub tag that moved after its check is said (v0.4.0 part 1, c; D-N5)

The rc8 full stage's D-N5: dh-fixture-retag was checked at v1.0.0, 1d15bc8,
and the tag was then moved to d4c0fdb. `check --plan` offered check-41's
pass for reuse, and submit's preview read "Checks: passed (check-41)", where
GitHub's v1.0.0 archive no longer matched the Portfile's checksums. Only
Git-fetched ports had their source recorded and read again.

- **The plan records each GitHub tag's commit** (`EnvironmentPlan.Tags`,
  beside `Git`): `macports.PortInfo.GitHubTag` is git.url and git.branch as
  the github PortGroup's github.setup sets them, for a port fetched as a
  tag's archive (github.tarball_from tarball, tags, or archive; not an
  uploaded release asset, not a Git fetch). `planning` carries it for what
  the check builds and what --only left out, and `engine.resolveTags` reads
  each with `git ls-remote` (`git.ListRemoteTags`, peeled), which spends no
  API budget. A name with no such tag that is a commit's is dropped, since
  a commit binds; a tag the repository lacks is recorded unresolved. Plans
  are JSON: no schema change. `Validate` refuses a tag for what isn't
  built or left out, a target with both a Git source and a tag, and a tag
  neither resolved nor said why.
- **A check doesn't reuse a build past a moved tag, and says so.**
  `reuse.Candidate.Tagged` is the tag's commit from the earlier build's
  check plan (read once a run in `earlier`, a missing plan read as none);
  `reuse.Target.TagMoved` skips it in `Choose`, and `driver.sayTagMoved`
  says "libharbor builds again: v4 now names d4c0fdb, not 1d15bc8, as when
  check-41 built it; dockhand checksums libharbor handles a stealth
  update". Where either commit isn't known, as for builds before this, it
  is reused as before.
- **Submit holds on it.** `movedSources` reads the plan's tags again
  (`plannedTags`, sharing `plannedBy` with `plannedSources`) and returns a
  `tag-moved` concern in the same words, which holds a submission nobody
  looks over and shows in the preview.
- `check --plan --json` gives each build a `tags` map; usage.md says it.

Not done: what was built against a target whose tag moved isn't rebuilt
with it, as it is for a Git-fetched target (`AgainstOtherSources`). A moved
tag's archive fails the Portfile's checksums, so the target fails and the
check with it; a dependent's reused result doesn't hide that.
