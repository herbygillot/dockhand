# Central implementation roadmap

Created `docs/roadmap.md` as the single current queue for Dockhand v2. The roadmap distinguishes implementation-ready work, accepted later work, unresolved design, deferred scope, and completed foundations.

The immediate order is explicit Tart image capability validation followed by dependent verification planning. Review controls remain in design because the existing command placeholders do not define what creates a review or what acceptance and dismissal authorize. Human corrections, standalone publication with missing evidence, unattended-publication authority, and cross-repository evidence reuse are also recorded as design questions rather than assumed behavior.

The roadmap records standalone checksum refresh, broader selectors, upstream discovery, PR observation, and engineering maintenance as planned work. Git-notes recovery, portable evidence exchange, a generic DAG, automatic PR-response mutations, broad provider matrices, and indiscriminate v1 parity are explicitly deferred.

Removed the stale priority list from `components.md` and replaced it with a link to the roadmap. Added roadmap links to the CLI design and README. Detailed behavioral specifications remain in their owning design documents, while activity reports remain historical records.

No Go code, schema, command behavior, dependency, or generated artifact changed. All roadmap prose was authored for Dockhand v2 during this documentation pass.
