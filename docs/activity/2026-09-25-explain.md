# 2026-09-25: explain

Design v3 §8: `dockhand explain <code>` quotes the MacPorts source behind each commit rule.

## What changed

- **`commitrules.Explain`** describes each rule the checks report. The eight rules are:
  - `subject-port`, `subject-vague`, `subject-length`, `body-wrap`, `ticket-url`;
  - `follow-up`, `merge`;
  - `revision-after-update`.

  For each one it gives what dockhand checks, in dockhand's words, and the MacPorts documents behind it. A test keeps the two lists in step: every code the checks can report is explained, and every explanation is of a code they report.
- **The sources are quoted verbatim** only where dockhand fetched the text on 2026-09-25:
  - The MacPorts Guide's contributing section (`guide/xml/project.xml` in macports/macports-guide), for `follow-up` and `merge`.
  - The guide's `revision` keyword entry (`guide/xml/portfile-keywords.xml`), for `revision-after-update`.
  - macports-ports' pull request template, for `ticket-url`, `follow-up`, and the Commit Message Guidelines item.
- **Where there is no quote.** This session's network policy blocked the Trac wiki, so its Commit Message Guidelines are linked but not quoted. `explain` says so instead of paraphrasing them as if quoting. The subject and body rules rest on that page, so for now they show dockhand's summary and the link.
- **Findings show their code** in brackets, such as `[follow-up]`, in tidy, submit, and review output, so there is something to pass to `explain`.
- **`dockhand explain`** with no code lists the rules.
