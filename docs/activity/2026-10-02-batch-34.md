# 2026-10-02: one reading of CMake (batch 34)

Batch 34 of the [roadmap](../roadmap.md): the architecture review's finding 3, and with it the options a CMakeLists.txt keeps in the files it includes.

## What changed

- **One document** (the [architecture review](../reviews/2026-10-01-architecture-and-helper-ownership.md)'s finding 3). `project` scanned a CMakeLists.txt for its options, its off defaults, and its stripped text, each pass on its own, and `sourcecompare` read conditions a second time, a regular expression over lines (`cmakeConditions`) and a word scan (`cmakeTests`), to say where a change was. A multiline `if(` read as "outside any if()", though the project reader had judged its block unreached. `project.CMakeDocument` reads the file once into its commands and a tree of `if()` blocks, each branch with its condition. What it declares (`Facts`), the options nothing turns on (`Off`), and what the default build reads of it (`Statements`, `Without`, `Rest`), each statement with the conditions it's under, structured (`CMakeCondition`: as written, the names it tests, and whether it's an `else()`), all come from it. `sourcecompare` only diffs statements and words what it finds; the line reader and the word scan are gone. An `else()` reads "NOT (…)" in a package's place as in a change's, where `ReadCMake` had written "not (…)".
- **The files a CMakeLists.txt includes, read in their place** (the dogfood run with 58e2d7eb, fluent-bit 5.1.3; D12's bound). `include()` reads a file into the same scope, so the document splices it in where it's included: by its path, from the source directory or `${CMAKE_CURRENT_LIST_DIR}`, or as a module, `name.cmake` on the `CMAKE_MODULE_PATH` the file sets or appends to, up to eight deep, a cycle stopping. An option one declares or flips is the document's, so a default flipped in `cmake/plugins_options.cmake` is said and holds; one it sets, as `set(FLB_DEMO ON)`, isn't taken as off, so what it gates is reached and holds; and a change in one is placed there, "outside any if() in cmake/plugins_options.cmake". The reading keeps every `.cmake` file in its first pass, as it keeps Cargo manifests, and keeps those a CMakeLists.txt includes (`ReaderVersion` 4); they're compared as part of their CMakeLists.txt, never alone, and named in what was read. `assess.Policy` is 16.

## Decided along the way

- **Statements, not lines.** What the default build reads is each command in one line, its arguments as CMake reads them, rather than the text with spans cut, so a change of indentation or wrapping isn't a change, said as "changes only comments and layout", which had said "comments and blank lines", and a condition is the same whether a block is cut or named.
- **A path built from another variable, and a project's own macro, stay the bound.** `include(${GENERATED}/x.cmake)` isn't followed, nor is what fluent-bit's `DEFINE_OPTION` does; an option such a macro names is taken as set, which holds what it gates, as before.
- **`add_subdirectory()` isn't followed.** It reads another directory's CMakeLists.txt in a scope of its own, which is another document, not this one's text; nothing asked for it.
