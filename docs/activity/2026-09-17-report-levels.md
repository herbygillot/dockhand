# Interface pass, step 1: report levels

Per the [output design](../output.md), every progress report now carries a level. `progress.Report` is info, `VerboseReport` and `DebugReport` are the other two, and the CLI filters with `-v`, `-vv`, and `--debug`; `--trace` implies debug and adds the guest log stream as before. The thirty-four operation reports and the CLI's own stderr lines were classified: index generation and image hashing announcements stay info because they explain a long wait; provider choice, fetch, acceptance receipts with their identifiers, index updates, and image inspection are verbose; archive-context checks, staging, transfer, launch, and cached-index hits are debug. Reports are scoped by port rather than attempt ID, and attached job lines name the port at info and the job ID at verbose. In JSON mode reports are one JSON object per line on stderr with `level`, `scope`, and `message`, so stdout stays the result. Tests that assert on verbose lines now ask for them.
