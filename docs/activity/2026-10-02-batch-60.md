# 2026-10-02: create from a registry name (batch 60)

Batch 60 of the [roadmap](../roadmap.md): item 7's `create` from registry names. The implementation plan Herby agreed to moves this after the release; it was built and tested by the time the plan arrived, so it lands here and the release's command freeze includes it.

## What changed

- **A new package, `internal/registry`,** reads where a project named in a registry keeps its source, through each registry's documented interface only:
  - `pypi:NAME`: PyPI's JSON API (`/pypi/NAME/json`), the first of `project_urls` labelled Source, Source Code, Repository, Code, GitHub, Homepage, or Home that is on a forge, else `home_page` where it is;
  - `crates:NAME`: crates.io's API (`/api/v1/crates/NAME`), the crate's `repository`, asked with dockhand's user agent as crates.io's policy requires;
  - `go:MODULE`: a module path on github.com, gitlab.com, or codeberg.org read as its repository, else the path's `?go-get=1` answer, its `go-import` meta for git.
  A name that isn't one the registry could hold is refused before any request; a registry that names no source says so (`registry.ErrNoSource`).
- **`create` takes the name in place of a URL** (`githubProjects.Project`) and goes on from the project it names. A source on GitLab or Codeberg is refused as any non-GitHub URL is, for now.
- Help and usage say it.

## Verification

- The registry test, against an httptest server for all three registries: each name's source, a module on a forge read without a request, a vanity path's go-import, names refused, no source, and the user agent; also under `-race`.
- `make test` with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.
