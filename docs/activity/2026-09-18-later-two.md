# Two small items from Later

The two candidates the drained queue pointed at first: the toolchain minimum for git-fetched module-mode ports, and the survey's coverage residues.

## go.toolchain_min from the repository

The toolchain rule read `go.mod` from the kept archive, and a git-fetched port keeps none on the host, so vault-shaped ports got no comparison. The forge repositories can now read one file at a commit, `forge.FileRepository`: GitHub through the contents API, which returns files up to a megabyte inline, and GitLab through the raw file endpoint, both bounded and both reporting an absent path as not found. `upstream.Service.Manifest` reads a file of the port's own repository at the resolved release's commit and reports an absent file as a missing manifest, as the archive read does; the editor takes it as `Manifests` and, for a git-fetched port, asks it for `go.mod` instead of searching downloads it does not have. Without a manifest source, or without a `go.mod` at the commit, the declared minimum stands, as before. The preparation adapter wires the upstream service in.

Against vault at an explicit 2.1.0, the read went to GitHub at the tag's commit and reported that the declared 1.26.4 already covers the 1.26 the repository's `go.mod` requires; a fixture with `go.toolchain_min 1.22` and a repository `go.mod` at 1.25 is raised, and the absent and unconfigured cases are left alone.

## The coverage residues

The corpus's three unknowns, each looked at:

- **rep-gtk** declared checksums for its patch files beside the archive's, an old convention from when MacPorts fetched patches that were not in `files`. With the patches present, the entries verify nothing. A declared group named by a patchfile that exists under `filespath` is now inert in the three coverage checks, left as written while the archive's entry is refreshed; absent from `files`, the patch would be fetched and checked, so its entry stays a declaration no archive covers. rep-gtk is ready; the corpus is 137 input-found, 8 unsupported, 2 unknown.
- **openjdk11** composes its version from two variables and a literal fragment, `${feature}.0.32.1` and a separate build number, which is the "multiple independent version inputs" design the roadmap already keeps separate.
- **gr-ieee802-15-4** pins a GitHub commit as its version with no tags to discover; a commit-pinned archive fetch is a design of its own, not a residue, and stays in Later.
