# 2026-10-02: the GitHub token read for each request (batch 44)

Batch 44 of the [roadmap](../roadmap.md), the first step of the "GitHub auth flow review" thread's plan for an expiring login, taken alone since it fixes serve today.

## What changed

- **A client asks its credential for each request.** `Client.AuthenticatedAPI` resolved the token once and gave it to go-github (`gh.WithAuthToken`), and the engine builds its forge client once, so a running serve carried the token it started with: a new `auth login` reached it only when it was started again, and after a 401 it stayed broken. The authenticated client now carries a `credentialTransport`, below the redirect guard, which sets each request's Authorization from a `credentials` holder; the holder keeps the token its source gave until five minutes before it expires, and a token with no expiry, as every one has now, for the process, as before, so the Keychain is read no more often than it was.
- **A 401 is tried once more with a token asked anew,** where the token came from dockhand's login or gh's: the holder is dropped and the source asked again, through `Renewer` where the source can renew a rejected token, as the login will in batch 45, and the request sent again with the new token, a write's body from `GetBody`; a 401 means GitHub did nothing, so a write is retried as safely as a read. The same token again, a second 401, or a token from GH_TOKEN, GITHUB_TOKEN, or configuration gives the rejection as before. A request another one already renewed for carries the renewed token without asking again.
- **`Token.Expiry`**, zero for one that doesn't expire or whose source doesn't say, kept from JSON as the secret is; `CredentialSource` reports the source of the token last carried.

## Verification

- `TestARejectedTokenIsReplacedAndTheRequestTriedAgain`, `TestARejectedWriteIsTriedAgainWithItsBody`, `TestATokenRejectedAgainOrFromTheEnvironmentIsRefused`, and `TestARunningClientCarriesARenewedToken`, against a GitHub stand-in.
- The full suite with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.
