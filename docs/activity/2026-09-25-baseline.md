# 2026-09-25: check --baseline and check.baseline

Design v3 §6.8: a baseline reports what happened in each run and nothing more.

## What changed

- **`check --baseline`** takes the ports that failed in the branch's latest finished check, or the ones named with `--only`. It builds them again at the master the branch starts from, in the same environments, and reports each port's result there beside its result on the branch:
  - `✓ builds at the base. This branch's result differs (check-2); the cause isn't established.`
  - `✗ fails at the base too, at install. Both results are kept; the cause isn't established.`
  - The results as the same are also reported: built at both, or failed at the base but built on the branch.

  A port the branch adds has no Portfile at the base, so it is left out, and the output says so.
- **Exit codes.** A baseline is evidence, so a port failing at the base doesn't fail the command: it exits 0. A run that needs attention exits 3, and a stopped one 130.
- **`check.baseline = true`** in the config runs a baseline of what failed right after a foreground check fails. `check -d` doesn't. The check's own exit code stands.
- **Recording.** A baseline run is marked in the new `runs.baseline_of` column (schema 6) with the check it looks into:
  - The branch's status and the publication rule skip it. A baseline that passes never reads as the branch's check, and never lets it be submitted (§3: "A baseline is evidence and never unblocks publication by itself").
  - `retry` of a baseline stays a baseline.
  - Its revision is the branch's base, recorded once as a commit revision of the branch.
- **The command provider** can build the base itself. Git refuses an empty bundle, so a baseline's bundle holds the base less its parent, which the receiver has too. `docs/command-provider.md` says so.

## Tests

The build script takes its outcome from a file, so the branch can fail while the base passes. The test covers:
- a baseline refused with no check yet, and with nothing failed;
- a failed check, then a baseline passing at the base, reported as a difference and exiting 0;
- `status` still showing the failed check, and nothing submitted;
- `check.baseline = true` running one by itself after a failure, reporting a failure at the base too.

The first run of this test found both the empty bundle and a baseline that needed attention exiting 0. Both are fixed.
