# Cobra integration report — September 10, 2026

Added `github.com/spf13/cobra` v1.10.2, matching the version in Dockhand v1. The selected pflag dependency remains at v1.0.10, also matching v1; mousetrap v1.1.0 is an indirect dependency. Added `go.sum` and kept the Go module path and Go version unchanged. No other v1 application dependencies were added.

## Command-layer structure

`internal/cli` owns all Cobra integration. `cli.Run` constructs a fresh command tree, supplies arguments and input/output/error streams, and executes it with the caller's context. It passes an explicit empty argument slice when no arguments are supplied, preventing Cobra from falling back to the embedding process's arguments. The executable entry point remains small and prints returned errors once; Cobra's automatic error/usage printing is disabled.

`cli.NewRoot` initializes startup configuration through `app.Initialize` before Cobra executes. This preserves config-directory creation for help and completion without relying on pre-run hooks that help bypasses. It registers `--lockfile` and `--json` as persistent flags. A small pflag-compatible path value rejects an explicitly empty lockfile and resolves relative overrides. Cobra performs the actual argument parsing; the hand-written `ParseGlobal` parser and its `GlobalOptions` type were removed.

The phase-one command tree contains `setup`, `bump`, `bump-revision`, `refresh-checksums`, `verify`, `publish`, `status`, `wait`, `cancel`, `start`, and `review accept`/`review dismiss`. Command-specific waiting, tracing, preview, publication, and verification-skipping flags follow the CLI design. Boolean shorthand flags `-N` and `-P` are supported. Cobra checks positional argument counts and declared incompatible flag groups before a workflow handler opens the repository. Trace sets the effective attachment option to wait through completion, without changing publication intent.

Help and usage are generated from the same command tree. `usage` aliases Cobra's help command, including nested command paths. Help displays the resolved config-directory and lockfile paths. Cobra's shell-completion generation is available through `completion`. These paths work outside a Git repository and do not build repository services or call providers.

Workflow handlers remain placeholders behind a shared execution boundary receiving the command, arguments, parsed options, streams, context, and application services. Repository service construction stays in `app`; no workflow transitions moved into Cobra callbacks. `setup` uses the existing application setup boundary without opening a repository first. JSON is parsed as an output preference; JSON result rendering, target resolution, request submission, and actual workflow execution remain unimplemented. No command reports a successful build, publication, or accepted job.

## Validation

`go build ./...`, `go vet ./...`, formatting checks, and `go mod verify` passed. The selected Cobra, pflag, and mousetrap checksums match v1's `go.sum`. Dependency archives were obtained from the existing module cache; no dependency cache or vendored files were installed in the project.

A newly authored temporary integration harness ran with the race detector against disposable directories and a Git repository. It checked:

- Every phase-one command, nested review commands, local flags, inherited globals, combined short flags, and explicit pending-workflow results.
- Root/command/nested help, the usage alias, and completion generation for Bash, Zsh, Fish, and PowerShell outside a Git repository.
- Missing or excess arguments, unknown commands and flags, missing/empty lockfile values, and incompatible flag groups before repository dependency construction.
- Global options before and after command names, equals syntax, repeated overrides, and literal arguments after `--`.
- Startup home/environment defaults, relative lockfile overrides, paths containing spaces, and help without creating a ledger lockfile.
- Fresh configuration and flag state between invocations, explicit empty argument handling, correct output/error routing, and errors printed once by the executable.

The harness, temporary config directories, module cache, and compiled binary were kept outside the project. No test suite was copied or added, and no real ports tree, VM, remote repository, or forge was modified.

## Follow-up: lockfile simplification

The config-directory setting, environment override, and startup directory creation have been removed. `--lockfile` now has the short alias `-L`, with the default `$HOME/.dockhand/ledger.lock` owned by Cobra. Ledger construction creates the lockfile and missing parent directories; help and completion create nothing. See the [lockfile simplification report](2026-09-11-lockfile.md) for the current behavior.
