# 2026-10-23: After rc5, two fixes for main

Both ride the release after v0.5.0. Neither touches rc5's acceptance.

## A replacement of someone's push must be their commit amended

D-S1 on rc4 (herbyg-test/macports-ports#84). submit's amend rule let a
commit replace what someone else pushed wherever the branch's reflog had
once seen their commit. Pulling a collaborator's commit, resetting it away
and submitting replaced their work, although the preview named it.
D-S1's harness made exactly that case (fixed in the harness, d9dd31ae).

- **The rule:** the replacement must also be their commit amended.
  `git.Repository.Amends` checks that it was made on their commit's first
  parent, or that its tree holds each file their commit changes exactly as
  their commit has it. An empty commit is amended only on its parent, since
  no tree holds anything of it.
- **Kept:** a commit on top of theirs still goes, leased to their commit.
  py-coremltools' amend (#35220) still goes, since it's made on their
  parent.
- **Tests:** TestSubmitUpdatesThePullRequestAndKeepsAPersonsDescription
  gains D-S1's case: a pull, a reset back to the branch's own commit, and
  an amend of that commit. It holds as someone else's push, and fails
  without the fix. TestAmendsIsTheirCommitAmended covers the rule's cases,
  the empty commit among them.

## A module go2port couldn't fetch is named

The corpus's terraform-ls 0.39.0 refused with "dependency: missing
generated Go checksum". go2port couldn't fetch the archive of
github.com/chigopher/pathlib, whose repository is gone, and wrote it a
sha256 of 0.

- `goRows` now returns `depblock.MissingChecksum{Module, Lock}`.
  `generateGo` reads go2port's standard error, which `run` now returns
  beside its output, and says: "go2port couldn't fetch
  github.com/chigopher/pathlib v1.0.0's archive (HTTP 404); its repository
  may be gone, so it wrote the module no checksum".
- The corpus row records that refusal.
- The roadmap asked whether keeping the Portfile's row for the gone module
  might let the update plan, as KeepGoModules keeps a pin. Checked: it
  wouldn't. The Portfile pins pathlib at v0.15.0, at 0.38.8 and at 0.39.0
  alike, but go2port's output for 0.38.8 has v1.0.0, so the Portfile's row
  isn't the one go.sum asks for.

## A signed-out refresh reads open pull requests first

rc5's D-C2: logged out, serve read 15 stale test pull requests one at a
time, used up GitHub's 60-an-hour anonymous limit, and never saw #88 close.
Prioritization placed the fix in 9ad891d2.

- **Where:** the rule is the engine's, in `RefreshPullRequests`, so
  status's and clean's refreshes share it with serve's. Signed in, nothing
  changes: one GraphQL read covers every branch.
- **Signed out:** `readPullRequests` now says whether its reads are
  signed in. Signed out, only the open branches with a pull request are
  read, newest pull request first, and closed ones wait for a signed-in
  refresh, which picks up a reopening.
- **At the limit:** a rate limit stops any refresh, since the rest would be
  refused alike. `RefreshResult.Unread` and `RetryAt` say how many were left
  unread and when the limit lifts, and `UnreadWords` says it: "GitHub’s
  rate limit left 1 pull request unread. Reading again after 15:04 EDT".
  serve reports it once, and status and clean print it.
- **Test:** TestASignedOutRefreshReadsOpenPullRequestsNewestFirst has 16
  records, the newest one open. On an allowance of 60 it reads that one
  alone, no closed one, and sees #88 close. With the allowance spent, it
  says one was left unread.
