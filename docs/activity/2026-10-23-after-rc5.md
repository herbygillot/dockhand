# 2026-10-23: After rc5, two fixes for main

Both ride the release after v0.5.0. Neither touches rc5's acceptance.

## A replacement of someone's push must be their commit amended

D-S1 on rc4 (herbyg-test/macports-ports#84). submit's amend rule let a
commit replace what someone else pushed wherever the branch's reflog had
once seen their commit. Pulling a collaborator's commit, resetting it away
and submitting replaced their work, although the preview named it.
D-S1's harness made exactly that case (fixed in the harness, d9dd31ae).

- **The rule:** the replacement must also be their commit amended.
  `git.Repository.Amends` checks that it was made on their commit's first
  parent, or that its tree holds each file their commit changes exactly as
  their commit has it. An empty commit is amended only on its parent, since
  no tree holds anything of it.
- **Kept:** a commit on top of theirs still goes, leased to their commit.
  py-coremltools' amend (#35220) still goes, since it's made on their
  parent.
- **Tests:** TestSubmitUpdatesThePullRequestAndKeepsAPersonsDescription
  gains D-S1's case: a pull, a reset back to the branch's own commit, and
  an amend of that commit. It holds as someone else's push, and fails
  without the fix. TestAmendsIsTheirCommitAmended covers the rule's cases,
  the empty commit among them.

## A module go2port couldn't fetch is named

The corpus's terraform-ls 0.39.0 refused with "dependency: missing
generated Go checksum". go2port couldn't fetch the archive of
github.com/chigopher/pathlib, whose repository is gone, and wrote it a
sha256 of 0.

- `goRows` now returns `depblock.MissingChecksum{Module, Lock}`.
  `generateGo` reads go2port's standard error, which `run` now returns
  beside its output, and says: "go2port couldn't fetch
  github.com/chigopher/pathlib v1.0.0's archive (HTTP 404); its repository
  may be gone, so it wrote the module no checksum".
- The corpus row records that refusal.
- The roadmap asked whether keeping the Portfile's row for the gone module
  might let the update plan, as KeepGoModules keeps a pin. Checked: it
  wouldn't. The Portfile pins pathlib at v0.15.0, at 0.38.8 and at 0.39.0
  alike, but go2port's output for 0.38.8 has v1.0.0, so the Portfile's row
  isn't the one go.sum asks for.

## A signed-out refresh reads open pull requests first

rc5's D-C2: logged out, serve read 15 stale test pull requests one at a
time, used up GitHub's 60-an-hour anonymous limit, and never saw #88 close.
Prioritization placed the fix in 9ad891d2.

- **Where:** the rule is the engine's, in `RefreshPullRequests`, so
  status's and clean's refreshes share it with serve's. Signed in, nothing
  changes: one GraphQL read covers every branch.
- **Signed out:** `readPullRequests` now says whether its reads are
  signed in. Signed out, only the open branches with a pull request are
  read, newest pull request first, and closed ones wait for a signed-in
  refresh, which picks up a reopening.
- **At the limit:** a rate limit stops any refresh, since the rest would be
  refused alike. `RefreshResult.Unread` and `RetryAt` say how many were left
  unread and when the limit lifts, and `UnreadWords` says it: "GitHub’s
  rate limit left 1 pull request unread. Reading again after 15:04 EDT".
  serve reports it once, and status and clean print it.
- **Test:** TestASignedOutRefreshReadsOpenPullRequestsNewestFirst has 16
  records, the newest one open. On an allowance of 60 it reads that one
  alone, no closed one, and sees #88 close. With the allowance spent, it
  says one was left unread.

## A signed-out refresh spends one request a pull request

Prime-time's rerun of D-C2 on rc5: signed out, each open pull request cost
at least five REST requests a refresh. Those were Observe's Get, then
Inspect's Get, ListReviews, ListCheckRunsForRef and GetCombinedStatus,
with CI's logs on a failing head. Every 5 minutes, that's the hour's 60
for a single pull request, and #88 and #89 were never read. Prioritization
placed the fix in c792f466.

- **One request:** signed out, `observeState` reads the state and head
  alone, with Observe. The review, checks and failing jobs recorded stay
  as they were, never cleared, and classifyCI is skipped. Signed in,
  nothing changes.
- **A reserve:** the refresh stops 10 requests short of the hour's
  allowance (`anonymousReserve`). The allowance is read from GitHub's
  rate_limit endpoint, which costs nothing, through a new
  `forge.AllowanceReader`. `github.Client.Allowance` carries what
  `Runtime.Allowance` did, and the forge's GitHub client's `RequestsLeft`
  answers through it. What's left unread is said with d922dbb2's line.
- **Test:** the signed-out refresh test gains a case with 12 requests
  left and five open pull requests. It reads the newest two, inspects
  none, leaves three unread, and keeps each one's recorded review and
  failing checks.
- **README:** the hourly-limit row now says that signed out the limit is
  60 an hour, which serve's watch of one open pull request spends, and to
  sign in.

## A license file whose only change is its party

Field testing: vault 2.2's LICENSE names "International Business Machines
Corporation (IBM)" as its licensor, and "IBM Corp." in six places, where
2.1.2's named "HashiCorp, Inc." and "HashiCorp". The Business Source
License terms are the same word for word. It held as "LICENSE changed; the
Portfile's license line may need to follow".

- **Detection:** sourcecompare's `partyOnly` compares the two texts word
  by word, by their longest common subsequence. Each change must replace a
  few words (at most 8, `partyWords`), with nothing only added or removed.
  Every old run must share a word, here HashiCorp, with possessives and
  punctuation set aside, and every new run must share one, here IBM. The
  party has to be named in at least two places, and licensecheck has to
  find the same licenses in both texts, or none in either: a single word
  swapped for another, as "MIT" for "Apache-2.0" in a test's LICENSE, is a
  license's change. Such a
  change is a license change of its own, How "party", rule
  `license-party`. It reads "upstream's LICENSE changed only the party it
  names, HashiCorp to IBM, in 7 places", and holds nothing, as a
  years-only change doesn't. Text changed beside the name is still the
  license's change.
- **Test:** TestALicensesRenamedPartyIsSaid uses vault's two LICENSE files
  (internal/sourcecompare/testdata/vault), then the same with a term
  reworded, which is a changed license.
- vault's update to 2.2.1 now plans with the party line, and no license
  hold.
- **Corpus:** vault joins it, by the rule for a port a finding names. No
  MacPorts bump to 2.2 exists yet, so its row replays the 2.1.2 bump.

## A revision set through a variable resets (2026-10-24)

Field testing: `update mysql9` refused with "revision is calculated or
overridden". mysql9's subports write `revision ${revision_client}` and
`revision ${revision_server}`, from `set revision_client 1` and
`set revision_server 1`. mysql8 went through only because its two were
already 0. Prioritization placed the fix in 2361088c.

- **portfile.SetLiteral** gives the value word of the one `set name
  <literal>` a Portfile writes, at any depth. It refuses a variable set
  twice, or not as a literal.
- **revisionReset:** where a revision's word is one variable (`$v` or
  `${v}`) and that variable is set once to the evaluated revision, the
  set's literal is reset to 0. Strict fidelity's check, after the edit,
  refuses one that moves anything else, another release's revision among
  them.
- **Tests:** TestPrepareResetsARevisionSetThroughAVariable covers mysql9's
  layout, with both lines reset, plus a variable set twice, which refuses,
  and a variable another release's subport reads, which strict fidelity
  refuses at fixture-legacy.revision.
- **mysql9:** a scratch `update mysql9 --new --plan` goes 9.7.2_1 to 9.7.4
  with both `set revision_*` lines at 0.
- **Corpus:** the corpus compares `set revision*` lines as the revision's.
  mariadb-10.11's 10.11.19 bump, a50e4e482ab, is the same shape and joins
  it. It passes on main and fails on rc4. mysql9 joins once MacPorts has a
  bump of it to replay, since field testing's isn't merged yet.
