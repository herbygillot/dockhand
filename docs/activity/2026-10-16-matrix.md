# The build matrix shows what was built

Herby's word, 2026-10-16, from the first `ship lazygit --yes` (#35566):
releases a build profile didn't build on aren't "not built" cells in the
pull request's matrix; keep the macOS versions builds happened on. The
terminal's table follows, so the two match.

- `model.Exclusion.Span`: the exclusion is minmax's choice, not a fact of
  the port. planning marks it where it makes the reason (`spanReason`),
  so nothing downstream reads the words. Stored in the plan's JSON, so no
  schema change; plans made before it carry none, and show as before.
- `evidence.Evidence.Shown()`: the environments a table shows, each but
  those where every target is a Span exclusion. `engine/body.go`'s Tested
  on table and `command/check.go`'s `writeResults` take it.
- In a release that is shown, a Span cell reads "—" (`targetWords`), where
  it read "— not built: minmax builds it on …" in full.
- Kept, as a port's own fact: an exclusion like known_fail stays a "— not
  built: …" cell, as wasmer's macOS 12 needed (#35077). Kept, too, the line
  under the table naming CI releases no check built: roadmap item 1's
  wording now says the table and that line apart, where the coordinator
  read them as one.
