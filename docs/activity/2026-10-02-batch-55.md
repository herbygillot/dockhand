# 2026-10-02: providers and coordination (batch 55)

Batch 55 of the [roadmap](../roadmap.md): the test plan's step 2 for the providers and coordination, step 3's Actions client and Tart registration, D20, and the library survey's launchd writer.

## What changed

- **The guards are tested:** setup's three refusals to clone or import over a VM Tart lists, with nothing cloned or imported (`tart/provision`); `DeleteCached`, removing only an image Tart lists as from a registry and saying one still listed after it (`tart/host`); the Actions provider leaving its check branch where it moved since the check, and removing it where it holds the commit (`buildenv/ghactions`); a run whose cancel was asked for while another held it, canceled by the next driver rather than built (`engine`); and a lease released for a resource never leased, stale and said (`store/sqlite`). None found a defect. A check branch already gone is said as removed, which `DeleteRemoteBranch` documents.
- **The Actions REST client is tested** against a server answering as GitHub documents: a branch's runs for a commit across pages, one run, its jobs at an attempt with their labels and runner, a rerun of the failed jobs, and a cancel GitHub accepts with 202. **Tart is registered where `tart` is found**, which no test reached, since the tests find none.
- **D20: `logs --port` starts a GitHub check's log at the port's own build**, as a Tart check's does: the Actions provider records each subport's steps by the workflow's `::group::` headings, which it read already for outcomes ("Installing dependencies for", "Installing", "Testing"), so the step after the dependencies' is where the port's own install begins. A runner's log without the headings is printed whole, and said to be.
- **One launchd writer:** `macos.LaunchdJob`, which `LaunchdPlist` is, with `KeepAlive` and `ProcessType`, now writes serve's agent, escaping its environment's keys too, where serve's own writer escaped only values. What the other callers write is unchanged, byte for byte; serve's agent is the same job in the shared form, which an installed one takes at the next `serve --install`.

## Not changed

- **The guest agent's plists in `tart/provision` stay as they are.** Their values are constants, so nothing is unescaped in practice, and they're part of what setup puts in an image: moving them onto the shared writer changes the provisioning code's bytes, which the setup pin says needs `tart.SetupProtocol` raised, ending the reuse of every check's evidence from images made before. That's worth doing only with a change that alters images anyway.
