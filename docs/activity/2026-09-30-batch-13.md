# 2026-09-30: the comparison's depth (batch 13)

Batch 13 of the [roadmap](../roadmap.md): what the upstream comparison didn't yet read, and two findings from the zola run with 68df8b57. Its fourth item, an upstream comparison for a version changed by hand, came with item 9's step 3.

## What changed

- **A Node project's workspaces are read with it.** beekeeper-studio 6.1.4 added `devicon` and `simple-icons` and moved electron from 39.8.5 to 39.8.10 in `apps/studio/package.json`, a yarn workspace, and the comparison said "no license, build file, or dependency changes", since it read the root's manifests alone.
  - `project.Read` reads the `package.json` of each workspace the root's names, in a second pass over the archive, taken only where the root names any, since the root's may come after theirs.
  - Patterns are globs of the path below the root, `**` standing for any depth and `!` leaving one out, as yarn and npm read them; `node_modules` is never a workspace.
  - `ReadPackageJSON` reads `workspaces`, an array or yarn's `{packages: …}` object, and any other shape names none rather than failing the manifest. It reads `license` too, for the license item below.
  - `project.ReaderVersion` is 2, so a kept reading made before doesn't stand.
  - A workspace's manifest is then compared as the root's is, by its path.
- **A Python project's `requires-python` is its own line,** as go.mod's `go` directive is a Go project's (the sshuttle run). sshuttle 2.0.0 raised it from `>=3.9` to `>=3.10`, and nothing said so.
  - `assess`'s `python-requires` says a move with `·`, and whether it admits the Pythons the port builds for. One that leaves one out holds, since a build needn't enforce it: a wheel is installed without asking. Against the base, as D14 has it: one the base left out too, with that Python built there, is said and holds nothing, and where the base's project said nothing of it, its baseline is unknown.
  - A specifier's verdict on a series can turn on the patch release, as `>=3.13.2`'s does on 3.13. There `assess.Wanted` asks for the version of MacPorts' own `python313`, as it asks for a requirement's provider, and one that can't be observed holds, as not judged.
  - The Pythons a port builds for are `macports.PortInfo.Pythons`: a `py313-` subport's own, else its `python.versions`, else the `python.version` an application's port pins. The evaluator now reads `python.versions`, `python.version`, and `python.default_version`.
- **A pin behind the python PortGroup's default is a quiet note** (`python-pin-behind`). sshuttle pins 3.13 where the default is 3.14.
  - The default is the PortGroup's own, `python_get_default_version`, which two Portfiles call too, so it's an interface MacPorts keeps. The evaluator computes it as `dockhand.python_default`, and `PortInfo.PythonPinned` reads it beside the pin. For a port whose `python.versions` lack 3.14, the default is the newest it names, so a port that can't take 3.14 yet hears nothing.
  - It isn't said where the new version's `requires-python` leaves the default out, the pin then being upstream's own ceiling, nor of a subport, whose stub carries the pin.
- **A license file's change names its evidence** ([zola, with 68df8b57](../reviews/2026-09-28-hugo-bump-exercise.md#zola-with-68df8b57), finding 1). zola relicensed to EUPL-1.2 in 0.22.0, and master's `license MIT` had been wrong since; the hold was right, but said only "LICENSE-MIT was added".
  - It now says what the project's manifest declares beside the Portfile's line: "Cargo.toml says EUPL-1.2, and the Portfile says MIT", or "Cargo.toml's license moves from MIT to EUPL-1.2" where the manifest's moved.
  - Where the candidate's license line names what the manifest declares, and the base's didn't, the Portfile has followed, and it's said with `·`: "Cargo.toml says EUPL-1.2, which the Portfile's license line now names". One the base named already still holds, since the new file isn't what the line followed.
  - The owners: `project.Reading.DeclaredLicense` reads the root manifest's license (Cargo.toml's, pyproject.toml's, or package.json's); `macports.License` maps it, now with EUPL-1.1 and EUPL-1.2, as four ports write them; `macports.LicenseNames` says whether a line names each license of another, a choice's included.
  - "the Portfile's license line may need to follow" is `assess`'s advice now, not `sourcecompare`'s, which says only what changed; every message it was in reads as before.
- **`assess.Policy` is 3.**
