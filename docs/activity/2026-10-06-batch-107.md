# 2026-10-06: bump takes submit's title, note, and skip notification (batch 107)

From the v0.3.0-rc6 full stage's B2. It comes after v0.3.0-rc6, for the release candidate after the run.

## What changed

- **`bump` and `update --submit` take `--title`, `--note`, and `--skip-notification`,** passed to the submission as `submit` takes them. B2's bump opened its pull request, herbyg-test/macports-ports#3, with nothing to mark it a test, since bump took none; `update` without `--submit` refuses them, as it refuses `--on`.
- **B2 marks its pull request a test one,** titled `[testing] …`, with the note and `--skip-notification` submit_pr gives, unless the approval list made it real.

- **master's refusal says its advice once.** The engine's refusal on your checkout's master named `-b`, and the command added "name one with -b <branch> or -p <port>" again; the engine's now names both, and the command adds nothing to it (`engine.ErrYourCheckout`).
- **archive reads the pull request's state before saying it's still open.** It went by the recorded state, and said "#3 is still open" of one closed with gh; it now asks GitHub, and falls back to the record where GitHub can't be read (`Archived.PullRequestOpen`).

- **A branch whose worktree and Git branch are both gone says what to do.** `revbump … --branch poppler-25.09`, after its Git branch was deleted by hand, refused with no way out; it now says "nothing of it is left: dockhand archive poppler-25.09 sets its record aside, and another name starts afresh". The name itself stays the archived record's: branch names are unique among branches not merged (schema 1's `branch_name` index), so reusing one needs a schema change, or a command that forgets a record, for the person to choose.
- **A10 counts a `submit --plan` example that needs a finished check as not run.** It runs `check` only as its plan, and submit's preview rightly refuses a commit no check passed; rc5's A10 passed only by finding A4's checked branch.

## Later: a check after a rebase

B5 rebased onto a newer master and submitted again, and submit refused: "no check has finished for this commit's files". That's by design: a rebase moves the commit, and evidence is for a commit's files; the check after a rebase reuses the earlier build, without building, where the port reads the same files (decision 28), which is what B5 meant by "a check that still applies is reused". B5 now checks between the rebase and the submit, and fails unless that check reused a build. `check --plan`, which can't say which ports reuse, since reuse is chosen as the check runs, now says on a branch with a passed check that "a port whose earlier passed build read the same files is reused when the check runs, not built; --fresh builds every port": it had read as a full build.

submit's refusal says the same where the branch has a passed check: "no check has finished for this commit's files; dockhand check reuses check-N's builds where a port reads the same files, building only what changed". Whether submit or rebase should make that check itself is left for the person: it would build where a port's files changed, which submit has never done unasked.
