# 2026-10-03: batch output a person can act on (batch 68)

Batch 68 of the [roadmap](../roadmap.md): the onboarding UX's share of the command-line UX review's §10, from field testing's notes of 2026-10-02. Severity marks apart from holds are layer 1's.

## What changed

- **`update --outdated`'s preview is a row a port:** the branch's name, and the port's version from and to, flagged where it's a new major version (`PlannedUpdate.CrossesMajor`, through `version.CrossesMajor`). The preview had said only "Will start 9 branches" and their names. With batch 65's names, the names it shows are the ones the run uses. Whether a port's edit can be made isn't known until it's tried, and a port that can't now starts no branch (batch 67).
- **Long lists name their first few and count the rest:** `prose.Few` and `prose.FewJoined`, for example "18 ports: terraform-1.16, terraform-1.17, terraform-1.18 and 15 more". This applies to a check plan's Changed, Also, and Order lines, eight named, and to an update's direct library dependents, twelve. `--json` carries every one. The review asks for the whole list at `-v` too. These writers take no context, and `-v` reports on standard error, so that's left for when they do.
- **A batch's exit says whether anything worked.** It exits 0 where every port was done, 3 where some were and the rest need a look, and 1 where none could be done. Before, an `update --outdated` whose nine ports all failed exited 3, like a held bump.
- usage says it.

## Verification

- The preview's row for jq, with the name the run uses.
- A batch's exit: none done, some done, all done.
- `prose.Few` with a short list, a long one, and none.
- `make test` with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.
