# 2026-10-02: the latent and the bounded (batch 36)

Batch 36 of the [roadmap](../roadmap.md), the last of the core made solid: the code-organization review's latent findings and one-shots, the evaluator's call bound tried against its heaviest real calls, and the tests that failed under load.

## What changed

- **The one-shots through `subprocess.Run`** (the [code-organization review](../reviews/2026-09-27-code-organization-review.md)'s finding 42, as batch 26 bounded the rest). `security`'s three calls, `pkgutil`, `gh auth token`, `gh pr ready`, `open`, `osascript`, `launchctl`, and `port version` called `os/exec` directly, with no bound on their wait and no shared error shape; each is now a `subprocess.Run`, with a bound on its output. `security -i`'s error says how it ended and never what it wrote, since its standard input is the secret. What still calls `os/exec` is what `subprocess`'s package comment allows: an editor, `xcodes`, the Tcl interpreter, a guest, a person's build, a decompressor, and the background cleanup.
- **One wait for a guest's SSH, which stops at a refusal** (finding 7). The provider, provisioning, and the facts tool each had a wait; only provisioning's stopped when the guest answered and refused, and the provider's retried for four minutes, dropping what ssh said, and the runner tried twice more. `channel.AwaitSSH` is the one wait: a failed connection is waited out, a refusal ("Host key verification failed", "Permission denied") ends it at once (`channel.ErrRefused`), as does any other failure and the VM's run ending. The provider marks a refusal `buildenv.ErrNeedsAttention`, which the runner tries no more: "the guest refused SSH; another attempt won't fix it, so none was made".
- **A write whose commit was uncertain, read back** (finding 24). `store.Recorded` runs a write and, only where its commit's outcome is unknown, asks a witness whether it landed, outside the caller's cancel. A new branch (`Start`, `AdoptPullRequest`), an update's and a create's edit record, and history's three checkpoint writes go through it; an update's files are written first, and a record that landed stands, where the update had said it failed. The policy is on `store.ErrUncertain`.
- **A remote read outside any repository** (finding 30). `ls-remote` by URL ran from the temporary directory, which a repository could enclose, so its `url.insteadOf` rewrote the URL; the review's verifier reproduced it. The three reads run in a fresh scratch directory with `GIT_CEILING_DIRECTORIES` at its parent; the test reproduces the rewrite with plain git and shows dockhand's read isn't rewritten.
- **The store's error kinds documented** (finding 41): `ErrConflict` as the store keeping its own contract, `ErrUnavailable` as anything else the driver gives, a busy database among it, `ErrUncertain` with the read-back policy, and what `Build.Record`'s error means to the runner.
- **No credentials remembered a while** (finding 45). Each anonymous read ran `security` and `gh auth token` again; finding none is remembered for five minutes, and an operation that needs a login always looks, so a running serve uses a login made meanwhile.
- **The evaluator's call bound against its heaviest real calls** (batch 26's leftover), in a live test, `TestTheCallBoundHoldsForTheHeaviestRealCalls`, which runs where `DOCKHAND_TEST_PORTS_TREE` names a ports tree. On the checkout at efde56cae1f: a session started, `initialize` among it, in 46 to 107 ms; a subport of `lang/php`, whose Portfile defines 605, in 23 to 28 ms, and of `textproc/tesseract`'s 101 the same; php's whole family in 13.3 s, a call each, each bounded alone. Every call is far inside the five minutes, so the bound ends only one that hung. The file cache was warm; a cold one needs `sudo purge`, which wasn't run.
- **Tests under load given room** (2026-10-01's run at load 40 to 194):
  - `TestReleasesTakeTheMacsSlotsInTurn` assumed the second release asked for a slot while the first's VM ran; under load the first could finish first, and nothing waited. The first VM now stops only once a release has said it's waiting, so they overlap however they're scheduled. A hundred runs at load 30 passed before the change, as the failure needed more.
  - `TestSubmitCheckKeepsToOneCheckAndItsCommit`'s "git ls-tree: exec: WaitDelay expired before I/O complete" was production code: Go starts `WaitDelay`'s timer as the process exits, so git's second bounded copying output it had already written. `subprocess.DefaultWaitDelay` is 15 seconds, which git uses too; a canceled command is still killed at once.
  - `TestStderrRetainsTail` waits for its writer to finish, and `TestBranchLockSurvivesDriverExitWhileGitStillRuns` gives its child a minute to start: upper bounds that end as soon as their condition holds.
  - `make test` and `make test-race` take `-timeout 40m` (`TEST_TIMEOUT`), since the engine and command packages ran past `go test`'s ten-minute default.

## Decided along the way

- **`decodePlan`'s branch for plans recorded before each environment had its own stays.** The review would delete it under the pre-release licence; plans recorded since September may still be read that way, and the item was the documentation.
- **The coordination lease's retry on `ErrUncertain` isn't taken.** The review narrowed it as starving no run; nothing asked for it.
- **Setup's protocol stays 3.** Provisioning's SSH wait moved to `channel.AwaitSSH`, which changes what it says, not what an image holds, so the pin its protocol test keeps moves instead.
- **A simulated clock wasn't the fix for these tests:** each waits on a real process, which no clock speeds up. Room, ending as soon as the condition holds, costs nothing when the machine is idle.
