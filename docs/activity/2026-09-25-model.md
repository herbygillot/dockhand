# 2026-09-25: the v3 model

Roadmap step 5, part 1: `internal/model`, v3's records and the vocabulary the domain packages share.

## The vocabulary moves out of `record`

`ObjectID`, `RepositoryID`, `Source`, `Target`, `Platform`, `CompareTargets`, and `Digest` now live in `model`. `record` keeps type aliases, plus two one-line functions, so the forty-odd domain packages that import them compile unchanged. They can move to `model` directly as each is touched, and `record` goes when step 5 replaces its workflow records.

`model` is a leaf package that imports nothing from dockhand. That's the role `record` played, and it lets every package use the vocabulary without depending on the engine.

## The v3 records (Design v3 §3)

- **`Branch`.** An ID separate from its Git name, a base, a worktree (managed or the person's own), a title, a state, and at most one `PullRequest`. States are open, merged, closed, and archived. A merge is final; closed and archived branches can reopen. A light check of the name follows `git check-ref-format`'s rules; Git stays the authority.
- **`Revision`.** Either a commit or a numbered snapshot of working files, which has a tree and no commit and records the checked-out head as provenance. `SameTree` is what lets a result for a snapshot apply to the commit `tidy` makes of it, when the base is the same too.
- **`Plan`.** Frozen coverage for one revision. Targets are in dependency order, each with a role (changed, also, or prerequisite) and a kind (substantive, revision-only, or unchanged). A plan also carries its exclusions with reasons, unresolved targets (a plan with any cannot run), the selection as given, every required environment, and a test policy. Validation checks that kinds fit roles and that each dependency comes earlier in the order.
- **`Run`.** One accepted check request, named `check-<n>` for people, with an origin (person or `serve`) that decides its place in the queue. States go queued → running → passed, failed, attention, or canceled, and a verdict is final.
- **`GuestExecution`.** The single owner of one environment for a run, per attempt, up to three in all (decision 30). An infrastructure failure ends an execution, and a retry is a new one.
- **`TargetResult`.** The checkpoint for one target in one execution. Outcomes are passed, failed at a phase, blocked, interrupted, not run, or unevaluated. Tests are reported apart from the verdict. A complete verdict (passed, failed, or blocked) is never replaced; a target that hadn't run can be marked interrupted when its guest is lost.
