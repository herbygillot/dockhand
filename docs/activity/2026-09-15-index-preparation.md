# Index preparation before Tart admission

Tart now materializes, indexes, validates targets, and packs source before reserving a VM slot or cloning/starting a guest. A preliminary capacity read avoids work when the pool is already full; the existing transactional reservation rechecks capacity after preparation. Cancellation and preparation errors therefore leave no VM reservation. Prepared archives are temporary until reservation and ordinary returns remove them; admitted inputs retain the existing artifact lifecycle. Recovery still reconciles the recorded execution rather than preparing another guest.

`macports/portindex` retains exact candidate indexes keyed by baseline tree and candidate tree. Standalone indexes remain in a separate namespace and use a last-successful-tree hint only as an incremental seed. The complete immutable Git diff determines changed directories; shared-resource edits force full indexing, and missing seed objects fall back to a full pass. A complete baseline index can seed candidates without being regenerated. The profile lock continues to serialize cache changes across processes. No SQLite schema or package boundary changed.

Regression evidence: the baseline/candidate fixture invokes the indexer once for its base and once incrementally for its change; re-staging either exact input adds no calls. Native MacPorts tests check standalone version edits, removed ports/subports, preserved existing parse gaps, and full invalidation after resource changes. Provider tests inspect the pool during source packing and prove no occupied reservation or clone exists, including cancellation, indexer failure, and an external VM consuming capacity before reservation.

Validation: `go test ./internal/macports/portindex ./internal/verify/tart ./internal/verify/staging` passed. These are native indexing and simulated VM lifecycle regressions; no new live VM build was needed for the ordering change. All implementation and test additions were authored for this design.
