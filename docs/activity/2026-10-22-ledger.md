# The ledger, finding kinds, and the decision record (v0.5.0 part 2, item 2)

## The reason a failure is accepted is a kind (R3-30)

`SubmitPlan.Accepted` held a sentence for each accepted failure, and words.go compared that sentence (`accepted == acceptedBlocked`) to decide how a blocked cell reads. It's now `engine.AcceptedFailure{Kind, Baselines}`:
- `AcceptedAtBase` carries the baselines that fail the port alike, the fact `AtBase` keeps.
- `AcceptedUnestablished` and `AcceptedBlocked` carry nothing more.

`Words()` says each kind as before, so the pull request's table, the preview's Checks line, and the terminal read unchanged. `submit --json` gains `accepted`, each port with its `kind`, `baselines`, and `words`. A standing acceptance of an environment failure is then one more kind.
