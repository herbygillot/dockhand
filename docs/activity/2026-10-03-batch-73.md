# 2026-10-03: failpoints, and release prep's code items (batch 73)

Batch 73 of the [roadmap](../roadmap.md): step 2a's H5, and step 3, release prep's code items, with field testing batch 10's open findings.

## What changed

- **Failpoints** (`internal/failpoint`). `failpoint.Hit(step)` does nothing in a normal build. Built with the `acceptance` tag, `DOCKHAND_FAILPOINT=<step>:kill` kills dockhand at that step: `update.prepared`, `tidy.prepared`, `rebase.prepared`, `submit.pushed`, and `check.running`. A test proves a normal build ignores the variable; `make test` also runs the tagged package's tests, and quick.sh builds `DH_FAILPOINT_BIN` for the kill rows.
- **The `Next:` rule.** A `Next:` line runs where the branch is: when the command wasn't run in the branch's worktree, it starts with `cd "$(dockhand path <branch>)"`, so each command it names accepts the branch as it stands (`nextIn`, used by edit, rebase, create, and impact). A reason is parenthesised, "Next: dockhand check (the files it builds on have changed)", so H6 can run the command alone. `providers setup tart` says "Checks build on it with --on tart:X." rather than a `Next:` that isn't one. setup's `Next:` names `outdated --mine` only once a maintainer is set. The checksums dead end now says to edit the version and checksums yourself and that `port checksum` shows what the archives have, after the version's edit.
- **The experimental notice:** `review` and `adopt --pr` say first that they evaluate the pull request's Portfiles, its author's, with MacPorts on this Mac.
- **README:** "What it supports" and "Known issues".
- **CI:** the MacPorts install is `.github/scripts/macports.sh`, shared by a new `intel` job (`macos-15-intel`, row A6), which runs the suite and builds on x86_64.
- **MacPorts CI's releases** (tart 2.40.1's lesson). `macports.CIReleases` reads the releases MacPorts' own CI builds from the ports tree's `.github/workflows/main.yml`. Submit's preview and the pull request say which no check covered, "MacPorts CI also builds on macOS 14 and 15, which no check here built on.", and `--on ci` (and `check.on = ["ci"]`) checks those releases. The default stays this Mac's.
- **Field finding 1:** update's "upstream moved" is a held finding, so `bump` stops on it and submit's preview carries it; author prints the move line only where no comparison carries it.
- **Field finding 2:** a binary distfile, a xar package or a Mach-O, is `archive.ErrBinary`, and its coverage is "not compared", not a tar header error.
- **Field finding 3:** every port of an `update --outdated` batch has an upstream line, compared or saying why not.
- **Field finding 4**, serve's doubled "passed" line, didn't recur in the quick stage's B3, where each check's line came once; it stays on the known-issues list until a check reproduces it.
- `config` shows `cleanup.min_free` in SI words.
- **A read-only command made dockhand's Tart home:** `tart.Client.Images` says a home that isn't there has no images without running Tart, which makes its home's directories on any command (the M1 shakedown's third finding).
