# 2026-10-02: a revision's change record (batch 61)

Batch 61 of the [roadmap](../roadmap.md): the first part of the implementation plan's step 1, the evaluated-change model's change record, made in the assessment pass and read by the upstream assessment.

## What changed

- **`model.ChangeRecord`:** what a revision changed in one port directory against its base, per subport (`SubportChange`: added, removed, changed, or unchanged) with the evaluated fields that moved (`FieldChange`: field, from, to), the platform both sides were evaluated on, the policy it was made under, and a `Problem` where a side couldn't be evaluated, in which case readers take the directory's text scope as before. `Unstable` is there for fields known to move without an edit; the multi-subport sweep says whether any do.
- **fidelity owns the comparison.** `fidelity.Changes` is `Compare`'s comparison made structured, with the revision added, each side normalized by its own root as aebad24e set out; `Compare` is now built on it, its options in a stable order. `fidelity.SubportChanges` compares a directory's two evaluations subport by subport, main port first. `fidelity.ChangePolicy` versions the rules.
- **Stored beside the assessments** (schema 29, `change_records`), keyed by branch, tree, base, and directory, as assessments are, so cleanup prunes them with assessments: an ended branch's, and an open branch's trees it moved past.
- **The trust rule:** `adopt --pr` marks its pull request `Adopted` (a new `pr_adopted` column; one adopted before is recognized by its adoption's event). Such a branch gets no record, and keeps its directories' text scope.
- **Made in the assessment pass** (`engine.revisionChanges`), as a check's driver and submit collect assessments: each changed directory evaluated at the base and the revision through MacPorts' evaluator (`evaluatedPorts.Family`, which `Ports` is now built on). An evaluator that can't give the family, as tests' fakes, makes none.
- **The first reader, the upstream assessment:** only the subports a record says changed are assessed. terraform-1.16's branch compared upstream for its 16 other subports; it now compares one. A directory without a record is assessed as before, and the `SameSource` filter stays for it.

The record is keyed by branch as assessments are, rather than by tree and base alone, so cleanup's pruning and the trust rule apply to it unchanged.

## Verification

- With MacPorts' tclsh: a three-subport port, an edit in one `subport` block changing that subport alone, its version's from and to said, and an edit inside `if {${subport} eq ${name}}`, terraform's stub, changing the main port's revision alone; the record read again as recorded; the assessment made for the changed subport only.
- An adopted pull request's branch gets no record, and reads as its text says.
- fidelity: added, removed, changed, and unchanged subports, each normalized by its own root.
- The store: a record replaced by its key and read back; pruned with its tree's assessment.
- `make test` with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.
