## What changed

The harness:

- **A GitHub token that reads only.** quick.sh takes `ACCEPT_GH_TOKEN`, or the file `ACCEPT_GH_TOKEN_FILE` names (`~/.dockhand-acceptance/gh-token` unless set), and passes it as `GH_TOKEN`, which dockhand reads before the person's own login, so the rows that ask GitHub get 5,000 requests an hour and the person's login is neither read nor renewed. Without one, quick.sh says so.
- **A10 is bounded.** `update --outdated --mine` isn't run (B3 runs a batch on two ports), `outdated --mine` runs only with the stage's token, and the stage's small Go port stands in for jq, the docs' example, which is current at the pin; a line naming one of jq's versions isn't run.
- **A setup's failure is the setup's.** `dh_setup` runs a step that only sets a row up, the update that makes its branch, and fails the row as its setup's with what dockhand said, where a later step's blank exit was reported. 23 rows use it.
- **GitHub's rate limit is never "refused well"**: run.sh grades such a row a failure, naming the limit.
- **A5 touches nothing of the person's**: without a database of theirs it isn't run, where SQLite made an empty one before the harm sweep's snapshot, and it opens one read-only; its ports tree falls back to the stage's `ACCEPT_PORTS_SOURCE`.
- **F6** runs `setup` without `--json`, which setup hasn't yet.
- **D-R2's vanilla image** defaults to the one dockhand's setup started from.

dockhand:

- **Tests keep their Tart locks out of the person's `~/.dockhand`** (A0's H9). `testsupport.IsolateHomeKeepingTart` pins the real Tart homes only where a live Tart test is asked for, and `internal/buildenv/tart` isolates its home too. Batch 77 put the locks beside dockhand's Tart home.
- **On macOS 27, a port that reads the architecture is sampled on x86_64 on macOS 26** (A0's three `portedit` failures). Golden Gate runs on arm64 alone, so its Intel archive went unsampled, and a per-architecture refresh found the Intel checksum uncovered. Each architecture is now sampled on this release where it runs here, and otherwise on the newest release it runs on.
- **`outdated` says when nothing could be checked, and fails** (D-N1): offline, it said "None of 1 port has a newer release" and exited 0. Where no port could be checked, each is listed with why, and the command fails with the first reason. A problem's lines are joined on one row.
- **An empty batch says why** (B3): `update --outdated` offline said "Nothing to update" and its JSON result was null. Where no port could be checked it fails the same way; and its JSON result now lists, beside what it prepared, every port it left alone, with why.
