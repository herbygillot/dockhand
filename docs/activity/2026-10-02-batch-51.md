# 2026-10-02: clean's guards, mutation testing, and SI sizes (batch 51)

Batch 51 of the [roadmap](../roadmap.md): the test plan's step 2 for clean, step 4's `make mutate`, and the library survey's one size formatter, in SI as the person chose. Before it, CI's serve-test failures were put right ([note](2026-10-02-ci-serve-waits.md)).

## What changed

- **Clean's guards are tested** (`clean_guards_test.go`), each a variation on a merged branch: a fork's branch that moved after the merge, or while clean ran; one no remote reaches, or whose fork can't be read; the github provider's check branches, kept when they moved since the check or while clean ran, or can't be reached or read; a branch whose merged commit isn't known; a worktree that took an edit, or a branch a commit, while clean ran; and the cleanup from before v3, keeping a fork's branch holding another commit, and what moved while it ran. None of these ran before, and none found a defect.
- **`make mutate`** runs go-mutesting by version, as deadcode runs: each mutant through `go test -overlay`, so the shared checkout is never edited, with `MUTATE_RUN` to narrow engine's tests and `MUTATE_TIMEOUT` (120 s) to end a mutant that loops; the first run's 600 s let looping mutants hold reuse's run for most of an hour. Not in CI. On reuse and commitrules: 246 mutants, 200 killed, 46 escaped, in a minute. The test plan's escaped mutant, `reuse.Current` without its directory check, is now killed by a result recorded for another directory. On clean.go, against the clean tests, the run reached line 865 before its hour ran out: most escapes are error returns no test can reach without a failing store or git, and the Cleanup paths the filter left out; one was a guard, the branch kept at plan time for its kept worktree, which only the apply-time check had held, now asserted.
- **One way to word sizes and counts:** `internal/prose`, with `Bytes`, SI as Finder and `df -H` count ("820 MB", "1.4 GB", "4 bytes"), and `Plural`, in place of five size formatters and three `plural`s across engine, command, archive, distfetch, and portindex. Engine said "GB" and "MB" of powers of two, and rounded a few bytes up to "1 MB"; it says SI now, exactly. The archive walk's limit stays 4 GiB, the person's of 2026-10-01, said as "4.3 GB".
- **`cleanup.min_free` reads SI:** "30GB" is 30,000,000,000 bytes, the default; "1.5TB" and "500MB" read, and GiB, MiB, and TiB name binary sizes. A size past 64 bits is still refused.

## Not changed

- The 46 escapes in reuse and commitrules, and clean's, are left to triage as later batches touch their files: most are counts and loop exits whose tests assert the outcome, not the count.
