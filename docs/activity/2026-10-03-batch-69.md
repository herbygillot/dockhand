# 2026-10-03: undo and open, and onboarding done (batch 69)

Batch 69 of the [roadmap](../roadmap.md): the command-line UX review's two smaller items that close the onboarding UX, step 2 of the implementation plan.

## What changed

- **`undo [<checkpoint>]`** puts back the history a tidy or rebase replaced, as `restore` did. The name follows the review: `git restore` restores files, and dockhand's restores history.
  - With no checkpoint it takes the branch's latest one (`engine.LatestCheckpoint`: applied, not restored since). It finds the branch through `-b`, `-p`, or `--pr`, else the one checked out here.
  - A checkpoint named carries its branch, so naming a branch too is refused.
  - `restore <checkpoint>` still answers, hidden.
  - Every "dockhand restore …" a command printed now says undo.
- **`open`** opens the branch's pull request in the browser and prints its address. A branch without one says so, with the submit that opens one.
- usage and README say them.

With batch 69, step 2 is built. Here's what it contains and where:
- the change record, step 1 (batches 61 and 62)
