# 2026-09-25: the v3 store, on a fresh schema

Roadmap step 5, part 2: `internal/store`, the contract for v3's records, and `internal/store/sqlite`, its implementation on `~/.dockhand/dockhand.db`, with no migration from v2 (the person's decision).

## The contract

`store.Store` registers repositories and opens transactions bound to one repository. The callback runs once, changes only records, and makes no external calls. Its methods are specific to their records:

- branches, revisions, plans, runs, executions, and target results;
- sessions, leases, and events for coordination.

The errors say what to do: `ErrNotFound`; `ErrConflict` (a duplicate, a disallowed state change, a final checkpoint); `ErrStale` (a lease generation that has moved on); `ErrSchema`; `ErrUnavailable`; and `ErrUncertain` (a commit whose outcome is unknown). `NewID` gives records random identities with readable prefixes.

## The rules, and where they're kept

Every write validates with `model` first. Rules that involve other rows are checked in Go, and wherever the database can check a rule itself, the schema checks it too, so a Go bug can't store a broken record:

| Rule | Go | Schema |
| --- | --- | --- |
| Branch and run states move only as `model` allows | ✓ | valid states |
| One unmerged branch per Git name; a merged name can be reused | | partial unique index |
| One branch per pull request | | partial unique index |
| Snapshots numbered 1, 2, 3 per branch | ✓ | unique index |
| A commit revision has a commit and no number; a snapshot the reverse | ✓ | CHECK |
| Run numbers are sequential; what a run asks is immutable | ✓ | UNIQUE |
| A run's plan is for its revision, which is on its branch, with nothing unresolved | ✓ | |
| An execution's environment is in its run's plan; one per environment and attempt; three attempts at most | ✓ | UNIQUE, CHECK |
| A finish time exactly when the state is terminal | ✓ | CHECK |
| A complete target verdict is final; a result's target is in the plan | ✓ | trigger |
| A lease generation never decreases and survives release | ✓ | trigger |

## Operational choices kept from v2

- WAL mode, `synchronous(FULL)`, foreign keys on, and a busy timeout.
- Writes begin `IMMEDIATE`, so writers queue on SQLite's lock rather than failing midway.
- A connection whose rollback failed is discarded.
- A commit error other than a constraint is reported as uncertain.

The database has its own application ID, "DHN3". Opening a v2 `state.db` is refused, and the error names it as a v2 database. A database with a newer schema, or a file holding someone else's tables, is also refused.

## Tests

They cover each rule in the table, including the schema's own checks, exercised with raw SQL. They also cover repository isolation, read transactions refusing writes, nested transactions refused, a failed callback committing nothing, plans round-tripping, the event journal's tail, and eight concurrent writers numbering runs 1–8 with none repeated. `go test -race -count=3` passes, as do `go vet ./...` and the full suite. `GOOS=darwin go vet` passes for the new packages.

Stored times are milliseconds, so a record read back carries them truncated to the millisecond.
