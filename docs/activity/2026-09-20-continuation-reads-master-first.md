# Continuing an open contribution reads master and its PR first

`dockhand bump packer` found the port's open contribution, continued it from the source recorded when it was first prepared, resolved 1.16.0 to 1.16.1 against that stale source, built, and then failed to publish because the PR was merged. The bind path took an open contribution's recorded source without fetching master or looking at the PR; the only live check was the publish precondition, after the build. The `open` it printed was the recorded disposition.

Bind now does three things before continuing. It fetches master on both branches, where before the fetch lived only on the fresh one. It evaluates the port on master and places it against the release the prior job recorded, deliberately without ordering versions, since dockhand has no `vercmp` and MacPorts' ordering is not something to approximate: master equal to the version the contribution started from is untouched; equal to the version it moved to means the update landed; anything else means someone else moved the port, which observing the PR alone would never show. Then it observes the PR the way `refresh` does, through the same code.

What follows is decided by one rule: bind never silently starts a new contribution after an observation changed the record. A merged PR retires the contribution and a new update starts from master, since a bump is what the person asked for and upstream may have moved on; the fresh path then reports "already current" through the existing outcome, or bumps to what is newer. A port master already carries while the PR is still open stops and says so, the case the user asked to be left to a person. A port someone else moved stops and names both versions. A PR closed without merging stops too: re-proposing what a maintainer declined is not done unasked. An unreachable forge leaves the recorded state as the only fact and the message says the PR was not re-checked; an unreachable master continues as recorded and says master was not checked, so `bump -P` keeps working offline. Each stop is `ErrContinuation`, exit status 3, and no job is created.

The decision lives in the engine as `CheckContinuation`, where the fixtures are; the app's bind calls it and keeps the continuation it had. Eight tests cover the table with a published contribution, a forge fake whose observed state is chosen per case, and a fake evaluator that answers per source tree, including that a merge retires the contribution in the record and not only in the message. The cost is one fetch, already paid on the fresh path, and one evaluation of the port on master per bump of a port with an open contribution.
