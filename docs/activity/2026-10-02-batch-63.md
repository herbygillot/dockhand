# 2026-10-02: one way to name a branch, and starting one (batch 63)

Batch 63 of the [roadmap](../roadmap.md): the onboarding UX's first part, the command-line UX review's §1 and §2.

## What changed

- **A selector names a branch** (`engine.Select`): a branch's name, with or without `dockhand/`; the one open branch whose name starts with it (`jq-4`); the one open branch that changes the port it names (`jq`), through `BranchesChanging`, which reads the change record where there is one; `#34901`, the branch whose pull request that is; and `check-42`, the branch that check checked. One that more than one open branch answers to is refused with them (`AmbiguousError`, `ErrAmbiguous`), never guessed. `Resolve` stays exact, for the code that asks whether a name is taken.
- **`-b` is `--branch`'s short form** everywhere it's offered, and takes a selector; `check`, `tidy`, `submit`, and `rebase` take it as their argument too (`check jq`), as `status` already did, which now reads selectors as well, falling back to a merged branch's record by name.
- **An authoring command on master chooses where nothing else could be meant** (§2): with no open branch changing the port, it starts one and says so first, "jq is in no open branch, so this starts dockhand/jq-4k2p for it.", in a script too, as `revbump` always has; with exactly one, it works there, "Working in jq-4k2p, the one open branch changing jq; --new starts another.". This is the recommended answer to the question put to the person as the batch started, whether a script acts alone on one match; with several, a terminal is asked and a script refused, naming them.
- **`init` ends with `Next: dockhand outdated --mine, or dockhand update <port>`**, and status with no branches says the same, `start <name>` being for work that isn't a port's.
- design-v3's "a port name never picks a branch" says what it keeps now: a port picks one only where exactly one open branch changes it.

## Verification

- The engine: a branch by its full and Git names, by a port only it changes where the start of its name is shared, by the start of another's name, by a check, by its pull request, a pull request no branch has, a port none changes, and a port two change, refused with both.
- The command line: an update with no branch starts one in a script and says so; with one changing the port, a plan and checksums go there without asking; an untracked branch that doesn't change the port is no context.
- `make test` with `DOCKHAND_TEST_MACPORTS_TCLSH`; fmt-check, vendor-check, vet, deadcode, and lint, each read for its exit status.
