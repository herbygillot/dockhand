# 2026-10-06: a new port's guesses hold its submission (batch 108)

From the v0.3.0-rc6 full stage's B8, which created countdown 1.5.0 (Go) and serie 0.9.3 (Rust). It comes after v0.3.0-rc6, for the release candidate after the run.

## What changed

- **A Go module before go 1.17 whose go.mod leaves out modules its build reads is refused.** go2port writes go.vendors from go.mod's requirements, and before 1.17 a go.mod needn't list every module the build reads: countdown's go 1.14 go.mod required go-runewidth, which imports rivo/uniseg, so the port's check failed at install. `create`, `update`, and `checksums` now refuse such a module, naming what go.sum has the source of that go.mod doesn't require ("go.sum has the source of github.com/rivo/uniseg too, which go.vendors needs by hand"), rather than write a go.vendors that can't build (`depblock.unprunedGraph`).
- **submit holds while a Portfile still marks a guess unconfirmed.** serie's preview said it was ready with six `# dockhand: unconfirmed` marks left, nomaintainer among them. Each Portfile the branch changes is read for them, and the plan is held, naming the guesses: "still marks 6 guesses unconfirmed (categories, license, maintainers, …): confirm each, remove its mark, and tidy" (`portcreate.Marked`). The marks are dockhand's own words, never MacPorts', so it holds rather than warns.
- **A coverage item named more than once is named once, with how many,** as "Cargo.lock (4)".
- **B8 tidies a new port before submit's preview,** which previews commits.

## Not changed

- Type(s) ticks nothing for a new port: MacPorts' template offers bugfix, enhancement, and security fix, and says a submission (a new Portfile) is detected by itself.

## Verification

- Tests: a go 1.14 module with a module go.sum has the source of and go.mod doesn't require is refused, and the same at go 1.17 isn't; submit holds a Portfile with a mark; a repeated coverage item.
- The full checks: fmt-check, vendor-check, vet, lint, deadcode, and the suite under MacPorts (port-tclsh).
