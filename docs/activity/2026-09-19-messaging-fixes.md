# What Dockhand says, checked against what it does

The [messaging scan](../reviews/2026-09-19-messaging-scan.md) found three defects and a set of drifts in the report, help, summary, and JSON surface. All were verified and fixed.

**Defects.** The bump family's automatic provider fallback said "Using GitHub verification." at info and only then tried to configure GitHub, which fails without a credential or a fork; it now says "Trying GitHub verification." before and "Using GitHub verification." once the configuration holds. `gc` printed "No eligible cleanup." and, under `--json`, a result object even when collection never ran, as outside a ports tree; the sentence now needs a successful call, and a failed call returns the envelope with a null result like every other command. A test runs `gc` outside a tree both ways.

**Identifiers at info.** The continuation line, `gc`'s registration and item lines, and the two PortIndex messages named change IDs, commits, resource and attempt IDs, or tree hashes at the info level; each now has a plain sentence at info and keeps its identifiers at `-v`. The PortIndex "this may take several minutes" warning stays at info without the hash. One exception was decided rather than fixed: the resume guidance's `dockhand wait --job <id>` for standalone work keeps the identifier, since it exists to be typed; the label side, where a bare job ID stood in for a port name, now reads "standalone job".

**Behavior and wording.** `status -v` on a terminal opened the printed record instead of the live table, silently stopping the processing the table does; the level now changes only what a printed snapshot shows, and the help says so. `--trace` help says it implies `--debug`. The `gc`, `db check`, and `db migrate` payloads carry lowercase JSON tags like `auth status` and the projection; `outdated` and `assess` embed evaluation types shared with stored records and were left as they are. Six progress sentences that began with a lowercase identifier now begin with a capital, by naming the Portfile's option rather than starting with it. `review` is listed in its own "Planned, not implemented yet" help group, and `--test-timeout`'s help derives its default from the constant that sets it.
