# 2026-09-25: `auth login`, `status`, and `logout` in v3

`submit` needs a GitHub login, and its errors named a `dockhand auth login` that v3 didn't have. This ports v2's.

- **`dockhand auth login`** runs GitHub's device flow with dockhand's OAuth application (the `public_repo` scope).
  - It prints a one-time code and opens the verification page; `--no-browser` prints the address instead.
  - It keeps the token in the macOS Keychain, under the same key v2 used, so a login made with `dockhand-v2 auth login` already works for v3.
  - It warns when `GH_TOKEN` or `GITHUB_TOKEN` would take precedence.
  - A failed login saves nothing.
- **`dockhand auth status`** asks GitHub which account submit would use, and from which source: `GH_TOKEN`, `GITHUB_TOKEN`, the Keychain, or the GitHub CLI.
- **`dockhand auth logout`** removes only dockhand's Keychain entry.
- **`dockhand init`** now reports publishing as one of its capabilities (§6.1), without asking GitHub: a token from the environment, a Keychain login, or "not set up: dockhand auth login".

**Tests** cover the whole round trip with a stand-in device flow, an in-memory credential store, and a local server standing in for GitHub's `/user`. They cover login, status, logout twice, status with no login anywhere, and a failed login saving nothing. The GitHub CLI is kept off `PATH`, so a login on the machine running the tests can't stand in.

**Not proven here:** GitHub's real device flow, and the macOS Keychain.
