# 2026-10-04: py-coremltools' field findings (batch 89)

Batch 89 of the [roadmap](../roadmap.md): from the Vx port session's update of py-coremltools from 5.2.0 to 9.0 on d8f70710, forwarded by field testing, with its re-check of py-mlx-vlm.

## What changed

- **`start <port>` checks the port's directory out.** A branch named for a port the tree has in one category gets that directory in its sparse checkout beside `_resources`, so its files are there to edit; py-coremltools' branch had only `_resources` until `git sparse-checkout add`. A name no port has, or one in several categories, starts as before, and edit and update still add a directory as they need it (`Engine.portNamed`).
- **A python stub says its subports are what's compared.** The `py-NAME` stub fetches nothing itself, and its coverage said "fetches no upstream source, so there's nothing to compare" beside its subports' real findings. It now says "builds nothing itself, so its subports' source is what's compared".
- **A Python subport new to its directory is compared with its sibling in the base.** py-coremltools' master had only py310, so py311 to py314 had no base, and the license and NOTICE findings read as py310's alone while the others got "·". A subport the base lacks is now compared with the base's newest subport of its package (`macports.CounterpartIn`), so each finds what py310 does.
- **submit says a finding once for every port that has it.** Its Upstream lines were grouped only where whole comparisons matched, and a python port's subports differ by their providers' names, so every shared finding repeated per subport. Each line now names the ports that found it, "py310-coremltools, py313-coremltools: …".
- **submit points at `--note` when the Description would say nothing.** A MacPorts update's commit has a subject alone, so the Description held only its trailers. Where no new port, note, or commit body says anything, submit's plan says "Note none, and the commit has no body, so the Description says nothing of the change: --note "…" adds one" (`prdescription.SaysNothing`).
- **An SSH server refusing every key is said plainly.** With the agent's key gone, `submit --plan` stopped on ssh-askpass's and ssh's raw words. Git commands whose SSH connection is refused now say "the SSH server refused this Mac's keys (git ls-remote); is your key loaded? ssh-add -l lists the agent's keys, and ssh -T git@github.com tries them", with ssh's words after it (`git.ErrSSHRefused`). This reads ssh's own message, "Permission denied (publickey)", which is how ssh reports the refusal to a person.
- **The roadmap's smaller items** carry field testing's py-mlx-vlm note, now done by the grouping above.
