# 2026-10-02: create for a Go project, and the survey's create fixes (batch 58)

Batch 58 of the [roadmap](../roadmap.md): the first of the work after the test batches, as the plan thread set it: `create` for a Go project, from field testing's sixth report (mods 1.8.1), with the library survey's two create fixes, and create's name check.

## What changed

- **A Go port's go.vendors is written.** create wrote "run go2port for go.vendors" and a Portfile that couldn't build. It now writes the block empty, and the checksums step create runs fills it: a refresh of a port whose dependency block is declared empty fetches the port's own source, keeps it while go2port reads its go.mod and go.sum, and writes the block, since an empty block holds no maintained override to keep. A module's checksums come only from fetching it, which go2port does, as cargo.crates come from a Cargo.lock without it. `checksums` does the same for any port whose block is declared empty, and an update of one regenerates it without comparing it to its source first.
- **go.toolchain_min isn't written,** where field testing asked for it "as update sets": update sets it only for a port that builds in module mode, `go.offline_build no`, where Go enforces go.mod's `go` line; a port with go.vendors builds offline, where the line is only an upper bound (macports.GoModuleMode).
- **A Python project's python.versions starts from the python PortGroup's default**, read as MacPorts evaluates the new Portfile, where create wrote 313 after the PortGroup moved to 314. Where it can't be read, the line is left out and marked.
- **The release's own archive is fetched where it carries one**: `github.tarball_from releases` where the release has `project-version.tar.gz`, the archive the PortGroup's releases fetch names, read by GitHub's "Get a release by tag name"; else GitHub's archive of the tag, as before.
- **create's name check reads a name no port has as free.** It said "whether a subport is named mods wasn't checked: no port named mods", since the port index's answer for a name it doesn't hold wasn't read as no port; `selection.ErrUnknownPort` says so, and the engine reads it as `ErrNoPort`, keeping the index's wording where it's said.

## Not changed
