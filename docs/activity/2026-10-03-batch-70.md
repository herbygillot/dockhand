# 2026-10-03: the acceptance runner and the harm sweep (batch 70)

Batch 70 of the [roadmap](../roadmap.md): step 2a's H1, the first part of the acceptance harness (the project's plan/acceptance-harness.md), under tools/acceptance/. Nothing in the release binary changes.

## What changed

- **`run.sh --stage quick|full --candidate <rc> [--rows …]`** runs rows and writes `results/<candidate>/<row>.json` under `ACCEPT_STATE`, the stage's scratch directory. Without that directory it refuses, so a run never touches the person's own state.
  - A row is `rows/<ID>.sh`, chosen for a stage by its `# stages:` line, with `setup`, `act`, and `assert`.
  - The runner snapshots between `setup` and `act` and again after `act`.
  - A row the harm sweep catches is a blocker, whatever it said of itself.
- **The row API** (`lib/common.sh`):
  - `dh`, and `dh_json` for one run with `--json` that's kept with its exit status;
  - `expect_exit`;
  - allowances for what a row is meant to change: files, refs that go, pushes, pull requests, and what it leaves running;
  - the four results prime-time.md names.
- **The harm sweep** (`lib/harm.sh`) checks the eight invariants:
  - H1, every edited or untracked file kept, with its content, every commit still an object, and no ref gone unsaid;
  - H2, the fork remotes' refs, with only what the row says pushed;
  - H3, the login's pull requests, which a stage without a login skips;
  - H4, a grep for GitHub's token prefixes in the output, the JSON, and the directories the stage names;
  - H5, status's heads and edits against Git's;
  - H6, every `Next:` line split into its steps and run, as `--plan` where it would change something, as named where it only reads, and said, not counted, where it can't be run from a script;
  - H7, Tart VMs running and checks queued or running;
  - H8, every envelope parsing, with its `exit_code` the process's and one of usage.md's.
- **`selftest.sh`**, `make acceptance-selftest`, and a CI step prove it. They run against a stand-in dockhand, `gh`, and `tart`:
  - a harmless row passes;
  - two rows that change only what they say pass;
  - a row made to break each invariant is a blocker, caught by that invariant alone.
- tools/acceptance/README.md says how it's used.
