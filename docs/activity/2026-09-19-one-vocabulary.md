# One vocabulary for a job

The structural review of 2026-09-19 found that the status projection in `workflow/view`, built on 2026-09-17 so that plain output, JSON, and the table would say the same thing, had left the action summary's own words standing. `bump`, `verify`, and `publish` rendered "verifying" where `status` said "waiting for capacity" or "building on macOS 26", and "preparing" where it said "integrating branch"; a `jobPort` existed in both packages with different fallbacks.

The view is now the phrasebook for both. It exports `PortLabel`, the display name with variants that a summary line uses, and `PortSelector`, the name or `--job <id>` that a suggested command needs, which is what the two `jobPort` copies were each doing under one name. `ChangeWords` says what a job does, `VersionMove` words a resolved release, and `JobState` gives the state word for one job from the same derivation the row uses, since the row's words for its current job are now computed by a function that takes only the job. The summary keeps its layout, the per-platform verdict lines, the pull request line, and the resume guidance, and takes every word about the job from the view; the preview's version line uses `VersionMove` too.

Two spellings were reconciled on the way. A no-update bump reads "already current at 2.0" in both places, with the latest eligible version named only when it differs, and its state is "no update needed" rather than the row saying "current" twice. A test in each package checks that the summary line and the projected row carry the same change and state words for one job.
