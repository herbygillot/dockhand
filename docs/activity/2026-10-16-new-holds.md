# The new holds, typed (v0.4.0 part 2, item 2)

Two holds, each a `!` line bump and serve keep, as the majors hold is.

- **A repository move or new owner.** `update` already found the GitHub
  repository a release came from answered by another name, a redirect,
  and held it (`upstream-moved`). Now a new owner is said as a transfer,
  not a rename (`upstream-transferred`): "upstream transferred from squash
  to WLTBAgent: GitHub answers … by a redirect, and its release is a new
  owner's to trust", since a new owner's release is a person's to trust,
  more so for what a port installs with privilege (sudosh2's). The same
  owner's is said as a rename. Either holds until `update --follow-moves`,
  the person's choice and never made unasked, points `github.setup` at the
  new name (`portfile.MoveGitHub`, each `github.setup` naming the old
  repository in literal words, subports' blocks too; one naming it by
  substitution is refused). Followed, the finding holds nothing, and
  update says "Followed the move: github.setup now names …"; `--json`
  carries it as `followed`. gitoxide's, Byron to GitoxideLabs, was followed
  by hand in field testing at 43949b89.
  The roadmap's "a redirect with byte-identical archives offers
  `--follow-moves`" is taken as offered always: GitHub serves the same
  archive through the redirect, so a byte comparison there tells nothing a
  person deciding on an owner would use.
- **A raised floor**, read from the change record, not a Portfile pattern:
  a subport's evaluated `platforms` whose darwin floor rose
  (`macports.DarwinFloor`: "darwin >= 21", "darwin > 19"), or its
  `macosx_deployment_target` raised where both sides set it
  (`darwin-floor`, `deployment-target`). `macosx_deployment_target` joins
  `ReadOptions`, and the change policy goes to 5, so records made before
  are made again. `SubmitPlan.Floors` joins `Concerns()`, so serve and bump
  hold on them; `macports.BaseAtLeast` compares the targets.
- A build that fetches outside its distfiles stays a notice, as decision 5
  has it, for layer 1.
