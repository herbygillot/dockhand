# 2026-09-27: dockhand bump

The person's decision: `dockhand bump <port> [version]` takes a port to its pull request in one command, asking nothing. It is `update --new --submit --yes` as a command of its own. `bump` is the one-shot, and `update` is the same work a step at a time, looking and editing in the branch's worktree along the way.

**The name.** `ship`, `propose`, `send`, and others were weighed. The person kept `bump` knowingly:
- MacPorts' `port bump` refreshes checksums after a hand edit, opening nothing; dockhand's `checksums` does that.
- v2's `bump` stopped at the prepared branch.
- Dependabot's "Bump x from 1 to 2" pull requests are the sense `bump` has here.

Its help opens by saying it opens a pull request and isn't `port bump`, and design §16's row for v2's `bump` says the meaning changed.

**What makes it more than the three flags.** Nobody looks between the command and the pull request, so it stops wherever a person should.

- **It asks nothing,** even on a terminal: it runs with streams that take every question's no-terminal course. The tidy of a new branch's one update is always dockhand's own edit, so it applies without review. The template's two questions aren't asked, and their checkboxes stay unticked unless `--tested-binaries` or `--tested-variants` says otherwise. They state what the person tested, which a routine command must never claim for them.
- **Before the edit, it changes nothing when it has nothing to do.**
  - An open branch already changes the port (by commits or working files, as `status --port` finds): it names the branch.
  - The check has nowhere to build.
  - The port is already at the newest release, or at the version named. This is found as `outdated` finds it, since `update --new` on a current port would leave an empty branch behind. A port the lookup can't place is left for the update to try. One it can't look up is refused unless a version is named.
- **After a passing check, it holds what serve's pull requests hold.** It holds for what blocks a submit, an upstream-comparison finding that holds an update, and a commit-rule finding. It also holds for a new reason: another open pull request for the port, or a failed search for one. The hold exits 3, "needs attention", like `status --attention`, and names the `submit --branch` that finishes it after a look. That submit needs no new check, since the check passed for exactly that commit.

**Serve's holds, shared.** The hold reasons are now one function, `SubmitPlan.held`, used by `ServeCandidates` and by the new `Engine.Held`, which reads the upstream holds for a branch of any origin. Another open pull request for the port, or a failed search for one, now also holds serve's `--submit-passing`. Before, serve could open a second pull request for an update someone had already proposed, and only listed the other in the description.

**What changed.**
- `internal/command/bump.go`: the command, `bump`, and `bumpable`, the checks before the edit.
- `Streams.unattended`.
- `submitChecked` takes `unattended`, and holds by `engine.Held`; `linkedOptions.unattended`.
- `engine.Held`, `SubmitPlan.held`, and `upstreamHolds`, which `BranchStatus` uses too.
- Help: `bump` leads the Author group, and the introduction mentions it.
- Docs:
  - usage's `bump` section, and its serve and exit-code lines;
  - design §5, §6.2, §11's guardrail, and §16;
  - a roadmap Decided entry;
  - the README.
- Tests:
  - `TestBumpGoesFromUpdateToPullRequestAskingNothing`: it runs on a terminal with answers waiting and asks nothing, and a second bump of the port is refused.
  - `TestBumpChangesNothingWhenItHasNothingToDo`: current, already at the named version, can't be looked up, nowhere to build, and flag refusals, with no branch started.
  - `TestBumpHoldsWhatServeWould`: exit 3, then `submit --branch` finishes it.
  - `TestServeHoldsAnUpdateAnotherPullRequestIsOpenFor`.
  - Each bump test fails without its piece: without the unattended streams it asks the template's questions, and without the hold it submits.
- The command tests' fake GitHub now finds other pull requests only when a test says so; serve's tests say nobody else's is open.

Revised the same day: `bumpable` and its release lookup are gone, and `bump` shares `update`'s code ([note](2026-09-27-update-and-bump-share.md)).
