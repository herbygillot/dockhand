# 2026-10-01: the limits sweep's gaps (batch 26, first part)

Batch 26 of the [roadmap](../roadmap.md): the gaps the limits sweep found that batch 25 and the archive sizes didn't take ([limits](../limits.md)); an agent's work, reviewed and merged. The waits with no bound, a body that stalls after its headers, and three reads with no memory cap remain.

## What changed

- **GitHub's rate limits are met in one place.** `forge.RateLimitError.RetryAt` was computed and read by nothing, and go-github refused a request on its own before any transport could wait. A transport below go-github (`github.rateLimited`), whose own check is now off through its documented `WithDisableRateLimitCheck`, reads GitHub's documented headers alone: `x-ratelimit-remaining` and `x-ratelimit-reset` for the primary limit, kept per resource, and `retry-after` for a secondary one, a 429 naming none waiting GitHub's "at least one minute". A read whose limit lifts within two minutes and before its deadline waits, says so once, and asks again, once; anything else is refused at once with when the limit lifts: "GitHub's rate limit for your login resets at 14:05, in 23 minutes", or, without a login, that `dockhand auth login` raises it. Nothing is sent while a limit holds, as GitHub asks, and a write is never retried.
- **Truncations are said, not silent.** A GitHub Actions job log past 64 MiB ends with a line saying it was cut, and where the rest is. The job log's readers and the build log's cause finder skip a line past their 4 MiB and 1 MiB and read on, where one long line ended the scan; the build log still counts the skipped line, so its numbering matches `buildlog.From`. A `.gz` or `.bz2` patch that decompresses past 64 MiB is left unchecked, saying so, rather than checked as its first 64 MiB. PyPI's JSON goes through `fetch.Open`, which refuses a redirect from HTTPS to HTTP, so one past 8 MiB says it's too large rather than "unexpected EOF".
- **A patch is judged by patch's exit status.** Past its 1 MiB of output, `patch` was killed by the closed pipe and its patch read as not applying, and a patch that applied with that much to say failed the whole check. `subprocess.Spec.Drain` keeps a command's first bytes and reads away the rest, so it runs to its end.
- **A forge file past GitHub's inline megabyte is read.** GitHub's contents API inlines content only to 1 MB, so `create`'s 4 MiB, and the manifest's 1 MiB near it, failed as "unsupported content encoding: none". It's asked with the object media type first, and with the raw media type where it gives no content inline, so each limit is the one that applies, with its own words; `download_url`, which expires and is another host, isn't used. GitLab's raw file is read through a limited reader, where the whole body was read before the limit was checked.
- **Today's events stay, however short `cleanup.after` is,** since `serve.submit_limit` counts since midnight: a few hours' `after` let serve open its limit again. The day's start is one function, `dayStart`, which both read.
- **A setting that overflows is refused.** `cleanup.min_free` past 64 bits wrapped, to 0 at "16777216TB", which watches no space; `cleanup.after` in days past what a duration holds went negative, which would prune everything.

## Decided along the way

- **Two minutes is the wait.** It covers a secondary limit's minute with room, and a primary limit near its reset; past it a person would rather hear when it lifts, and serve asks again on its next pass.
- **A kept archive is still signed in memory.** openssl signs by path, but signify's signature, which MacPorts checks, is plain Ed25519 over the whole file, which Go's `crypto/ed25519` signs only from memory; hashing as it reads saves nothing. Streaming it needs an Edwards25519 library (a new dependency) in two passes, or a memory-mapped file, the person's question of the same day. It's a gap in [limits](../limits.md), the person's to choose.
- **A guest's file and git's blobs are left as they are.** `Guest.Read` keeps `runner.log`, whose tail is shown, and `results.json`; a cap would cost the tail. `git.ReadBlob` reads Portfile-sized blobs.
