# 2026-09-25: clean

Design v3 §6.13: `dockhand clean --merged` removes what merged branches leave behind.

## What changed

- **`PlanClean`** previews, for each merged branch:
  - its managed worktree;
  - its local branch;
  - your fork's branch, found through the Git remote that pushes to the PR's head repository.
- **Each item is removed only while it still holds the merged commit.** The merged commit is the PR head GitHub last reported, or failing that the commit dockhand pushed. An item is kept, with the reason shown, when:
  - it has commits beyond the merge;
  - the worktree has uncommitted edits or untracked files;
  - the fork's branch moved after the merge;
  - the branch is checked out in your own checkout.
- **`ApplyClean`** checks each item again as it removes it. Branch deletions are conditional, so a branch that moves while clean runs is kept. Checkpoint refs and snapshot commits go only when everything else did, so kept work can still be restored. Each removal is journaled as `branch.clean`. The branch's record stays, so `status --all` still finds it.
- **The command** shows the preview first:
  - on a terminal, it asks before removing;
  - a script passes `--yes`;
  - without either, it says nothing was removed.

## Tests

- **Engine:**
  - a submitted and merged branch loses its worktree, branch, fork branch, and refs, and keeps its record;
  - a merged branch with a later commit, and one with an untracked file, keep their work.
- **Command:** `submit`, a merge, `status --refresh`, then `clean` previewing, refusing without `--yes`, and removing with it.

**Not yet:** automatic cleanup (decision 36), and `clean` for closed or archived branches.
