# 2026-09-30: branches, done, never dockhand's, or rewritten more than they need (batch 10)

Batch 10 of the [roadmap](../roadmap.md): what `status`, `clean`, and `adopt` don't yet see, and what `tidy` rewrites that it could keep.

## What changed

- **`tidy` keeps the commits it wouldn't change.** Adding py-flatbuffers to #35044, `tidy --apply` wrote the pull request's first two commits again, with the same trees and messages and another committer time. So the next submit replaced the pull request's history rather than adding a commit to it (adding py-flatbuffers, finding 3).
  - A commit the branch has already, at the same place, from the same parent, with the same tree, author, and message, now stays as it is. Once one is written anew, those after it are too, their parents being new.
  - The message rule is `commitmsg.Unchanged`: the same, or the same but for the attribution line where both carry one, since Generated-By names the build that wrote each, and the one written stays true. One naming a build of uncommitted source isn't kept, since tidying again with a pushed build is what `submit` asks for to replace it. A commit without the line doesn't stand for one tidy would attribute.
  - `tidy` says "Kept 1 commit as it was, and created 1". Where every commit the pull request has is kept, it says the pull request gains the new ones when you submit, rather than that submit replaces its history. `--json`'s applied result has `kept`.
