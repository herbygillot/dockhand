# D-I5: the sleep half tests a running check

On rc10, D-I5's check (the Go port, quick) finished at 01:51Z and the person's
sleep came at 02:30Z, so "a running check resumes after sleep" went untested.

- The sleep half starts its check only after the person says they're ready to
  sleep the Mac within a few minutes.
- It builds `ACCEPT_SLEEP_PORT`, a longer build, the Rust port unless set
  (full.sh documents and exports it), on a branch of its own.
- The check is confirmed running right before the sleep is asked for.
- Afterwards, `pmset -g log` (no sudo) must show a sleep between the check's
  building and its end. Without one, the sleep half's reason is kept across
  the reboot and the second half records the row as not run, saying why.

Unattended `pmset sleepnow` with `pmset schedule wake` would remove the person
from the loop but needs sudo, so it isn't used.

## The reboot half, the same way

On rc10 the reboot half's check-132 (the Go port, kept archives) passed in two
minutes, before the reboot at 02:50Z. The reboot half now asks the person to
be ready first, builds `ACCEPT_SLEEP_PORT` on its own branch through serve,
gates on serve's log saying the check is running, and checks again 30 seconds
later that it hasn't ended before asking for the reboot. The state file keeps
the check's name and serve.log's offset. After login, the second half waits
for serve's "resuming" line for that check, then for its end. A check that
ended before the reboot is "not run"; one serve never resumed, or that never
ended, fails; one that resumed and ended is judged, passed or failed with a
reason, with tart list for orphaned VMs.
