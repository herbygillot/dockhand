# Flags in sections

Item 6 of the flag review: a run command's flags were one alphabetical list of five different kinds of thing, twenty-seven of them on `bump`, and one of them was not a run's to set.

**Sections.** Every flag on bump, bump-revision, checksums, amend, rebase, verify, and publish is annotated with its kind where it is defined, mostly in the helpers that already partitioned them: Selection, which contribution; Change, what the commit says; Build, how it is built; GitHub, how it reaches the fork and the pull request; and Run, where it stops and how the run behaves. The usage template is cobra's default with its two flag blocks replaced. It prints the sections in that order with a blank line between, then the command's unsectioned flags under "Other flags", which is only `--help`. The global flags divide into Path and Output and print as "Global path flags" and "Global output flags" on every command, and as the command's own on the root. A command with no sectioned flag prints as cobra would. A test checks that every flag on a sectioned command has a section and that no flag on any other command does, so a new flag cannot fall through unlabeled. Nothing is hidden: hiding says a flag is not for you, and a section says what it is for.

**`--capacity` moved to setup.** The review said the flag recorded a pool-wide limit from a per-run command. The mechanism was stranger than that: the pool record is immutable, so `--capacity` set the limit on the first Tart run ever and was refused afterwards whenever it differed from the record, as "configuration differs from the existing pool". It was a write-once setting wearing a run flag's clothes. `setup --capacity N` records the limit now: a pool not yet recorded is registered with it, and a recorded pool keeps its identity and takes the new limit through a store method that changes the one pool fact that is policy rather than identity, refusing a changed artifact directory. It is the one thing setup writes to the state database, and its help says so; a driver already running keeps the limit it started with until it restarts, since the pool is read when a provider opens. The run commands no longer know the flag, and the Tart provider names its pool through one function, which the app uses to find the record.

**Retracted from the review.** `--detach` and `--trace` stay per command, under Run; a global flag would show on every help screen and be refused on most of them. `--keep-failed` stays per run; it is recorded on the job spec and means this run's VM.
