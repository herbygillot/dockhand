# UniqueLiteral on the parser

`UniqueLiteral` finds the one place a Portfile writes a value the editor must own but cannot attribute to a command argument: a digest held in a table, as the qt family keeps its module checksums in a `set modules` list, or the words `revision N` for a revision the Portfile computes from such a table. It searched the raw bytes for the value bounded by whitespace, braces, quotes, or a backslash, skipping lines that began with `#`. That was a small lexer of its own, `boundary` and `inComment`, outside the package that lexes Tcl.

The parser now supplies what it needed. `Script.TokenRuns` lists the runs of sibling tokens at every depth: a command's words; a braced word's own commands when its body parses as a script, which is how a table and a subport's declarations are reached; its list elements when it does not; a quoted word's inner text; a command substitution's commands. Comments contribute nothing at any depth. `UniqueLiteral` looks for exactly one window of adjacent tokens in one run whose text is the value, which is how the two-word `revision 3` still matches without either caller changing.

One choice is worth recording. A braced body that parses as a script is walked as one, so a `#` line inside it is a comment and its contents are not tokens. Tcl itself does not treat `#` inside braces as a comment, so a value on such a line in braced data would be invisible; but a Portfile with a `#` line inside a checksum table would already be broken for MacPorts, whereas a commented-out `revision 2` inside a subport body is ordinary, and treating that as an owner would edit the comment. Script semantics first is the safer reading for the values this function is asked about.
