# 2026-09-25: create from a URL

Design v3 §6.4: `dockhand create <url>` writes a new port's first Portfile from what can be observed of its project.

## What changed

- **`dockhand create <url>`**, for projects on GitHub.
  - It reads the repository's description, homepage, and detected license, then its latest release that is neither a draft nor a prerelease, then the build files at that release's commit.
  - It writes `<category>/<name>/Portfile` in the branch's worktree, widening a sparse checkout to include it, and stages it, so the next check captures it.
  - It records a `create` edit, whose subject is MacPorts' "<port>: new port, version <version>". Tidy prefers that subject over the checksum edit that follows it.
  - It then fills in the checksums through the same refresh `dockhand checksums` runs. When that can't run (no MacPorts here, say), it leaves placeholders and says so.
  - It refuses a name a port already has in any category, found with one `git ls-tree` over every category.
- **`internal/macports/newport`** writes the Portfile.
  - The layout is `port lint --nitpick`'s: the modeline, values in one column, and rmd160, sha256, and size checksums.
  - It uses the github PortGroup and `github.setup` with the tag's prefix, plus `github.tarball_from archive`. The build files decide the rest:
    - `Cargo.toml` adds the cargo PortGroup;
    - `go.mod` uses the golang PortGroup and `go.setup` instead;
    - `meson.build`, `CMakeLists.txt`, `pyproject.toml`, or `setup.py` add meson, cmake 1.1, or python;
    - `configure.ac` without `configure` sets `use_autoreconf yes`.
  - A Rust project's `cargo.crates` come straight from its `Cargo.lock`: each registry package's name, version, and checksum, sorted the way cargo2port writes them.
  - Licenses go from SPDX to MacPorts' names (Apache-2.0 is Apache-2, BSD-3-Clause is BSD, and so on). One MacPorts has no name for is written as `unknown`, and marked.
- **Guesses are marked, never presented as fact.** A `# dockhand: unconfirmed, …` comment sits above:
  - the license (the forge's detection);
  - the long description;
  - the category, when it was guessed;
  - the maintainer, when the config names none (`nomaintainer`);
  - a build the files don't settle: Go's vendors, Python's versions, or an unrecognized build.

  `create` lists what it marked.
- **The category** is `--category`, asked on a terminal with a guess as the default, or guessed and marked. The **name** is `--name`, else the project's in lower case, with `py-` for a Python project. The **maintainer** is the config's `maintainer`.
- **Schema 8** lets an edit's kind be `create`.
- **Git:**
  - `Repository.Add` stages new files;
  - `ExistingPaths` lists which of several paths a tree holds, in one call.

## Not yet

- **Registry names** (`pypi:`, `crates:`, `go:`), **GitLab URLs**, and **`--like <port>`**. The URL parser says so plainly for anything that isn't GitHub.
- **`go.vendors`**. Every module zip would have to be fetched for its rmd160, sha256, and size, which is go2port's job. The Portfile marks it.
- **A project with no release.** `create` names the version from the latest release, and says so when there is none.
- **Treating `--nitpick` findings as errors for a new port in `check`.** That belongs to the Tart provider's lint step.
