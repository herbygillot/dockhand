# Adopt

Discussed and agreed on 2026-09-21 after the morning's exercise: the contribution branch is dockhand's unit of work, and a person's branch should be able to enter it without a build. Adoption existed as a side effect of `verify --adopt` and `publish --adopt`, so a malformed branch was discovered inside a verify that had already started a VM, and there was no way to ask what dockhand would make of a branch.

**The command.** `adopt <branch> [port]` tracks a branch dockhand did not make as a contribution under its own name. It fetches master, requires the branch to be one commit above a commit of master, refusing a stacked branch with its commit count and a branch off master with a word about rebasing, requires that commit to change one port directory, infers the port from that directory unless one is named, checks that a named port lives there, binds the target and release scope the way verification does, and records the change and its first revision. `--dry-run` reports all of that and records nothing. Once tracked, verify builds it, publish opens its pull request, amend and rebase revise it, and status shows it; `--adopt` on verify and publish stays as the one-step spelling, and its help now names the command.

**The hatch.** A preparation refused as an unsupported source edit, in a dry run or at binding, ends with the way out: make the edit by hand on a branch and adopt it, and report the Portfile at the issue tracker if dockhand should have handled it. `assess` says the same once when any port came back unsupported. The other hatch already existed and the day showed it: when dockhand's edit was right but the port needed a patch, xymon-client, `amend` carried it.

**Decided for later, recorded in the roadmap's Next section:** preparing onto a contribution's own revision, which is what `bump` on a branch-only port needs; `--adopt` on the three preparations; `adopt --squash`; and multi-target contributions with one commit per port directory, which adopt refuses until then by naming the directories.

The engine's call reuses the untracked-source rule publication already enforced, the target binding verification uses, and the ancestry check the base check already made, now exposed as two git helpers, `IsAncestor` and `CountCommits`. Tests cover a dry run that records nothing, the recorded change and revision, a second adoption refused by port name, a stacked branch, and a two-directory branch, at the engine and through the command.
