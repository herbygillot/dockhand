## What changed

- **A change record never narrows the scope past what it covered** (finding 1). Any record that found a change counted as the whole scope, so a revision changing one subport natively and another only under Darwin 19 narrowed to the first. `portfile.UnseenChanges` reads which subports the Portfile's text changed under a condition this Mac's evaluation doesn't take: inside a `platform` block, or a control structure whose condition reads the platform (the `os.*` variables, the deployment target, the macOS and Xcode versions, the build architecture). The record keeps them as `Unseen`, or `AllUnseen` for such a change outside any subport's block, and `ChangeRecord.Scope` adds the unseen subports to the changed ones, or leaves the text scope for `AllUnseen`. status notes an unseen subport as "changed where this Mac's evaluation doesn't look". `ChangePolicy` is 3, so earlier records are made again. Evaluating under other contexts stays with layer 1.
- **A record that couldn't be made is made again** (finding 5's first part). Collection skipped any recorded directory, failed or not; it now evaluates a failed one again and replaces it. A read that collects nothing, as status's, evaluates nothing and notes the record's own words, "the base couldn't be evaluated: …", where it said "not yet evaluated".
- **create refuses a Go module below its repository's root** (finding 3). `go:github.com/hashicorp/vault/api` resolved to the vault repository as if the module were its root, and the port would build the wrong thing. `registry` now refuses it with `ErrSubdirectory`, naming the subdirectory, whether the path names its forge or a go-import tag gives its root; a major version's suffix, `/v2` and on, isn't a subdirectory. A typed project reference that can build from a subdirectory comes after the release.
- **The rest:** finding 2, a patch's contents changing under the same name, which the upstream assessment reads as the base's source, is a known issue in the README; finding 4, one shared revision analysis, is roadmap step 5.1; the rest of finding 5 and finding 6 come after the release.

- **An Intel Mac is told Tart isn't for it** (the Intel CI job, row A6, once its suite passed). setup and `providers` told an Intel Mac "needs Tart: sudo port install tart, then dockhand setup tart", which would never work there. `tart.Supported` says whether this Mac's macOS guests run, Apple silicon's; `providers` and setup say "needs Apple silicon; checks here build on GitHub, with --on github", and `providers setup tart` refuses the same way. The job's prepare step puts `/opt/local/bin` on `PATH`, which a runner's step doesn't read from a login shell, so `update --plan` finds `portindex`. A check's "nowhere to build" error still lists `--on tart` on an Intel Mac, after `--on github`.
