# 2026-09-25: `check`, with your own script as the provider

Roadmap step 5, part 5 (Design v3 §3, §7, §11), except for the Tart guest. Tart, prefix, and github need a Mac or GitHub to prove, so the provider built here is `command`, your own script (§7). It is enough to run the whole check path here, and it is a real provider in its own right.

## The command

- **What `dockhand check` captures** depends on the flags:
  - By default it captures the branch's tracked files as they are on disk: a commit when they equal the committed tip, otherwise a numbered snapshot.
  - Checking again with nothing changed reuses the same snapshot.
  - `--staged` captures the index and `--head` the committed tip.
  - A `--branch` checked out elsewhere is checked at its committed tip, unless that worktree has edits. Then it asks for `--head` or `--working-tree` rather than choosing.
  - Untracked files are listed and left out; `--include` adds one without staging it.
  - Unresolved conflicts, or files that change while they are read, stop the capture.
- **The plan:**
  - Every subport of each directory the revision changes by MacPorts CI's rule, evaluated on each environment's platform.
  - Targets excluded by `replaced_by`, `known_fail`, or `supported_archs` are recorded with the platform and reason. A target excluded everywhere is not built, and an excluded target is not required to pass.
  - A target is **revision-only** when nothing under `files/` changed and the Portfile is identical once its `revision` lines are set aside. This is proven from the source, never from evaluated metadata.
  - Targets are in dependency order and otherwise keep their order, so a directory's subports stay together.
  - `--only` narrows the check and adds back the changed prerequisites it needs, marked as such. `--also` adds unchanged ports.
  - A directory that can't be evaluated, or a dependency cycle, leaves the plan unresolved with the reason; nothing is dropped.
  - `--plan` shows the plan and changes nothing.
- **Where it runs:**
  - `--on`, repeated, names the providers, all of which must pass. `check.on` in the config sets the default.
  - `--on tart…`, `prefix`, and `github` say they are not in v3 yet.
  - Without `serve`, the check runs in the foreground and says so. It prints progress from the event journal, then each target's result per environment.
  - With `serve` leading, the check is handed over and followed. `serve` itself is the next part.
  - `-d` queues the check and says whether anything will run it.
- **Exit codes follow §12:** 2 for a failed check, 3 for attention needed, 130 for an interrupt. `main` now maps them; before this, every error exited 1.

## The runner

`Drive` runs a queued run under the session's fenced lease on it.

- **One guest execution per environment.** Each target's result is checkpointed through `Build.Record` as it finishes.
  - A target whose changed dependency did not pass is blocked, not built, and never failed. Anything a provider leaves unrecorded behind a failed dependency is recorded as blocked.
  - Trouble with the environment is tried again, up to three attempts. A later attempt builds only what has no complete verdict yet, because verdicts are final and are merged across attempts.
  - An execution left running by a process that died counts as infrastructure trouble and is tried again.
- **The run's outcome:**
  - `passed`;
  - `failed` when any target failed or was blocked;
  - `attention` when a provider is missing, attempts ran out, or targets did not finish;
  - `canceled`.
- **Cancel** (§11):
  - `RequestCancel` records the request on the run. A queued run is canceled at once.
  - The driver notices the request within a poll interval and stops, keeping what finished. When no live session holds the run, the canceller applies it itself.
  - An interrupt settles the run the same way.

## The command provider

`internal/provider/script` gives the script a request file and reads its result file. The format is in [docs/command-provider.md](../command-provider.md).

- The revision is a Git bundle less the base, so a clone of master can fetch it. A snapshot becomes a commit of its files on the base, kept under `refs/dockhand/revisions/`.
- A missing or unreadable result file is infrastructure trouble.
- Each attempt has its own directory under the logs beside the database, and the script's output goes to `command.log`.

## Other changes

- **Schema 3** adds a run's cancel request.
- The evaluator now also reads `known_fail` and `supported_archs`.
- `coord` gains `Holder`, which names a resource's live holder without taking it. `check` uses it to tell whether `serve` leads.
- Evidence for `submit` merges verdicts across attempts and skips excluded environments. The PR body's grid shows "— excluded".
- Configuration gains `[check] on` and `tests`, and `[providers.command] run` and `name`, all checked on reading.

## Tests

- **Engine tests** (with a stand-in evaluator and provider) cover:
  - capture: commit or snapshot, reuse, `--staged`, `--head`, and `--include`;
  - the plan: scope, subports, dependency order, per-release exclusions, revision-only proven from source, `--only` with prerequisites, `--also`, unresolved evaluation, and cycles;
  - the runner: a passing run as evidence, one retry after a VM stops mid-run, blocking without a retry, attempts running out, a missing provider, and a cancel applied by the live holder or at once when queued.
- **Command-provider tests** run a real shell script. They cover the request file, a bundle that lists the revision under its ref, results including advisory test failures, and a script that writes nothing, tried three times.
- **Command tests** cover:
  - `check` with no provider;
  - `--plan`;
  - a foreground run;
  - `-d` with no `serve`;
  - a failed check exiting 2.
- **Also here:** the config and coord tests. The full suite passes with `TMPDIR` behind a symlink, as on macOS, and so do the race runs, `go vet` (Linux and `GOOS=darwin`), `make vendor-check`, and `make fmt-check`.

**Not proven here:** the real planner on MacPorts' evaluator (it needs `port-tclsh`), and the Tart, prefix, and github providers.

## Still to come in this part of the design

- `--replace`, `--variants`, `--baseline`, `--lint`, and `--also-dependents`.
- `retry`, and per-target reuse across runs (whole-tree evidence stands until then).
- An untracked patch that a changed Portfile references should be a missing-input error. It isn't detected yet.
