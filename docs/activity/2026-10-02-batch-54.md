# 2026-10-02: git's guards, and the tree-read cache (batch 54)

Batch 54 of the [roadmap](../roadmap.md): the test plan's step 2 for git's ref and working-file primitives, step 3's `CommitBefore` and `CommitTime`, and the test suite analysis's tree-read cache, which the guards now cover. With it, the person's last decisions, D15 and D19, recorded: none is open.

## What changed

- **git's guards are tested** (`internal/git/guards_test.go`): a ref transaction whose `git update-ref` is killed, through a stand-in git, or whose context has ended, is `ErrRefUpdateUncertain`, for the caller to read back, while a ref that isn't as expected is a `RefConflict`; a working file that appeared or went since its edit was prepared stops every edit, as one that changed did already; and writing working files deletes one, creates one in a directory not there yet, and sets and clears the executable bit. None found a defect.
- **`CommitBefore` and `CommitTime` are tested**, which the port index mirror reads: the newest first-parent commit at or before an instant, start included, none before the first, and a commit's committer time; both refuse a name that isn't an object ID.
- **Tree reads are kept for the process**, by repository and object ID, since a tree's ID names its contents: `ReadTree` runs `git ls-tree` once a tree, where a path read walked it one directory at a time, again for each file. At most 16,384 trees are kept, then forgotten. Engine's tests went from 115 s to between 99 and 110 s here; dockhand reading many Portfiles of one tree does fewer runs of git the same way.
