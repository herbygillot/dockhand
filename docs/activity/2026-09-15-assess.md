# Preparation assessment

Implemented `dockhand assess` for explicit ports, maintainer/category filters, and `--all`. `--version` resolves one exact release using the same tag-prefix inference as bump. Human output and JSON retain per-check findings, version-input locations, and explicit untested stages. Mixed selectors and ambiguous version selection are rejected before repository work.

## Ownership and shared code

- Added `internal/assess` for assessment orchestration; it has no workflow or state dependency. `app` wires integrations and `cli` owns flags, rendering, and exit status.
- Moved existing committed-source selection and workspace lifetime from `outdated` into `internal/macports/survey`, shared by both capabilities. Index omissions remain visible, and indexed subports are not mistaken for their primary ports.
- Added assessment evidence in `macports/portedit`, using its existing native evaluator and literal-input probes. Failed counterfactual evaluations remain unknown through a typed error; error strings are not parsed to choose outcomes.
- Extracted the archive preparation plan up to the first download, dependency declaration/patch checks, dependency source stripping, and checksum-source association checks. Assessment and bump use those same operations.
- Added a typed missing-helper error. Assessment checks configured helper availability without running `go2port` or `cargo2port`.
- Kept PortIndex reading and staging in one package. The all-port filter is small and retains existing coverage reporting; this implementation did not require a further split.

All assessment code and tests were authored for this implementation. Existing v2 source selection and preparation code were moved or factored in place; no v1 comments or tests were copied.

## Result contract

`input-found` identifies local candidates, not a proof of a future update. `candidate-checked` requires the resolved release to pass the pre-download edit plan. Missing helpers are blocked; established preparation limitations are unsupported; inconclusive observations remain unknown. All findings are retained when more than one condition applies.

Source downloads, generated-manifest equivalence and preservation of maintained overrides, lint, builds, tests, and installation remain untested. Assessment uses committed HEAD and disposable materializations, and does not open state, create jobs, modify refs, or edit the user's checkout. Portfile Tcl still executes; the workspace is not a sandbox. Indexed scans can update the index cache.

## Validation

- Focused native tests cover literal, calculated/date, and procedure/fragment inputs; ambiguity; sibling changes; inconclusive real and synthetic probes; fetch/checksum limitations; and missing or present optional helpers without helper execution.
- CLI regressions cover exact tag and inferred prefix selection, per-port failure retention, duplicate selectors, selector validation, human/JSON output, all-port and filtered index coverage, dirty checkout preservation, unchanged refs, no database or source downloads, and temporary-source cleanup.
- Import guards protect the new assessment boundary and the updated outdated boundary.
- Full serial Go suite, focused race-enabled tests, vet, build, and whitespace checks were run; final results recorded below.
