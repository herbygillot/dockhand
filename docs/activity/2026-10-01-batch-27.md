# 2026-10-01: a Go pin the update outgrows (batch 27)

Batch 27 of the [roadmap](../roadmap.md), from the trivy run ([#35083](https://github.com/macports/macports-ports/pull/35083)); an agent's work, reviewed and merged.

## What changed

- **A Go the Portfile pins, older than go.mod requires, holds.** trivy 0.75.0's go.mod requires Go 1.27.0; `update` raised `go.toolchain_min` from 1.26.3 to 1.27.0 and said the minimum "already gates on" it, while the Portfile pinned Go 1.26 (`go.bin ${prefix}/bin/go-1.26`, `depends_build port:go-1.26`), which a build can't get past. The toolchain rule judged the requirement against the minimum alone.
  - `macports.PortInfo.GoPinned` reads the pin: a `go.bin` naming one of the versioned toolchains, as `${prefix}/bin/go-1.26` or the go in its GOROOT, and a build or library dependency on `go-1.NN`, which a port may pin with alone, putting the toolchain on PATH, as vault and usql do. The evaluator now reads `go.bin`; snapshots from before still find a pin through the dependency.
  - The toolchain rule says it in the same finding: "upstream: go.mod requires Go 1.27.0, but the Portfile pins go-1.26 (go.bin, depends_build); the pin may be obsolete", which replaces "already gates on" where a pin contradicts it, and follows "is raised from 1.26.3" where the minimum was raised. It holds where the pin is the candidate's, or the base's go.mod couldn't be read; a pin the base had, already short of the base's go.mod, is said and holds nothing.
  - `update` warns of the pin as it reads go.mod, and leaves it in the Portfile for the maintainer to remove.
- **`assess.Policy` is 10,** which also has assessments recorded before batch 23 made again, with what they read and checked.

## Decided along the way

- **One finding, not two.** The pin joins the `go-toolchain` finding, keeping its identity, and is `present` only where every problem it names was the base's too.
- **`go.bin` decides** where it names a series, since the build runs it; otherwise the newest series a dependency names. Run dependencies, `go-devel`, and the plain `go` port aren't pins.
