# 2026-09-25: --json

Design v3 §12: `--json` writes one versioned envelope on standard output.

## What changed

- **The envelope** has five keys: `{"version": 1, "command", "exit_code", "error", "result"}`, with snake_case keys throughout.
  - It is written when the command ends, and nothing else goes to standard output. Progress stays on standard error.
  - The error is carried in the envelope rather than printed. The process still exits with the outcome's code: 2 for a failed check, 3 for attention.
  - A command line that fails to parse still gets an envelope.
- **Which commands report JSON.** `status` (and bare `dockhand`), `path`, `diff`, `impact`, `check`, `retry`, `wait`, and `queue` report their results:
  - `status` gives the attention list, with each row's kind (`failed`, `needs_you`, `ready`) and next command. It also gives each branch with its ports, work, latest check and its targets' results, active checks, and pull request (with GitHub's last reading). With `--attention`, it gives the list alone.
  - `check`, `retry`, and `wait` give the revision, the plan (targets, exclusions, unresolved ports), the run, and each target's result in each environment. `--plan` gives the plan with no run, and `-d` the queued run.
  - `queue` gives serve's line and the runs.
  - `diff` gives the port changes and files, and the patch unless `--stat`.
  - `impact` gives dependents with their phases, and shared files with the ports that load them.
  - `path` gives the path.
- **Every other command refuses `--json` before it does anything.** A script can't have `tidy` or `submit` do work whose result it can't read. Those commands follow as their results are given shapes.
- **A `--json` command line never asks.** It counts as no terminal, so a missing choice is an error, as for any script. JSON never implies approval.

## Pushback

The design lists four keys and calls the envelope versioned. The version is a fifth key, `version`, so a script can tell a result shape it doesn't know. The results use their own snake_case types in `command/json.go`, not the engine's or the model's, so the stored model can change without changing what scripts read.

## Tests

`TestJSONEnvelopes` decodes all of standard output as one envelope each time, and covers:
- `check --plan`;
- `check -d`, then `queue`, then `wait` with a target's result;
- `status`, and `status --attention` exiting 3 with a `ready` row;
- `diff` with its patch, and `path`;
- a failed check exiting 2, with the error and the failing phase;
- `tidy` refused with nothing done;
- an unknown flag.
