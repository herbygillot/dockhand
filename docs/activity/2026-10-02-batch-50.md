# 2026-10-02: field testing's eighth report (batch 50)

Batch 50 of the [roadmap](../roadmap.md): three of the four ports field testing's 21-port update batch couldn't update at 200a077e, taken first since field testing retries them as fixes land. Each claim was checked against the code before it was changed, and each holds.

## What changed

- **pgdog: a Git crate the Portfile declares stays declared, under its own label.** pgdog's lock pins scram and pg_raw_parse by `?rev=`, which `cargo.crates_github` can't express, since the cargo PortGroup writes the declared value into Cargo's source replacement as a branch; with `cargo.offline_cmd` empty, depblock leaves such crates to Cargo's online resolution and declares none. pgdog's maintainer declares both anyway, labelled `master`, at the lock's commits, so the old source's regenerated block, empty, differed from the Portfile's, and the update was refused. `GeneratedBlocks.KeepingDeclared` now declares again, at the lock's commit and under the Portfile's label, each crate left online that the Portfile declares by name and repository, for the old source and the new alike: the comparison is by commit, and the rewrite keeps the label.
- **termusic: what differs is named, and an override the lock moves past is dropped.** "existing cargo.crates differs" named nothing; `depblock.Differences` names each crate, module, or Git crate that differs, and the refusal says them. A registry crate the Portfile pins at another version than the old lock's, termusic's soundtouch 0.4.1 over 0.4.0, is an override: it's kept back while the new lock is below it, refused then and named, and dropped once the new lock has the crate at the pin's version or later, which the update says ("The Portfile pinned soundtouch 0.4.1 over the lock's 0.4.0; the new lock has 0.5.4, so the pin is dropped."), and `--json` carries as `dropped_pins`. Whether an override goes is decided after the new lock is read, so a refused one now costs the downloads; any other difference is still refused before them.
- **reposurgeon: the Go PortGroup's toolchain check is recognized for every host go.setup fetches from.** The pre-fetch hook is the PortGroup's, registered whatever `go.domain` is, and was recognized only for github.com; reposurgeon's is gitlab.com. `macports.GoDomains` lists the six hosts the PortGroup's `go.setup` handles (github.com, gitlab.com, bitbucket.org, git.sr.ht, codeberg.org, gitea.com), and any other domain is still refused, naming them.
