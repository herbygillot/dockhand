# Tart's limit is the Mac's VMs

2026-10-27, at the person's "Let macOS be the limit. Not Dockhand."
(2026-10-26 20:24Z; roadmap 124f9546). `providers.tart.capacity`, 1 when
unset, let one check at a time use Tart in a database, foreground checks
too (engine/slots.go `awaitSlot`), so a second check waited while the Mac
had a VM free.

- The key is deleted (config's TartProvider), with no alias: a file that
  still sets it is refused by name, as any unknown key is, and `dockhand
  config` no longer lists it. Tart's capacity is `config.TartCapacity`, 2,
  as many checks as the Mac runs VMs; each check's VMs still wait for a
  free one before they start (buildenv/tart's `slot`), so a minmax check
  beside another waits for its second VM.
- A third check's wait says "Tart takes as many checks as the Mac runs
  VMs, 2, and check-1 and check-2 are using them"; serve's capacity line
  says "tart (as many checks as the Mac runs VMs, 2, each VM waiting for a
  free one)". docs/usage.md says to delete the line.

v0.7.0's release notes, when they're written, say to delete a
`providers.tart.capacity` line.
