Batch 81 of the [roadmap](../roadmap.md): step 3, from the M1's quick stage rerun at 95f28fe0 (the project's plan/quick-run-2026-10-03-b.md): 23 passed, 3 refused well, 4 known issues, 13 failed, 3 blockers by H6, and 1 not run, where the first run had 18 pass and 18 fail.

## What changed

dockhand:

- **An altered kept archive is built, not given to a guest** (D-T1). A kept archive counted as kept by its size alone, so one altered by a byte was chosen to give a guest, where signing it would have refused it and failed the check. `installs` now reads its digest, and one that isn't what it was kept as is left to MacPorts to build, with an event: "the archive kept of X isn't the one it was kept as, …, so the guest builds it instead". Keeping a build's archive replaces an altered one. In the quick stage no kept archive is given to a guest, since its ports depend on none, so D-T1 says so as not run; the engine's test alters one.
- **A submit is suggested with the fork it needs** (D-S6). status's `Next:` and attention rows say "fork macports/macports-ports on GitHub and add it as a Git remote, then dockhand submit --branch X" where no remote pushes to a GitHub repository but MacPorts' own, read from the remotes' addresses alone.
- **A role GitHub won't say is unknown access** (E9). `review` failed on a 403 for collaborators/permission, which GitHub gives a fine-grained token not granted the repository; that's `forge.ErrAccessUnknown`, the review goes on with "access dockhand couldn't read with this login", and only requesting changes waits.
- **core.autocrlf** (F4). A worktree's CRLF lines read as a change of every line, and `update` said the Portfile changed while its edit was prepared. Working files are hashed, and edits' blobs written, as Git cleans them at their path (`hash-object --path`), the ports tree's `.gitattributes` and core.autocrlf applied, so a CRLF checkout is the LF blob it came from and a `.diff` stays as it is.
- **A0's dispatcher test** piped echo into true, which exits without reading, so echo now and then wrote to a pipe with no reader; its pipeline's writer now writes nothing.

The harness:

- **H6 runs only the Next: lines after a row's own breakage**: `next_superseded` marks the lines before a rename (D-S5), a deletion (D-S9), or a removed worktree (D-S3) the row makes on purpose. In the quick stage, a submit refused for want of a GitHub fork is unverified, not broken.
- **D-I3 moved the pinned upstream to the tip** of the person's tree, where dust's update had landed: `rev-list -1 --reverse` limits before it reverses. It moves one commit now.
- **A10** marks submit and other releases' checks as not run in the quick stage, which has no GitHub fork and only this Mac's image.
- **D-R2** clears slot VMs a killed run left; **F4**'s setup is graded as setup's; and quick.sh says a token file others can read.

- **The test account** (herbyg-test, 2026-10-03): where `ACCEPT_GH_FORK` names its fork, the quick stage adds a remote `github` read over HTTPS, which submit's preview finds as the fork (D-S6), with an SSH push URL its `GIT_SSH_COMMAND` refuses outright, so nothing is pushed there and no key, the agent's included, is offered. The full stage offers the test account's key alone (`ACCEPT_GH_KEY`, `IdentitiesOnly=yes`, no agent), since the agent on the M1 holds Herby's own key, and `reset-user.sh` copies it into dhtest. Tried in a scratch repository: the push was refused, and the read answered.
