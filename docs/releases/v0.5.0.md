# dockhand v0.5.0 release notes

The third release of dockhand v3, tagged on 6246e4b9, the commit of
v0.5.0-rc5. The stage ran five candidates, rc1 to rc5. rc2 fixed Rust
updates that list their crates, which rc1 refused; rc3 took the fixes
from an architecture review of rc1's commit, among them serve holding a
source whose current commit it couldn't read; rc4 said a wait for a VM
slot at every level; and rc5 fixed Go updates whose `go.vendors` carries
its checksums.

## What's new since v0.4.0

- **Output says what changed, and `-v` says the rest.** By default a
  command says what changed, a line per stage with its outcome, what
  needs you, and one `Next:`: a clean `bump jq`'s 46 lines in v0.4.0
  become a line per stage. Each stage's full report, a check's attempts
  and provider steps, the processes table, and GitHub's request count
  are `-v`'s; `-vv` is as before. A stage that held or failed, or asks, still shows its report.
  `ship --mine` prints a row per port, its stages as cells, then "Needs
  you".
- **Marks and width.** `✗` is broken, `!` look at this, `✓` done, and
  `⋯` under way, in every command; a hold is said as "held". On a
  terminal the marks alone are coloured, and a table's widest cell is
  cut with `…`. Off a terminal, under `NO_COLOR`, and with `--json`,
  nothing is coloured or cut, and prose wraps at `COLUMNS`, else 100.
- **An overview for `status`, `outdated`, `clean`, and `setup`.**
  `status` groups branches under "Needs you" and "Working", with the
  pull requests waiting on reviewers as a count with CI's tally; `status
  -v` lists every branch, the checks, and the dockhand processes working
  on the checkout. `outdated` groups ports into Ready to ship, Held, Not
  checked, and Current. `clean` says what it did in one line.
- **`explain` for checks and branches.** `explain check-42` says where a
  check failed, the failed step's last lines, and whether a baseline can
  say more; `explain -b <branch>` says where a branch stands and what
  clears it. A failed check's `Next:` names it.
- **The command contract.** Every command takes `--json`, or says why
  not, and keeps `--plan` apart from `--yes`. `bump --plan` and `clean
  --plan` show what a run would do. `checksums` and `revbump` plan on
  master without a branch, as `update` does. A refusal says its kind,
  which decides its exit code, and ends with its `Next:` steps: "couldn't
  reach GitHub" is said as the network's, not as git's words.
- **One verdict on a branch.** status, tidy, submit, serve, and the hold
  list read one judgment of a branch's state, where each judged it for
  itself. `status --json` gives each branch's `check_standing`. `submit`
  commits edits not yet committed, as `tidy` would, and submits them.
- **Strict fidelity in `update`'s plan.** Each edit predicts what it
  changes, and the result must equal the prediction. A sibling that moves
  with the version is a finding `--shared-release` answers, not a
  refusal, and a sibling that fetches its own archives, as xapian-core's
  bindings do, has them fetched and its checksums written. A commit pin,
  as wezterm's, moves to the branch's head or a commit named; a version
  in several literals, as openjdk's, moves together; and LyX's revision
  and checksums, set in each branch of an `if`, are found.
- **Standing acceptance of a failure.** `submit --accept <port>
  --standing` accepts a dependency failing to install on an image, keyed
  to the dependency's version and the image: later checks name it, and
  submit, bump, and serve take it until either changes. A failed result
  names the dependency and its version. `holds.allow` lists rules whose
  concerns an unattended update says and goes on past.
- **The libraries a build links.** A passed build on Tart records what
  each installed Mach-O links under the prefix, and the port that
  provides it. A link to a port `depends_lib` doesn't declare is a
  notice, in the check's report and the branch's detail; a clean scan
  says so, as "crystal links 5 ports, each declared in depends_lib".
- **Working on a check.** `check --keep` keeps each Tart clone where its
  guest finished, passed or failed, and `dockhand shell check-N` runs a
  command or a shell in it; `shell --test` reruns the port's test phase.
  `logs --follow` prints a running target's log as it grows, and `logs
  --phase` one step of it. A failed test phase brings back the tests'
  own logs and names the tests that failed. `check -d` with no serve
  leading starts a background drain.
- **Waiting is said.** A check waiting for a VM slot says so at every
  level, with or without a terminal.
- **serve holds on an unknown current commit.** A source whose current
  commit couldn't be read holds serve, and a person's submission shows
  it.
- **CI failures by cause.** status reads a pull request's failed CI
  jobs' logs, and says a fetch failure as one, as "failed fetching
  jni-sys-macros-0.4.1.crate (mirror.sjtu.edu.cn answered 403)"; `retry
  --ci -b <branch>` runs the failed jobs again, with write access.
- **Branches and cleanup.** `clean --delete` forgets an archived branch,
  its Git branch, worktree, and record, listing its unmerged commits
  first. A command naming a branch finds its checkout from outside the
  ports tree. `outdated` asks before a look past GitHub's hourly
  allowance, and refuses without a terminal unless `--over-allowance`.
- **Fixes the candidates found:** a Rust update listing its crates
  refused on `dist_subdir` (rc2); a Go update whose `go.vendors` carries
  its checksums refused (rc5); a Go module's major-version suffix, as
  direnv's `/v2`, read as a moved module (rc5); and a long `go.vendors`
  block, as opkssh's, passing the RPC frame limit (rc5).
- **Fixed from v0.4.0's known issues:** a license file gaining labels or
  copyright lines, status during a passed check's baseline, a
  configure.ac library named by a variable, the baseline offered for new
  tests, the 97 ports refused for a PortGroup reading the host, wezterm's
  panic, `tidy` leaving out a new patch, a diagnostic check's extra
  releases, build files below the source's top, `--follow-moves` on a
  branch at the version, and `logs` before a branch's first check.
- **For developers: a Portfile corpus.** `make test-corpus` replays
  MacPorts' own last bumps of 12 Go and Rust ports through `update
  --plan` and compares the version, checksums, and dependency blocks.
  rc4 matched 5 of 12, rc5 matches 12. It needs the network.

## Upgrading from v0.4.0

- The database, `~/.dockhand/dockhand.db`, is migrated forward, from
  schema 32 to 39, the first time v0.5.0 opens it, and a copy of it as
  it was is kept beside it. v0.4.0 can't open it after; a migration is
  refused while a dockhand process on the older schema is working,
  unless you answer it. Any command migrates it, `status` included. To
  try a newer build without touching your database, point DOCKHAND_DB at
  a copy of it. Acceptances move into the decision record unchanged in
  meaning.
- Scripts that read a check's progress at the default level, such as
  "runs here" or "attempt 2 of", pass `-v`: off a terminal it's `-v`'s
  now. The same goes for each stage's full report from `ship`, `bump`,
  and serve's batch.
- `submit` on a branch with edits not yet committed commits and submits
  them, where it refused; `submit --plan` shows the commits it would
  make, and `--head` submits the committed head alone, as before.
- A commit rule's warning is said and holds nothing in serve, as `tidy`
  keeps the commit; an error still holds.

## Known issues

Each harms nothing a look wouldn't catch, and each has a workaround. The
README's [known issues](../../README.md#known-issues-in-v050) list them in
full, as they stand in this release. Those marked are fixed on main, for
the release after v0.5.0:

- `check` builds on this Mac's release unless told otherwise, and
  MacPorts CI also builds on macOS 14 and 15. `submit` and the pull
  request say which releases no check covered; `--build macports-ci`
  checks on all three, and `build.default = "macports-ci"` makes it the
  default.
- A batch of submits, with serve watching their pull requests, can spend
  GitHub's hourly limit of requests; dockhand says when it lifts. Signed
  out, the limit is 60 requests an hour, and serve's watch of a single
  open pull request spends it all. Sign in with `dockhand setup github`.
  Fixed on main: signed out, a refresh reads each open pull request's
  state alone, and stops short of the limit.
- On a new macOS release, before MacPorts' builders have archives of a
  Rust or Go toolchain, the first Tart check of a Rust or Go port there
  builds the toolchain from source, for hours. The check says so first.
  Check such a port on the previous release, `--on tahoe`, or let the
  first check run.
- After you pull a collaborator's commit to a branch's pull request and
  discard it with a reset, `submit` replaces their commit with yours.
  Its preview says so on its Push line; read it before you confirm.
  Fixed on main: a commit replaces theirs only when it's their commit
  amended.
- A port whose project moved its releases to another repository, so the
  old repository's tags stop below the port's version, reads as current
  in `outdated`, as mergestat, carl, and zed with zq do. Check such a
  port's project page. Fixed on main (1c9d5a47): `outdated` holds it for
  a look, and `update` asks for the version to take.

- A trailer given in `tidy --squash --message` that the branch's
  commits already carry, as `Assisted-by:`, is written twice in the
  squashed commit. Leave it out of the message: tidy keeps the commits'
  own trailers. Fixed on main: a trailer the message gives is written
  once.
