# dockhand v0.4.0 release notes

The second release of dockhand v3, tagged on 5897a828, the commit of
v0.4.0-rc5. It passed the full acceptance stage on an M1 Mac, in a fresh
macOS account with dockhand installed from its own Portfile. The stage ran
five candidates, rc1 to rc5, and covered an upgrade from rc4 while `serve`
ran, a 24-hour soak of `serve` across 1102 ports, sleep and reboot during a
check, and use over SSH with nobody at the screen. It found nothing that
harms work, logins, pushes, or pull requests.

What dockhand does, and what it needs, is in the [README](../../README.md).
To build this release, clone its tag:

```sh
git clone --branch v0.4.0 https://github.com/herbygillot/dockhand.git
cd dockhand
make build
```

## What's new since v0.3.1

- **`ship` and `bump`.** `dockhand ship <port>` takes a change from a new
  release to its pull request: the update, one commit, a check, and the
  submission, asking once on a terminal. `dockhand bump <port>` is the same
  asking nothing, and stops wherever a person should look. `ship --mine`
  takes your ports with newer releases, and `ship --passing` submits the
  branches whose checks passed.
- **Holds.** A change nobody looks over waits for a look where one is due:
  a new major version (`holds.majors`), another open pull request for the
  port, what comparing the upstream archives found, and a commit rule's
  finding. It also holds a repository transferred or renamed upstream,
  until `update --follow-moves` points github.setup at it; a revision that
  raises a port's darwin floor or `macosx_deployment_target`; and an
  archive name MacPorts' mirror already holds another file of under a
  shared `dist_subdir`, as gopls's was, naming `dist_subdir ${name}` as the
  fix. Each says the command to run after the look.
- **Build profiles.** Where a check builds is a profile: `host`, `minmax`
  (each port's oldest and newest release), `macports-ci` (the releases
  MacPorts' CI builds on), `all`, or one of your own under
  `[build.profiles]`. `build.default` and `build.unattended` name which.
- **Baselines and accepted failures.** After a failed check, `check
  --baseline` builds the ports that failed at master, and `submit
  --accept` takes a failure master shares, which the pull request says.
- **Scripts.** A refusal is one sentence and exits 1, `--yes` answers the
  questions, and the exit codes are named. `checksums --plan` plans on
  master, and exits 3 naming each distfile that doesn't match.
- **`status` and `serve`.** `status` reads stale pull requests itself, in
  one GraphQL request it shares with `serve`. serve's daily look notifies
  when the ports it found changed, and `serve --install` and `--uninstall`
  wait for launchd.
- **Progress.** A check shows the Tart guest's progress as it goes, and
  says which dependencies build from source. A command that waits says
  what it's waiting on.
- **Branches.** A command in a checkout dockhand doesn't track offers to
  track it. Starting a branch on an archived branch's name offers to rename
  the old one aside. `adopt` names the ports not yet committed.
- **`submit`.** A commit made on, or amending, someone else's push now
  submits. `--accept` takes a changed port whose baseline fails the same
  way, and the description says why each accepted failure was accepted.
- **Updates and fetches.** Go toolchain ports, as go-1.26's
  `go_toolchain.setup`, update. A redirect is followed with no Referer,
  which fixes SourceForge mirrors that served an HTML page. Mirrors behind
  a new release are said, and tried again later. `outdated` counts the
  ports it didn't check by reason, says a release that isn't ready, and
  lists in MacPorts' name order.
- **Tart and checks.** A new image installs this Mac's MacPorts, and one
  note names stale images. `check` marks the untracked files in the ports
  it builds.
- **The command surface is final for v0.4.0.**
  - `-b` names only an existing branch; `--new=<name>` starts one.
  - `ship` replaces `update --submit`, `update --outdated`, `submit
    --check`, and `submit --passing`, and `serve.ship_to` replaces
    `serve.for_outdated` and `serve.submit_passing`.
  - `queue` and `watch` fold into `status` (`status --watch`).
  - `status`, `path`, `archive`, and the run commands take `-b`, `-p`, and
    `--pr`.
  - `logs --all`, `outdated --all`, and `diff --archive` become `--full`,
    `--current`, and `--source`.
  - The hidden `auth` command is gone: `setup` names your GitHub login,
    and `setup --json` reports it.
- **Fixed from v0.3.1's known issues:** a GitHub tag moved after its check,
  the account a `GH_TOKEN` submits as, who requested changes in `submit
  --json`, `dockhand path` for a merged branch whose worktree `clean` kept,
  terraform's stub wording, an old Tart in `check` and `serve`, a deleted
  base image's restore, and a guest's error tried again three times where
  it isn't the VM's.

## Upgrading from v0.3.1

- The database, `~/.dockhand/dockhand.db`, is migrated forward the first
  time v0.4.0 opens it, and a copy of it as it was is kept beside it.
  v0.3.1 can't open it after; a migration is refused while a dockhand
  process on the older schema is working, unless you answer it.
- A configuration that names `serve.for_outdated` or `serve.submit_passing`
  is refused, with the `serve.ship_to` that replaces it: `for_outdated =
  "draft"` is `ship_to = "commit"`, and `submit_passing = true` is `ship_to
  = "submit"`.
- Scripts that ran `update --submit`, `submit --check`, or `submit
  --passing` run `ship` or `bump` instead.
- dockhand builds for macOS and Linux only.

## Known issues

Each harms nothing a look wouldn't catch, and each has a workaround. The
README's [known issues](../../README.md#known-issues-in-v040) list them in
full, as they stand in this release. Ten were found after rc5, and are
fixed on main for v0.5.0:

- An update whose license file keeps its licenses but gains labels,
  copyright lines, or terms of its own, as libxkbcommon 1.13.2's did,
  holds, saying the file "now reads as no license that's known". Read the
  license file's change with `dockhand diff --source`, then submit after a
  look.
- While a baseline of a passed check runs, `status` says the branch is
  checking, and `serve` and `ship --passing` wait to submit it. Let the
  baseline finish, or `dockhand submit --branch <name>`.
- An update whose configure.ac names a library through a shell variable, as
  GraphicsMagick 1.3.49's does, says that library was removed. Read
  configure.ac's change before submitting after a look.
- A failed check offers `check --baseline` for tests the branch adds and
  master doesn't run, where a baseline has nothing to compare.
- `update` refuses a port whose PortGroup reads the host as it loads, as
  qmake5's does, saying the version probe is inconclusive, though its
  version line and archives read nothing of the host: about 100 ports,
  LibreCAD, cpi, and the PyQt5 and Qt 5 ports among them. Edit the version
  line by hand, then run `dockhand checksums <port>`.
- `dockhand update <port>` for a port that pins its source to a commit
  and tracks a branch, as wezterm does, stops with a Go panic before it
  changes anything. Edit the commit and the version by hand, as `outdated`
  says, then `dockhand checksums <port>`.
- `tidy` commits a Portfile whose `patchfiles` names a new patch that Git
  doesn't track yet without the patch, and the check then fails fetching
  it. `git add` a new patch before `tidy`. `check` warns of an untracked
  file in a port it builds, but `ship` doesn't.
- A diagnostic check of some of a branch's ports on a release
  `build.default` doesn't name makes `submit` ask for every port of the
  branch there. Check the other ports on that release too, or make a
  diagnostic check on a branch of its own.
- The upstream comparison reads build files only at the top of a port's
  source, so a port that builds from a directory below it, as i2pd's
  `cmake.source_dir` does, can say "no build file changes" where that
  directory's changed. `dockhand diff --source --stat` lists it; read its
  change before submitting.
- `update --follow-moves` on a branch already at the version changes
  nothing, and `submit` still holds on the move. Pass `--follow-moves` on
  the update that moves the version, or edit github.setup's owner by hand.

## Not covered by the acceptance stage

- A non-English locale, a clock a few minutes off, and the daily look across
  the US clock change (F10) weren't run again. v0.3.0's stage passed them,
  and the code they cover hasn't changed since.
- A port whose new release is on Codeberg alone (C4), and a fixture MacPorts
  master can't hold (D-N2), weren't run.
- `serve` refreshing pull request states overnight had no open pull request
  to refresh. Updating a pull request was covered by `submit` and `ship`.
- Tart checks ran on macOS 27 only, the one release the Mac had images for.
  Other releases were covered by GitHub Actions on the fork, and by
  `check --on` refusing them with the `setup tart` that adds them.
- Downloads from SourceForge mirrors were covered by field testing on this
  commit, not by the stage: scons 4.11.1, GraphicsMagick 1.3.49, libpng
  1.6.59 and freetype 2.15.0.
- Some rows ran on rc4 and weren't repeated on rc5: device login, uninstall
  and reinstall, a revoked login, another account's `GH_TOKEN`, a pull
  request updated after review, and `port selfupdate` during a check. rc5's
  rerun repeated the rows its changes touch.
