v0.7.0's acceptance runs on the M1, as v0.6.0's did. Its full stage also
builds on one older Tart release, so `minmax` runs as two releases, with
two VMs and the wait for them. As planned, it adds:

- a port selection compared with `port echo`;
- two Tart VMs at once (S2 and B7);
- `status --all` on the test database, against rc2's 55 s;
- the build of a created gopls in Tart;
- G5, two outdated subports of one Portfile updated in one branch and
  tidied into a commit each, titled for its subport (`ACCEPT_SUBPORTS`).

```sh
git clone --branch v0.7.0 https://github.com/herbygillot/dockhand.git
cd dockhand
make build
```

## What's new since v0.6.0

- **Tart uses the Mac's VMs.** Tart takes as many checks as the Mac runs
  VMs, 2, where `providers.tart.capacity` let one check at a time use
  Tart. Each check's VMs still wait for a free one, so a `minmax` check
  beside another waits for its second VM. A third check's wait says
  "Tart takes as many checks as the Mac runs VMs, 2, and check-1 and
  check-2 are using them".
- **Another's Portfiles, and `review <pr> --check`.** Where dockhand
  evaluates on this Mac a Portfile someone else wrote, as an adopted pull
  request's, it says once whose: "Evaluating @alice's Portfiles on this
  Mac, for pr-4711". `review <pr> --check` adopts the pull request and
  checks it in Tart, or where `--on` says. The experimental notice on `review` and `adopt --pr` is gone.
- **`dockhand decide`.** `dockhand decide <rule> [<port>] --because "…"`
  records your answer to one hold with your reason; `--waiting "…"`
  records that you're waiting on something, which blocks submit. An
  acceptance lets the hold go for an unattended submission, is said under
  "Decided", and goes into the pull request as a "Reviewed:" block. It
  lapses when the port's own files change. Every held row's Next names
  the decide that answers it.
- **What the build installs.** A passed build records its own libraries'
  install names and the files it installed, and compares them with the
  port's earlier build in that environment, else with master's binary
  archive. A moved library is a notice naming its dependents and
  `update --revbump-dependents`, as "libexiv2.27.dylib is
  libexiv2.28.dylib now"; a file gone or added is a notice too. The
  configure phase's summary is compared the same way, so an optional
  dependency the build stopped finding is said. The check's report says
  them under "Against the earlier build", and so do status's detail and
  the pull request's description.
- **Patches.** A patch that applies at an offset is re-emitted from the
  applied tree, its header comment kept, and update says "Refreshed patch
  …". A patch that applies only with fuzz holds an unattended run
  (`patch-fuzz`); an attended update re-emits it and names each fuzzed
  hunk for you to look over. A hunk upstream already carries is dropped.
  A patch that doesn't apply (`patch-rejected`) stops an unattended ship
  before its check. patchcheck reads git's quoted file names.
- **After submit.** A merged pull request with commits past the merge
  offers `dockhand start --from <branch>`, which starts a branch from
  master with those commits. A pull request that conflicts with master is
  said, "#123 conflicts with master", with Next `dockhand rebase`. A
  failed MacPorts CI job quotes its log's first error line, and says each
  port's result, as "CI: exiv2 ✓, gpsbabel ✗ (build)".
- **Notices on a change.** tidy, submit's preview, and review say a line
  a PortGroup already sets (`restated`), a `port:` dependency the tree
  writes path-style (`path-style`), and a Trac ticket that belongs in a
  `Closes:` trailer (`ticket-trailer`). `update`, `ship`, and `bump` take
  `--closes <ticket>`, written as the `Closes:` trailer. A maintainer's
  instruction in a Portfile's comments is quoted, as "Do not update past
  3.8.3.". `port lint`'s warnings are said; for a port the branch adds,
  lint runs with `--nitpick` and its warnings hold submit until fixed or
  taken with `--accept`.
- **Port selectors.** `outdated`, `update`, and `ship` take
  `--maintainer`, `--category`, and `--not-maintainer`, combined as
  MacPorts combines them, beside `--mine`. serve's selection is
  `serve.maintainers`, `serve.categories`, and `serve.not_maintainers`,
  your ports when the first two are unset.
- **What an update says.** An update to a lower version raises the epoch,
  "Lower version: MacPorts orders 1.6 below 1.7, so the epoch is raised
  by one", and the `version-order` commit rule catches a hand edit that
  doesn't. An update's commit body says the version it updates from and
  links the release's page, else the compare page, at best effort. A stealth update says whether the archive's contents
  changed. A Go port's `-X` target that upstream moved, a C++ standard
  upstream raised past `compiler.cxx_standard`, literal Homebrew library
  paths the new source adds, and a moved repository whose old owner's
  name now belongs to another account are each said.
- **Holds and Next.** A build linking a port `depends_lib` doesn't
  declare holds an unattended submission (`link-undeclared`). Where a
  passing `host` check covers an update that raised a floor, Next names
  the wider check it asks for, with its port where it names a variant.
  After an amend, what still needs a pass names its platforms and their
  `--on`.
- **Checks.** `check` or `review --check` asked while the same files'
  check is running follows it, where it refused, if that check covers
  the one asked: its environments, targets, variants, tests, and
  freshness. One that doesn't is said, with what it doesn't cover, and
  check offers `--replace`, which stops it, keeping what it finished, and
  checks this one. A check's report and `status -v` give
  each release's and each target's time. A failed build's summary quotes
  the tool's last lines before MacPorts' "Command failed:". A queued check
  nothing is running says so, and how to run it. `dockhand artifacts
  [branch]` prints the archives the latest check built. setup says
  whether go2port and cargo2port are installed.
- **`create`.** `create go:<module>` takes a module below its
  repository's root, as `create go:golang.org/x/tools/gopls`, building in
  the module's directory. A Cargo workspace's programs are read from each
  member, and `create --plan` prints the Portfile it would write, writing
  nothing.
- **status and clean.** status gathers every branch's facts at once: on
  the test fixture's six branches, 62 git processes became 18. clean
  removes a merged branch whose changes are all on master, and offers the
  fork branches a closed, archived, or forgotten branch and a canceled
  check left. Where a `local` check is building in a prefix, status names
  the check holding it, "held by check-12 (pid 4711)", as a check waiting
  for it does.
- **`--json` carries what the text says.** A branch's status JSON has a
  "detail" with what its text details: your decisions, a Portfile's
  instructions, lint, undeclared links, and what moved. A finished
  check's JSON carries its report's lint, links, and installed files.
  `review --check --json` is the review, with its check inside it under
  "check", where it was the check alone.
- **serve's log and its idle cost.** Everything serve logs is a "serve:"
  line with its stamp; a fetch of master nobody waits on is no longer
  said in it, where rc6's acceptance found it 87 times in 16 hours.
  serve's submit pass reads only the branches a check has finished for,
  where it read every open branch every five minutes.
- **The pull request.** Its description fits GitHub's limit of 65,536
  characters, trimming the generated sections and saying so, and lists
  the dependents `--revbump-dependents --except` left out, with the
  reason, even where every one was left out.
- **Lint fixes on the lines a change touches.** Where an edit writes a
  Portfile, and in tidy's plan for a hand edit, dockhand fixes on each
  line the change adds or alters what `port lint` would say of it:
  trailing whitespace, leading tabs under MacPorts' modeline, a `\` that
  carries the next line's option into its command, and `maintainers
  openmaintainer` alone, which becomes `nomaintainer`. A version update of
  a port that fetches GitHub's tarball moves it to `github.tarball_from
  archive`, since its checksums are made anew, and names `releases` where
  the release carries its own archive. Each fix is said, "Fixed:" in
  update's report and "Fixes:" in a plan. `check` makes tidy's fixes in
  the working files before it captures them, so the check builds what
  tidy commits and a trailing space doesn't cost a second build.
- **Four more notices.** tidy, submit's preview, and review say a license
  named by its SPDX identifier where MacPorts names it otherwise, BSD for
  BSD-3-Clause (`license-spdx`); `supported_archs noarch` where platforms
  are darwin (`noarch-platforms`); an added line of commented-out Tcl
  (`commented-code`); and a file added under files/ that the Portfile
  doesn't name (`unreferenced-file`). None holds anything.
- **`tidy --restyle`.** Restyles each Portfile the branch changes whole,
  in a last commit of its own, "<port>: whitespace": trailing whitespace,
  tabs, indentation in fours, and each run of declarations' values lined
  up. A Portfile whose ports evaluate otherwise restyled is left as it
  was, under "Not restyled:". Nothing else restyles a line the change
  didn't touch.
- **Several ports of one Portfile.** `update` takes several ports, each to
  its newest release, in one branch: `update kubectl-1.34 kubectl-1.35
  --new` starts one, named for their directory. A version still goes with
  a lone port. `update --mine`, `ship`'s selection, and serve put the
  ports of one Portfile in one branch, where each had a branch of its
  own. tidy makes a commit for each update, in the order made, titled
  for its port, "kubectl-1.35: update to 1.35.10". Where it makes one
  commit for several subports, as after a hand edit between them, its
  subject names each, and your own message for dockhand's edits, as
  `tidy --squash --message` gave it, is kept, where `ship` rewrote it.
- **Saved tidy plans.** A plan saved with `tidy --plan --out`, on a branch
  that takes an untracked patch patchfiles names, applies; v0.6.0 refused
  it as stale.
- **Removed flags say what replaced them.** A flag an earlier release
  removed answers with its replacement, where it said "unknown flag":
  - `update --submit`: `ship <port>`; `update --check`: `ship <port> --to
    check`; `update --outdated`: `update --maintainer` or `--category`, or
    `ship --mine`.
  - `update --on`, `--note`, `--title`, `--skip-notification`,
    `--tested-binaries`, `--tested-variants`: update edits alone; `ship`
    and `submit` take them (`check --on` too).
  - `submit --check`: `ship -b <branch>`; `submit --on`: `ship --on`;
    `submit --passing`: `ship --passing`.
  - `serve --submit-passing`: `serve --ship-to submit`, or
    `serve.ship_to = "submit"`; `serve --no-submit-passing`: `serve
    --ship-to check`.
  - `logs --all`: `logs --full`; `outdated --all`: `outdated --current`;
    `diff --archive`: `diff --source`.
  - `clean --legacy`: nothing replaced it.
- **Fixed from v0.6.0's known issues:** `status --all` reading each
  branch in turn; an adopted pull request's Portfiles evaluated without
  saying whose; a saved tidy plan refused as stale over an untracked
  patch; comparing two license files using memory quadratic in their
  words, now bounded at 16 MB, past which the license is said as changed
  and holds; a self-hosted GitLab whose instance URL has a path refused
  for source archives; and a check started beside the guest program a
  crashed dockhand left building, which now waits for it, "waiting for
  check-12's program (pid 4711), which its dockhand left running, to
  finish in /opt/local".
- **MacPorts base's master.** Its SDK, tool, and compiler lookups, which
  it asks from another interpreter than 2.12 does, are answered for the
  context dockhand models, so a macOS 12 context no longer reads this
  Mac's SDK.

## Upgrading from v0.6.0

- Delete `providers.tart.capacity` from your config. A config that still
  sets it is refused: "providers.tart.capacity is gone: Tart takes as
  many checks as the Mac runs VMs; delete the line".
- No flag v0.6.0 takes is removed. The flags earlier releases removed now
  say what replaced them, each listed under What's new: `update
  --submit`, for one, answers "update --submit is gone: ship <port>
  updates, checks, and submits it".
- The database is migrated forward, through schemas 43 to 49, the first
  time v0.7.0 opens it, and a copy of it as it was is kept beside it.
  v0.6.0 can't open it after. Any command migrates it, `status` included.
  To try a newer build without touching your database, point DOCKHAND_DB
  at a copy made with `sqlite3 ~/.dockhand/dockhand.db ".backup <file>"`.
- "Unattended" means serve, and ship or bump with `--yes` or with nobody
  asked. The holds, `--hand-edit`, and the fuzzed patch's re-emission
  read it.
- New holds on unattended runs: `patch-fuzz`, `patch-rejected`, and
  `link-undeclared`. `holds.allow`, or a port's own `allow`, lets each
  go, and `dockhand decide` answers one for a branch.
- New errors among the commit rules: `version-order`, a lower version without a
  raised epoch, and `replaced-by-unchanged`, a `replaced_by` with the
  version, revision, and epoch all standing. `holds.allow` can name
  either.
- `review --check --json` prints the review, with its check under
  "check", where it printed the check alone. A script reading the check
  reads `.check`.

## Known issues

<!-- acceptance: pending. Add any known issue the stage finds, and mark
those fixed on main. -->

Each harms nothing a look wouldn't catch, and each has a workaround:

- `check` builds on this Mac's release unless told otherwise, and
  MacPorts CI also builds on macOS 14 and 15. `submit` and the pull
  request say which releases no check covered; `--build macports-ci`
  checks on all three, and `build.default = "macports-ci"` makes it the
  default.
- On a new macOS release, before MacPorts' builders have archives of a
  Rust or Go toolchain, the first Tart check of a Rust or Go port there
  builds the toolchain from source, for hours. The check says so first.
  Check such a port on the previous release, `--on tahoe`, or let the
  first check run.
