# dockhand v0.7.0 release notes

The fifth release of dockhand v3, tagged on 47f00138, the commit of
v0.7.0-rc7. The stage ran seven candidates, rc1 to rc7. rc2 freed a
check's Tart slot only once macOS had let its VM go, had a batch say
which checks run together and how long each waits, named in `check
--plan` a target that builds again because its tag moved, and held
submit's preview where a fork refuses this Mac's key. rc3 read a
candidate in an older version scheme, or from a repository that now
answers as another project, as uncertain, and checked a port's patches
in order. rc4 refused a branch rebased onto another master, and kept
master's commits out of a tidy or a submission of a branch moved past
its recorded base, a harm rc2's acceptance found. rc5 and rc6 kept
`clean --delete` to what dockhand made, so a worktree holding work of
its own is kept. rc7, cut on the branch release/v0.7, read, reviewed,
and submitted a pull request within one repository, where rc6 had keyed
an adopted pull request by its number alone.

v0.7.0's acceptance ran on the M1 MacBook Pro used for v0.6.0, as a test
user with a GitHub test account, and ended with no harm open. It
covered:

- on rc1, the quick stage's 49 rows and the full stage's 81;
- on rc2, the full stage, which found the harm rc4 fixed;
- on rc6, the quick and full stages, twelve hours of serve (S1), C1's
  renewal, and a clock change (F10), which found the adoption rc7 fixed;
- on rc7, the upgrade from rc6 under serve (A7), the rows its changes
  touch (A4, B1, D-S1, D-S2, D-S12, E9, F1, G20, G21, G22, D-T1, and
  S2's 24 prepared branches in 115 GitHub requests), and the sitting:
  SSH with a locked Keychain, `port selfupdate` during a check, a German
  locale with the clock five minutes ahead, serve checking in /opt/local
  as root, a check in /opt/local asking for sudo's password again after
  its five minutes, a sleep during a check, and a reboot under serve,
  which resumed its check after login.

/opt/local's active ports were left as they were before the `local` rows
ran. What the stage found that does no harm is listed under Known
issues.

What dockhand does, and what it needs, is in the
[README](../../README.md). To build this release, clone its tag:

```sh
git clone --branch v0.7.0 https://github.com/herbygillot/dockhand.git
cd dockhand
make build
```

## What's new since v0.6.0

- **Tart uses the Mac's VMs.** Tart now takes as many checks at once as
  the Mac runs VMs, 2, where `providers.tart.capacity` let one check at
  a time use it. Each check's VMs still wait for a free one, so a
  `minmax` check running beside another waits for its second VM. A third
  check's wait says "Tart takes as many checks as the Mac runs VMs, 2,
  and check-1 and check-2 are using them".
- **Another's Portfiles, and `review <pr> --check`.** When dockhand
  evaluates on this Mac a Portfile someone else wrote, as an adopted
  pull request's, it says once whose: "Evaluating @alice's Portfiles on
  this Mac, for pr-4711". `review <pr> --check` adopts the pull request
  and checks it in Tart, or wherever `--on` says. The experimental
  notice on `review` and `adopt --pr` is gone.
- **`dockhand decide`.** `dockhand decide <rule> [<port>] --because "…"`
  records your answer to one hold, with your reason; `--waiting "…"`
  records that you're waiting on something, which blocks submit. An
  accepted hold lets an unattended submission go ahead, is listed under
  "Decided", and goes into the pull request as a "Reviewed:" block. The
  decision lapses when the port's own files change. One on a moving
  source, `source-moved`, `tag-moved`, `release-moved`, or
  `assessment-moved`, holds for the two commits it was made on, so a
  later move holds again. status says `assessment-moved` as submit does,
  and drops what a decision answers. Every held row's Next names the
  decide that answers it.
- **What the build installs.** A passed build records the install names
  of its own libraries and the files it installed, and compares them
  with the port's earlier build in that environment, or else with
  master's binary archive. A moved library becomes a notice naming its
  dependents and `update --revbump-dependents`, as "libexiv2.27.dylib is
  libexiv2.28.dylib now"; a file gone or added is a notice too. The
  configure phase's summary is compared the same way, so an optional
  dependency the build stopped finding is said. The check's report lists
  them under "Against the earlier build", and so do status's detail and
  the pull request's description.
- **Patches.** A patch that applies at an offset is re-emitted from the
  applied tree, its header comment kept, and update says "Refreshed
  patch …". A patch that applies only with fuzz holds an unattended run
  (`patch-fuzz`); an attended update re-emits it and names each fuzzed
  hunk for you to look over. A hunk upstream already carries is dropped.
  A patch that doesn't apply (`patch-rejected`) stops an unattended ship
  before its check. patchcheck reads git's quoted file names. A patch
  that only refreshes Cargo.lock is described as a lockfile refresh the
  new release's own lock may make unnecessary, which v0.6.0 described as
  "edits dependency manifests; regenerate manually".
- **After submit.** A merged pull request with commits past the merge
  offers `dockhand start --from <branch>`, which starts a branch from
  master carrying those commits. A pull request that conflicts with
  master is said, "#123 conflicts with master", with Next `dockhand
  rebase`. A failed MacPorts CI job quotes the first error line of its
  log and gives each port's result, as "CI: exiv2 ✓, gpsbabel ✗
  (build)".
- **Notices on a change.** tidy, submit's preview, and review point out
  a line a PortGroup already sets (`restated`), a `port:` dependency the
  tree writes path-style (`path-style`), and a Trac ticket that belongs
  in a `Closes:` trailer (`ticket-trailer`). `update`, `ship`, and
  `bump` take `--closes <ticket>`, written as the `Closes:` trailer. A
  maintainer's instruction in a Portfile's comments is quoted, as "Do
  not update past 3.8.3.". `port lint`'s warnings are reported; for a
  port the branch adds, lint runs with `--nitpick`, and its warnings
  hold submit until they're fixed or taken with `--accept`.
- **Port selectors.** `outdated`, `update`, and `ship` take
  `--maintainer`, `--category`, and `--not-maintainer`, combined as
  MacPorts combines them, beside `--mine`. serve selects with
  `serve.maintainers`, `serve.categories`, and `serve.not_maintainers`,
  and takes your ports when the first two are unset.
- **What an update says.** An update to a lower version raises the
  epoch, saying "Lower version: MacPorts orders 1.6 below 1.7, so the
  epoch is raised by one", and the `version-order` commit rule catches a
  hand edit that doesn't. An update's commit body names the version it
  updates from and links the release's page, or else the compare page,
  at best effort. A stealth update says whether the archive's contents
  changed. Each of these is pointed out: a Go port's `-X` target that
  upstream moved, a C++ standard upstream raised past
  `compiler.cxx_standard`, literal Homebrew library paths the new source
  adds, and a moved repository whose old owner's name now belongs to
  another account. A port's own livecheck that reads a page answering
  404, as tao's reads its GitHub release's download folder, is said to,
  with the note that `port livecheck` finds the same, and that naming
  the version works: `dockhand update tao <version>`.
- **Holds and Next.** A build that links a port its `depends_lib`
  doesn't declare holds an unattended submission (`link-undeclared`).
  Where a passing `host` check covers an update that raised a floor,
  Next names the wider check it calls for, with its port where it names
  a variant. After an amend, what still needs a pass names its platforms
  and their `--on`. Each held line in update, status, and submit ends
  with the rule that raised it, "[build-file-changed]", and one line
  after them says that serve and `ship --yes` wait on them, that your
  own submit goes ahead, that `dockhand decide <rule> -p <port>
  --because "…"` answers one for the branch, and that `holds.allow` lets
  a rule go for every branch.
- **`dockhand rename` and `dockhand move`.** `dockhand rename <port>
  <new>` moves a port's Portfile and files/ to the new name's directory,
  sets the name on its name line, or on one below the setup it comes
  from, keeps its source, and leaves an obsolete stub, replaced_by the
  new name, at its version with its revision raised; it lists the lines
  still naming the old name and the ports depending on it. `dockhand
  move <port> <category>` moves a port to another category, naming it
  first on its categories line. Each is one edit tidy commits, "xgo:
  rename from goplus" or "dockhand: move to macports". check, tidy, and
  submit take a rename as one change: the new port is read against the
  old Portfile, not linted or described as new, and the stub isn't
  built. With an update after the rename, tidy's commit is "xgo: rename
  from goplus, update to 1.7.5". The plan says "xgo (renamed from
  goplus)".
- **A port rename is held as one.** A repository renamed under the same
  owner, where the port is named after it (case and a group prefix set
  aside), or where the project's own name changed with it (its Go
  module, Cargo package, or Python distribution, as goplus's gop became
  xgo), is held as `upstream-renamed-port`, its line leading with
  `dockhand rename <port> <new>`. `--follow-moves`, asked for, still
  follows it and keeps the name; a port's `moves = "follow"` and serve
  never do. Any other rename's line names `dockhand rename` after
  `--follow-moves`. A project's rename is said as `project-renamed`.
- **`dockhand undo check-N` puts a prefix back.** A local check kept
  with `--keep`, or one that stopped before it could put its prefix
  back, is put back by dockhand's own put-back: each port active before
  is active again at its version. v0.6.0 offered `sudo port restore`,
  which brings back the ports requested before and leaves the rest
  inactive, a known issue there. A kept check's record stays until then,
  and the next check in that prefix leaves the put-back to it. Where the
  guest program dies and dockhand lives on, the put-back asks for root
  again on the terminal. A check's directory in /var/tmp is removed once
  its prefix is put back, where a cancelled check used to leave one; a
  directory dockhand can't remove is said.
- **No refusal names a package.** serve's "could not read pull requests:
  forge: authentication is required" now reads "no GitHub login was
  found; dockhand setup github signs in", and the forge's other refusals
  lose their "forge:".
- **serve's sudo rule is one line.** Every root step of a local check
  runs the prefix's `port-tclsh` alone, and that is what sudo is asked
  about, so one line, `<you> ALL=(root) NOPASSWD:
  /opt/local/bin/port-tclsh`, added with `visudo`, lets serve check in
  /opt/local. v0.6.0 needed a rule for `/usr/bin/true` and
  `/usr/bin/env`, which gave root to any command. serve's refusal prints
  the line with your name and the prefix's `port-tclsh`.
- **Submit needs where you named.** When you name where a check builds,
  with `--on` or `--build`, submit needs exactly that: after `check --on
  local` or `ship --on local`, submit passes on the prefix alone, even
  with Tart set up, where it used to ask for Tart's `host` as well. When
  you name neither, it needs `build.default`'s environments, as before.
  The newest check of the files covering every changed port decides, so
  asking again replaces an earlier ask, while a check narrowed with
  `--only` adds its results and sets none. A failure in any check of the
  same files still blocks until it passes or is accepted, as long as its
  environment stands. A branch of serve's own that you checked where you
  named is left to you to submit.
- **Checks.** `check`, or `review --check`, asked while a check of the
  same files is running follows that check, where it used to refuse, if
  the running check covers the one asked for: its environments, targets,
  variants, tests, and freshness. One that doesn't is said, with what it
  doesn't cover, and check offers `--replace`, which stops it, keeps
  what it finished, and runs this one. A check's report and `status -v`
  give each release's and each target's time. A failed build's summary
  quotes the tool's last lines before MacPorts' "Command failed:". A
  queued check that nothing is running says so, and how to run it.
  `dockhand artifacts [branch]` prints the archives the latest check
  built. setup says whether go2port and cargo2port are installed. A
  `local` plan's JSON carries its prefix's note, that MacPorts' binary
  archives are built for /opt/local alone, as its text does. The plan
  states its test policy once, "tests where declared" or "tests
  skipped", where "tests declared" read as the port declaring them, and
  names the targets that declare none. The link notice names the ports a
  target links, "links openssl3 and zlib's libraries, each declared in
  depends_lib", and leaves out the ports of the target's own Portfile.
  `--on tart:12,tart:26` plans as `tart:12,26` does, where it was
  refused, and an item that is neither a provider nor a release names
  the forms `--on` takes. `check --baseline --of check-N` compares with
  an earlier check of the branch's, where the newest was always taken,
  and `--baseline` refuses the flags it doesn't take, `--on`, `--tests`,
  `--variants`, and the capture's, where it ignored them. A failed build
  whose last lines show make rerunning autotools, as `make: ***
  [aclocal.m4] Error 127`, gets a note: the distfile's generated files
  may be stale, often upstream's packaging slip, and `use_autoreconf
  yes` regenerates them where every source is shipped.
- **`create`.** `create go:<module>` takes a module below its
  repository's root, as `create go:golang.org/x/tools/gopls`, and builds
  in the module's directory. A Cargo workspace's programs are read from
  each member. `create --plan` prints the Portfile it would write, and
  writes nothing.
- **A migration refused names who's working.** A database migration
  refused because dockhand processes are working on the older schema, or
  because a release last opened the database, names each process as
  status does: "serve, pid 4711, v0.5.0, since 2026-10-28 10:02, leads
  the queue and runs check-12". A copy of the database counts only the
  processes working on the copy, whose heartbeat moves in it, not those
  on its original. A copy named with DOCKHAND_DB, as the refusal
  advises, migrates without asking even where a release last opened it,
  and says so, naming where its older form is kept; the default database
  still asks.
- **status and clean.** status gathers every branch's facts at once: on
  the test fixture's six branches, 62 git processes became 18. clean
  removes a merged branch whose changes are all on master, and offers
  the fork branches that a closed, archived, or forgotten branch, or a
  canceled check, left behind. Where a `local` check is building in a
  prefix, status names the check holding it, "held by check-12 (pid
  4711)", as a check waiting for the prefix does.
- **`--json` carries what the text says.** A branch's status JSON has a
  "detail" carrying what its text details: your decisions, a Portfile's
  instructions, lint, undeclared links, and what moved. A finished
  check's JSON carries its report's lint, links, and installed files.
  `review --check --json` is the review with its check inside it, under
  "check", where it was the check alone.
- **serve's log and its idle cost.** Everything serve logs is a "serve:"
  line with its stamp. A fetch of master that nobody waits on is no
  longer logged; rc6's acceptance found it 87 times in 16 hours. serve's
  submit pass reads only the branches a check has finished for, where it
  read every open branch every five minutes.
- **The pull request.** Its description fits GitHub's limit of 65,536
  characters, trimming the generated sections and saying so. It lists
  the dependents `--revbump-dependents --except` left out, with the
  reason, even where every one was left out. A one-port branch of
  several commits is titled for the commit that names the version it
  moves the port to, where its first commit used to title it, as "abook:
  fix formatting" did. A branch that moves a port's version ticks
  enhancement whoever wrote its commits, where only an update dockhand
  made did. The tick rests on the branch's change record, so where none
  could be made, as without MacPorts to evaluate the Portfile, nothing
  is ticked. A revbump or a new port ticks nothing.
- **Lint fixes on the lines a change touches.** Where an edit writes a
  Portfile, and in tidy's plan for a hand edit, dockhand fixes on each
  line the change adds or alters what `port lint` would say of it:
  trailing whitespace, leading tabs under MacPorts' modeline, a `\` that
  carries the next line's option into its command, and `maintainers
  openmaintainer` alone, which becomes `nomaintainer`. A version update
  of a port that fetches GitHub's tarball moves it to
  `github.tarball_from archive`, since its checksums are made anew, and
  names `releases` where the release carries its own archive. Each fix
  is said, as "Fixed:" in update's report and "Fixes:" in a plan.
  `check` makes tidy's fixes in the working files before it captures
  them, so the check builds what tidy commits, and a trailing space
  doesn't cost a second build.
- **What a check will install, estimated.** check's plan says, for each
  environment, "about 14 dependencies to install, 3 with no archive on
  packages.macports.org for this release, by the port index; the clone
  decides". The count is the port index's closure of the targets'
  dependencies, less what a local prefix has active, nothing in Tart or
  GitHub, and of those, the ones whose directory on
  packages.macports.org lists no archive of their version for the
  release. `check --plan` waits for the listings, eight at once, kept
  for a day; a check says what's kept, and its run says the rest as it
  starts, never waiting on them. A local prefix whose variants.conf sets
  global variants has its archives left unsaid.
- **A batch's checks run together.** `ship` of several ports runs their
  queued checks together where no serve leads, at most as many at once
  on a provider as its capacity, two on Tart, and finishes each change
  as its check ends, submitting it where ship goes on to submit. Before,
  they ran one at a time in the order given, and a batch took the sum of
  its checks. Where serve leads, each change is finished as serve's
  check of it ends. Each change's `--json` carries its own check and
  submission, where a batch gave every change's to the last.
- **A GitHub check per release.** Each macOS release MacPorts' workflow
  names is its own environment, "github macOS 15 (Sequoia) arm64", with
  its own column, and one run of the workflow builds them all. A job no
  runner took, as GitHub cancelled macOS 26's three times in v0.6.0's
  acceptance, leaves that release unchecked and the others recorded,
  where the whole matrix used to fail as infrastructure. submit names
  it, quoting GitHub's annotation, and says to check that release with
  Tart, `local`, or a command provider, or to try again later. A run
  where no job ran is retried once for every release still without a
  result. Tested on gives one run's releases together, "macOS 15, 26".
  The plan says before the push what the workflow won't build:
  `--also`'s unchanged ports and a baseline's. `--on github:15` is
  refused, since the workflow runs its whole matrix.
- **Another open pull request, said at the start.** `start --port` names
  each port's other open pull requests, "Also open for jq: #34620 jq:
  update to 1.8.0", as `update` does, which now searches beside its
  download rather than after it. Each port is searched once a run, one
  search at a time within GitHub's limit, and bump, ship, and serve read
  the same answers; `submit` searches again before it publishes, since a
  pull request may have opened during the check. A title's leading tag,
  as "[WIP]", is set aside. A failed search says nothing where you work;
  unattended, it still holds.
- **Plain-HTTP links switched to HTTPS.** An update, a checksums
  refresh, and create write `https` for each plain-HTTP `homepage`,
  `master_sites` site, and `livecheck.url` that answers over it, a site
  only where the distfile it serves does, keeping its tags and its place
  in its list, and say so: "Switched to HTTPS, which answers there:" in
  the edit's report, "Switches homepage and master_sites to HTTPS." in
  tidy's commit, and in the pull request's description. A link that
  doesn't answer is said as before, and one the Portfile writes through
  a variable or in quotes is left alone. The asks start beside the
  download, eight at once, each within 5 s, and a URL is asked once a
  run, so the common update waits on none. `[update] keep_http = true`,
  or `--keep-http` on update, bump, ship, create, and checksums, asks
  nothing and changes nothing; serve reads the key.
- **Four more notices.** tidy, submit's preview, and review point out a
  license named by its SPDX identifier where MacPorts names it
  otherwise, BSD for BSD-3-Clause (`license-spdx`); `supported_archs
  noarch` where platforms are darwin (`noarch-platforms`); an added line
  of commented-out Tcl (`commented-code`); and a file added under files/
  that the Portfile doesn't name (`unreferenced-file`). None holds
  anything.
- **`tidy --restyle`.** Restyles each Portfile the branch changes,
  whole, in a last commit of its own, "<port>: whitespace": trailing
  whitespace, tabs, indentation in fours, and each run of declarations'
  values lined up. A Portfile whose ports evaluate differently once
  restyled is left as it was, under "Not restyled:". Nothing else
  restyles a line the change didn't touch.
- **A rebuild's commit follows what it rebuilds for.** tidy commits the
  rebuilds of `--revbump-dependents` after the port they rebuild for,
  whoever changed it. Before, a library you updated by hand came after
  dockhand's rebuilds for it.
- **Several ports of one Portfile.** `update` takes several ports, each
  to its newest release, in one branch: `update kubectl-1.34
  kubectl-1.35 --new` starts one, named for their directory. A version
  still goes with a lone port. `update --mine`, `ship`'s selection, and
  serve put the ports of one Portfile in one branch, where each had a
  branch of its own. tidy makes a commit for each update, in the order
  made, titled for its port, "kubectl-1.35: update to 1.35.10". Where it
  makes one commit for several subports, as after a hand edit between
  them, the subject names each, and your own message for dockhand's
  edits, as `tidy --squash --message` gave it, is kept, where `ship`
  rewrote it.
- **Saved tidy plans.** A plan saved with `tidy --plan --out`, on a
  branch that takes an untracked patch patchfiles names, applies; v0.6.0
  refused it as stale.
- **Removed flags say what replaced them.** A flag an earlier release
  removed answers with its replacement, where it said "unknown flag":
  - `update --submit`: `ship <port>`; `update --check`: `ship <port>
    --to check`; `update --outdated`: `update --maintainer` or
    `--category`, or `ship --mine`.
  - `update --on`, `--note`, `--title`, `--skip-notification`,
    `--tested-binaries`, `--tested-variants`: update edits alone; `ship`
    and `submit` take them (`check --on` too).
  - `submit --check`: `ship -b <branch>`; `submit --on`: `ship --on`;
    `submit --passing`: `ship --passing`.
  - `serve --submit-passing`: `serve --ship-to submit`, or
    `serve.ship_to = "submit"`; `serve --no-submit-passing`: `serve
    --ship-to check`.
  - `logs --all`: `logs --full`; `outdated --all`: `outdated --current`;
    `diff --archive`: `diff --source`.
  - `clean --legacy`: nothing replaced it.
- **Fixed from v0.6.0's known issues:** `status --all` reading each
  branch in turn; an adopted pull request's Portfiles evaluated without
  saying whose; a saved tidy plan refused as stale over an untracked
  patch; a second `local` check of the same revision refused until the
  first's image was uninstalled, which it now uninstalls itself, saying
  so, where that image is inactive and unrequested, as a check leaves
  it; a port with `extract.mkdir yes` whose patches read as not
  applying; a comparison of two license files in memory quadratic in
  their words, now bounded at 16 MB, past which the license is said as
  changed and holds; a self-hosted GitLab whose instance URL has a path
  refused for source archives; and a check started beside the guest
  program a crashed dockhand left building, which now waits for it,
  "waiting for check-12's program (pid 4711), which its dockhand left
  running, to finish in /opt/local".
- **`dockhand usage`.** The guide is in the binary. `dockhand usage`
  prints the one-time setup and the straight path to a pull request, and
  `dockhand usage <topic>` prints a workflow across commands:
  `branches`, `hand-edits`, `checks`, `publishing`, `recovery`,
  `batches`, `unattended`, `new-port`, `review`, `agents`, which says
  what a script or an agent needs, and `configuration`. They are the
  pages docs/usage keeps, which docs/usage.md now indexes.
- **MacPorts base's master.** Its SDK, tool, and compiler lookups, which
  it asks from another interpreter than 2.12 does, are answered for the
  context dockhand models, so a macOS 12 context no longer reads this
  Mac's SDK.

## Upgrading from v0.6.0

- Delete `providers.tart.capacity` from your config. A config that still
  sets it is refused: "providers.tart.capacity is gone: Tart takes as
  many checks as the Mac runs VMs; delete the line".
- serve's sudoers rule for local checks names the prefix's `port-tclsh`.
  Replace a v0.6.0 rule for `/usr/bin/true, /usr/bin/env` with `<you>
  ALL=(root) NOPASSWD: /opt/local/bin/port-tclsh`, which no longer lets
  every command run as root.
- `--build local` and `build.default = "local"` are refused: `local` was
  another name for Tart's `host`, while `--on local` is the MacPorts
  prefix. Use `host` for Tart on this Mac's release, or `--on local`.
- No flag v0.6.0 takes is removed. The flags earlier releases removed
  now say what replaced them, each listed under What's new; `update
  --submit`, for one, answers "update --submit is gone: ship <port>
  updates, checks, and submits it".
- A GitHub check from v0.6.0 stood for every release at once, so it
  covers none now: check again with `--on github`. A build profile with
  provider github that lists releases is refused, as is `--on
  github:15`.
- update, create, and a checksums refresh switch a Portfile's plain-HTTP
  links that answer over HTTPS, beyond the lines the change touches.
  `[update] keep_http = true` leaves them as they are and asks nothing,
  where v0.6.0 asked and said them.
- The database is migrated forward, through schemas 43 to 52, the first
  time v0.7.0 opens it, and a copy of it as it was is kept beside it.
  v0.6.0 can't open it after. Any command migrates it, `status`
  included. To try a newer build without touching your database, point
  DOCKHAND_DB at a copy made with `sqlite3 ~/.dockhand/dockhand.db
  ".backup <file>"`, which a development or rc build migrates without
  asking.
- "Unattended" means serve, and ship or bump with `--yes` or with nobody
  asked. The holds, `--hand-edit`, and the fuzzed patch's re-emission
  read it.
- New holds on unattended runs: `patch-fuzz`, `patch-rejected`, and
  `link-undeclared`. `holds.allow`, or a port's own `allow`, lets each
  go, and `dockhand decide` answers one for a branch.
- New errors among the commit rules: `version-order`, a lower version
  without a raised epoch, and `replaced-by-unchanged`, a `replaced_by`
  with the version, revision, and epoch all standing. `holds.allow` can
  name either.
- A `source-moved` or `tag-moved` concern's `subject` in `--json` is the
  commit checked and the one current, `<checked>..<current>`, where it
  was the current commit alone; a `release-moved` or `assessment-moved`
  concern's is the commit the update prepared or the assessment read and
  the one checked, `<prepared>..<checked>`, where it was the checked
  commit alone.
- `update --json` no longer carries `others_problem`: a failed search
  for other open pull requests says nothing where a person updates.
- `review --check --json` prints the review, with its check under
  "check", where it printed the check alone. A script reading the check
  reads `.check`.

## Known issues

Each harms nothing a look wouldn't catch, and each has a workaround:

- `check` builds on this Mac's release unless told otherwise, and
  MacPorts CI builds on the releases its workflow lists, macOS 15 and 26
  at master today. `submit` and the pull request say which of them no
  check covered; `--build macports-ci` checks on those releases, read
  from the last master fetched, and `build.default = "macports-ci"`
  makes it the default.
- On a new macOS release, before MacPorts' builders have archives of a
  Rust or Go toolchain, the first Tart check of a Rust or Go port there
  builds the toolchain from source, for hours. The check says so first.
  Check such a port on the previous release, `--on tahoe`, or let the
  first check run.
- A `local` check's guest program killed from outside dockhand, as with
  `kill -9`, reads as an infrastructure failure: dockhand puts the
  prefix back, then builds again, twice, each attempt as root and asking
  for sudo's password. Answer the prompt or interrupt the check; nothing
  is left changed. Fixed on main for v0.8.0, where such a kill is said
  and not tried again.
- A check of a port fetched as a GitHub tag's archive can say it "builds
  again: v1.7.1 now names 6bfede5, not 30693df, as when check-929 built
  it; dockhand checksums jlv handles a stealth update" when the earlier
  build was of another version, at another tag, often on another branch,
  and then reuse an older build of the same version. The tag didn't
  move, and the reuse is right; nothing needs doing, and `dockhand
  checksums` would find the checksums as they are. Fixed on main for
  v0.8.0.
- A port that declares a library through a `path:` dependency, as curl's
  `path:lib/libssl.dylib:openssl` does, is said to link openssl3 without
  declaring it, since openssl's file is a link to openssl3's. The check
  says it as a notice, and submit's preview repeats it under "Serve
  would hold it". The dependency is declared; leave the Portfile as it
  is, and answer the hold with `dockhand decide` where serve prepared
  the branch. Fixed on main for v0.8.0.
