## What's new since v0.5.0

- **Checks on this Mac's MacPorts, with `--on local`.** A Mac without
  Tart, or an Intel Mac, can now record a check like any other provider.
  `check --on local` builds in /opt/local, and `--on local:<prefix>` in a
  prefix of your own; several `--on` flags must all pass. The branch
  reaches MacPorts through a macports.conf of the check's own, read
  through `PORTSRC`, so the prefix's etc/macports is never written.
  dockhand takes a `port snapshot` first and puts the active ports back
  after; `--keep` leaves the branch's versions active. A check that
  stopped part way is said by status, as "your MacPorts is as check-3
  left it; sudo port restore --snapshot-id 12 puts it back". serve skips
  `local` unless `[providers.local] serve = true`. An adopted pull
  request is refused there, since its Portfile would run as root. See
  [docs/local-provider.md](../local-provider.md).
- **Holds for one port.** `[holds.ports."<port>"]` overrides `majors` and
  `allow` for that port, and adds `moves = "follow"`, which follows a
  moved repository in unattended runs, and `after = ["harfbuzz-devel"]`,
  which holds the port's unattended submission until the named port is at
  the same version or has a pull request open at it. submit's preview
  says what serve would hold, under `Serve`, and the submission goes
  ahead.
- **`update <port> --hand-edit`.** Where the plan refuses, an attended
  update with `--hand-edit` starts the branch with dockhand's best
  attempt, the version, the checksums it fetched, and the dependency
  blocks it could write, recorded as your hand edit with the refusal's
  reason. status says "By hand", the pull request says it, and serve and
  bump never take it.
- **The baseline in every check's path.** `check.baseline = true` now
  runs the baseline for `check -d`, ship's, and serve's checks too, not
  only a foreground check. A baseline stands across a rebase where
  nothing master's build read has changed, and where something did, the
  offer names it.
- **Less of GitHub's hourly allowance.** Each GitHub read keeps its
  answer and sends it again with its ETag, so a read of something that
  hasn't moved costs nothing: `outdated` over ten ports spent 20 requests,
  and the same look again spent 1. The answers are kept on disk, so the
  next command's look is nearly free too. Signed out, a refresh reads only
  open pull requests, newest first, one request each, and stops about ten
  requests short of the limit, saying how many it left unread. The spend
  line names each request the cache didn't answer.
- **serve doesn't propose a closed update again.** An update whose pull
  request was closed unmerged is left alone at that version, as "jq:
  1.8.1's pull request #123 was closed unmerged, in jq-1.8.1; a newer
  release lifts this". An attended `update` or `bump` goes ahead and says
  the earlier close.
- **MacPorts' modeline.** Every Portfile an update, bump, ship, or serve
  edits gets the modeline `port lint --nitpick` expects, added where line
  1 has none and replaced where it says the same settings another way. A
  modeline with other settings stays. `--keep-modeline` leaves line 1 as
  it was. `tidy` leaves it alone.
- **A check off a terminal says each step.** At the default level, a
  foreground check off a terminal, as under an agent, prints each step as
  it changes, as v0.4.0 did. A target whose log hasn't grown for ten
  minutes is said once, "arowpp's log hasn't grown in 10 minutes
  (destroot)". `check --help` says that `-d` with no serve runs the check
  in the background.
- **Waits say whose.** A wait for Tart's capacity names the check that
  holds it, its process, and how long it has run; a wait for the Mac's
  VMs names the checks running them, or your own VMs. `status -v` names
  each running VM with the Tart home to reach it, as `TART_HOME=~/.dockhand/tart
  tart exec <vm> …`. revbump says what it waits on before it waits.
- **Checks on GitHub.** A fork whose Actions workflow is missing or
  disabled is refused before the push, naming the fork's Actions page,
  where it waited ten minutes; setup's github line says the workflow's
  state. A job GitHub cancelled before any runner took it says so, with
  the run's address, where it reported a 404 on the job's log.
- **An upgrade looks again.** An assessment that couldn't finish records
  the build that made it, and a newer dockhand makes it again, so an
  open branch doesn't keep an old "couldn't compare" hold after an
  upgrade. A complete one stands.
- **Authoring fixes.** `checksums` writes a subport's own declaration
  where it has none, and where the port's unnamed declaration would
  otherwise be read as the subport's. A revision set through one
  variable, as mysql9's `revision ${revision_client}`, resets. A port
  whose git.url points at a fork is compared at the fork's commit. An
  explicit prerelease on a stable port is said, "this takes jq out of
  stable (1.7.1 → 2.0-rc1)". A licensor's rename in a license file is
  said and holds nothing.
- **Smaller fixes.** A baseline of a `--variants` check builds the same
  variants at master. `subject-port` accepts a subject naming a subport
  the branch adds. Off a terminal, and always under serve, git's ssh
  fails at once rather than asking for a passphrase. `-v` prints a plan's
  lists whole. A link scan that couldn't read says why, in one line. A
  grid cell from an earlier check says once that it stands. serve's stop
  says each unfinished run before it waits, and no error its own stop
  caused. The advice to copy the database says `sqlite3 <database>
  ".backup <file>"`.
- **Wording.** dockhand's messages, help, and pull request text were
  reviewed and made plainer, with commands and values unchanged. "Needs
  you" is "Needs attention", and a held ship says "needs review, so
  nothing was submitted", then "After review: <command>".
- **Fixes the candidates found:** status ran `git remote` for each branch
  (rc2); status checked out again a removed worktree of a branch `update
  --hand-edit` started (rc2); submit's preview didn't say serve's holds
  (rc3); serve opened a closed update's pull request again each day under
  `ship_to = "submit"` (rc5); and a Portfile reading `source_date_epoch`,
  as syft's, uv's, and cloudflared's do, refused to evaluate (rc6).
- **Fixed from v0.5.0's known issues:** GitHub's signed-out limit spent by
  one open pull request, `submit` replacing a collaborator's commit after
  a reset, a moved project read as current, a squash's trailer written
  twice, the silent check off a terminal, a rejected login said as GitHub
  unreached, and setup offering a login under a locked Keychain.
- **For developers.** The Portfile corpus, `make test-corpus`, gained the
  other shapes' exemplars and a CI job. A weekly CI job runs the
  evaluator's tests against MacPorts base's master.

## Upgrading from v0.5.0

- The database, `~/.dockhand/dockhand.db`, is migrated forward, from
  schema 39 to 42, the first time v0.6.0 opens it, and a copy of it as it
  was is kept beside it. v0.5.0 can't open it after; its refusal now names
  the build that migrated it and the copy. Any command migrates it,
  `status` included. A development or candidate build asks before it
  migrates a database a release last opened, and refuses without a
  terminal. To try a newer build without touching your database, point
  DOCKHAND_DB at a copy made with `sqlite3 ~/.dockhand/dockhand.db
  ".backup <file>"`.
- The first look after the upgrade makes again each incomplete
  assessment an earlier build made, a few fetches each.
- Updates now write MacPorts' modeline on line 1. Pass `--keep-modeline`
  to update, checksums, revbump, bump, ship, or serve to leave it as it
  was.
- Scripts that read dockhand's words change with them: "Needs you" is
  "Needs attention", and a check's progress says "running here" where it
  said "runs here". `--json` is unchanged.
- GitHub's answers are kept in `dockhand/github` under your user cache
  directory, or where `DOCKHAND_GITHUB_CACHE` points. It is safe to
  delete.
- With no terminal, git's ssh no longer asks for a key's passphrase.
  Under serve or a script, push over ssh with an agent holding the key.

## Known issues

Each harms nothing a look wouldn't catch, and each has a workaround. The
README at the tag lists the first three of them; this list is the whole
of it. Those marked are fixed on main, for
the release after v0.6.0:

<!-- acceptance: pending rc6 on the M1. Add any known issue rc6's stage
finds. -->

- `check` builds on this Mac's release unless told otherwise, and
  MacPorts CI also builds on macOS 14 and 15. `submit` and the pull
  request say which releases no check covered; `--build macports-ci`
  checks on all three, and `build.default = "macports-ci"` makes it the
  default.
- On a new macOS release, before MacPorts' builders have archives of a
  Rust or Go toolchain, the first Tart check of a Rust or Go port there
  builds the toolchain from source, for hours. The check says so first.
  Check such a port on the previous release, `--on tahoe`, or let the
  first check run.
- `status --all` reads each branch in turn, close to a minute with
  several hundred branches, most of them archived (55 s for 683 on rc2).
  Plain `status`, or `status <branch>`, stays quick. Fixed on main:
  status reads each kind of git fact once for every branch.
- D-N6's tokenless read: signed out, a second `outdated` look within the
  hour can spend a GitHub request on something that hasn't moved. In
  rc4's quick stage the second look counted 1 request where none was
  expected; signed in, rc4's full stage counted 8, then 0. Sign in with
  `dockhand setup github`. The spend line names the request.
- Submitting a pull request you adopted evaluates its Portfile on this
  Mac, read-only, without saying so; v0.7.0 says it. The evaluator can't
  write, reach the network, or run programs, and serve submits only the
  branches it prepared. Read an adopted pull request's Portfiles before
  you submit it. Fixed on main: dockhand says whose, "Evaluating
  @alice's Portfiles on this Mac".
- A plan saved with `tidy --plan --out`, on a branch whose patchfiles
  names a patch not yet added to git, is refused as stale when `tidy
  --apply` reads it ("its files were edited"), and a new plan is refused
  the same way. `git add` the patch first, or run tidy without a saved
  plan. Fixed on main.
- Comparing two license files can use memory quadratic in their words,
  51 MB for a 25 KB pair, a large file's license read for an update.
  Fixed on main: the comparison is bounded at 16 MB, past which the
  license is said as changed.
- A self-hosted GitLab whose instance URL has a path, as
  `gitlab.instance https://gitlab.example.com/root`, is refused for
  source archives as "not supported". Fixed on main.
- After a dockhand crash, wait for the check's port-tclsh to finish
  (status shows the prefix as building) before another check on that
  prefix; a check started sooner builds beside it. Fixed on main: the
  next check waits for it.
- A second `local` check of the same revision in a prefix is refused,
  "jlv @1.7.1_1 is installed in /opt/local already", since the first
  left its build inactive for `port reclaim`. Run the `port uninstall`
  the refusal names, then check again. Fixed on main: the check
  uninstalls an inactive, unrequested image of its own version itself.
- A port with `extract.mkdir yes`, whose archive has no top directory,
  has each patch read as not applying (`patch-rejected`), which holds
  serve and `ship --yes`, where a check shows them apply. Submit it
  yourself once its check passes. Fixed on main.
- serve with nothing to run spent about 15% of a core over 16 hours on a
  database of 838 branches, in rc6's acceptance. Stop serve when you
  won't need it for a while. Partly fixed on main: its submit pass reads
  only the branches a check has finished for.

## Not covered by the acceptance stage
