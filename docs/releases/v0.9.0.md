# dockhand v0.9.0 release notes

<!-- acceptance: pending; v0.9.0's candidates follow v0.8.1's tag -->

A release of dockhand's core, in progress on main: what you ask of a
branch, an update's edit, a submission, and a check's end are each
recorded, so a command that stops partway is finished by the next one.
Its notes are added to as each change a person sees lands.

## What's new since v0.8.1

- **A branch keeps what you asked of it.** What `update`, `bump`, and
  `ship` are asked is kept on the branch until the submission that takes
  it has finished. A later ship goes on with the release kept for each
  port, "jq goes on with 1.8.1, the release kept", and looks for no
  newer one; a version you name replaces it and says so. A `--to` given
  is kept, and a later ship without one says "stays at --to check, as
  kept; ship --to submit goes further". A flag given replaces the one
  kept and is said, and a flag left out leaves it. A ship that stops
  before a later stage says the flags kept for it: "Kept for the check:
  --on sequoia, --tests required." `check` and `submit` read what's kept
  where you give them none, "Taken from what the branch's request kept:
  --draft, --type bugfix". `dockhand usage flags`, a new page, lists
  every flag with how long it lasts.
- **A flag that can't be carried out is refused by name.** `--source
  releases` where the release carries no usable source, and
  `--follow-moves` where the update didn't follow the name GitHub
  answers, stop the branch, your own `check` and `submit` included,
  until you give the flag another way. `--keep-http`,
  `--keep-old-checksums`, `--keep-modeline`, and `--shared-release` are
  refused where they change after the version's edit was written.
  `dockhand status` names what was refused.
- **An update that stopped partway is finished, not repeated.** An update
  records its edit before it writes the files. The next command on the
  branch finishes the record where the files were all written, writes
  them where none was, and otherwise stops and names the command: "jq:
  update to 1.8.1 was cut short: textproc/jq/files/fix.diff aren't
  written yet; dockhand update jq finishes it". A file you changed since
  is never overwritten. `status` says a branch whose preparation didn't
  finish, and `dockhand ship -b <branch>` finishes it, each port at the
  release chosen for it. serve takes up its own unfinished preparations
  at each day's look, never yours, and nothing unattended commits,
  checks, or submits past one.
- **A port already at its newest version takes what you ask beside the
  version.** `update --source releases` or `--source archive` moves the
  source at the version the port is at, writing the new checksums and
  leaving the version and revision alone (#121). `--with-obsolete` moves
  its obsolete stub, `--follow-moves` follows a moved repository, and
  `--revbump-dependents` bumps what links it, each said as done, or as
  already so. `--closes` with nothing else to change is refused.
- **A submission records what it owes, and the next submit settles it.**
  Before its first push, submit records the commit, the fork's branch,
  the title and description it writes, and each step it still owes. If
  it ends partway, `status` shows the submission as unfinished with what
  is owed, and `dockhand submit` reads the fork and GitHub first, so a
  push that landed or a pull request GitHub opened is found and nothing
  is done twice. `--ready`, your answer about the reviewers, `--draft`,
  `--no-check`, `--type`, and `--skip-notification` carry to that
  submit, and its plan says so. A second submit of the same fork branch
  while one runs is refused, naming the process. `submit --json` and
  `ship --json` list what is still owed under `pending`, each with its
  reason.
- **Reviewers are asked about before the push.** Where a reviewer
  requested changes, submit asks whether to request their review again
  with the plan, and makes the request as its last step, after marking
  the pull request ready. A no is kept. Each reviewer is asked on their
  own, a request that may have been sent is never sent again, and
  `status` says who was asked. Just before it edits the title or
  description, marks ready, or asks a reviewer, submit reads the pull
  request again and leaves alone what changed on GitHub meanwhile.
- **A waiting reviewer is read rightly.** `status` says "#36300
  @reneeotten commented; awaiting your response" for a comment that is
  the conversation's latest human word. A bot's comment no longer hides
  it, your own later comment or a push dockhand recorded clears it, and
  an adopted pull request no longer names your own comment (#248).
- **dockhand asks before it evaluates someone else's Portfiles.**
  `review` of another person's pull request lists the Portfiles and
  PortGroups it changes and asks "Evaluate them", where `d` shows the
  diff first and no, the default, gives a text-only review that says
  what it left out. A yes is kept for the pull request and the author's
  commit, so a new push asks again. `check`, `tidy`, `submit`, and the
  authoring commands ask the same on an adopted branch. In a script,
  `review --evaluate` or `dockhand adopt --pr 35174 --evaluate` answers;
  `--yes` never does, and serve and a queued check evaluate only what
  you allowed (#162). Control characters in an author's files, paths,
  and titles are shown as visible marks, such as `<U+202E>`.
- **A cancel is finished only when the work is seen to end.** A cancel
  stops and deletes a Tart check's clone, cancels every run of a GitHub
  check, and stops a `local` build or a script's shell with its whole
  process group, then puts a local prefix back, also for a check whose
  dockhand was killed. Until each has ended, `status` shows the check as
  `canceling` and names `dockhand cancel check-N` as the next step;
  serve looks again as it passes. A root `local` build is stopped this
  way once this Mac's sudo has passed a probe, run at your account's
  first root build; until then the cancel names the command to stop it
  by hand. `dockhand usage checks` says what the probe needs. Closing
  the terminal or losing the SSH session stops a foreground check as
  Ctrl-C does.
- **A dead check's VM no longer holds a slot.** A check waiting for one
  of the Mac's two VMs removes a clone that a check of this checkout
  left running when its dockhand was killed, and says so. A VM kept for
  `dockhand shell`, and your own VMs, are left.
- **A GitHub check has a branch of its own.** `--on github` pushes
  `dockhand-check/<commit>-<check ID>`, so two checks of one commit
  never share a run and a cancel stops only its own. The branch is
  removed when the check's attempts end, and `dockhand clean` and the
  daily cleanup remove one that was left. Runs in flight share one
  listing each poll, and `[providers.github] capacity` now defaults to
  20.
- **A result that no longer counts says why.** Where a tag moved, a Git
  source couldn't be read, or a dependency's source moved, `status`
  shows the port as not run and submit holds, in the same words: "built
  by check-1 from v4 at 1a2b3c4, which now names 5d6e7f8, so it doesn't
  count; dockhand check builds it again". Where the latest check passed
  for an earlier version of the files, status's detail labels its
  results with the check and lists ports it didn't build as "not
  checked by check-<n>". An environment whose identity can't be read, as
  when Tart doesn't answer, holds serve and `ship --yes` as
  `identity-unread`, and your own submit says it and goes on.
- **Checks.**
  - A reused result lints again after a comment, a blank line, or a
    declared dependency the build already had, so `status` shows the
    Portfile's own lint lines (#258).
  - A check asked for an environment the running check doesn't build is
    refused as an environment difference, where it said an upstream tag
    may have moved (#259).
  - The plan lists the subports a change alters on `Changed` and the
    untouched subports of the same Portfile, built too, on `Siblings`.
  - A dependent uses the default build of a prerequisite the check
    makes, or its only configured build; where two remain, planning
    refuses and names both. Changing a prerequisite's variants rebuilds
    what consumes it.
  - `logs jq --phase install` takes a lone port for the branch's latest
    check. `artifacts` and `shell` given an attempt name the check to
    run them on.
- **Kept clones are listed, bounded, and yours to remove.** A failed
  Tart check keeps its clone only when a person ran it; a check serve or
  `--yes` started keeps none. Failure clones expire after seven days and
  the four newest in each Tart home are kept. A clone `--keep` asked for
  has no age limit and survives later checks of the branch. `dockhand
  clean --kept check-12`, or `--kept` with `-b`, `-p`, or `--pr`,
  removes clones and leaves the branch alone. A check's final notice and
  `status` name each kept clone with its size, and `--json` gives them
  under `kept_clones`.
- **`submit --no-check` says more, and is refused where the build can't
  pass.** A hold whose rule says the build fails, `patch-rejected` or
  `cargo-lock-stale`, refuses a `--no-check` submission until you decide
  the hold or `holds.allow` names its rule. The description names the
  releases MacPorts CI builds on and that nothing covers any other.
  Where a check passed on an earlier commit, it names that check, its
  commit, and the files changed since, as history, never as a result.
- **Cargo ports.** Where the new source ships no `Cargo.lock` and
  `cargo.update` is off, an update writes the version, checksums, and
  patches, leaves `cargo.crates` as it was, and holds as
  `crates-unlocked` whether or not a check passes, where it refused.
  An update also holds as `cargo-lock-stale` where a local package's
  locked version differs from its `Cargo.toml`.
- **`dockhand backup`.** `dockhand backup <file>` makes a consistent
  copy of the database while serve or a check writes to it, and never
  replaces an existing file; given a directory, the copy is named by the
  minute it was made. It reads the database without migrating it. The
  copy is the database alone, without kept archives and check logs.
  Where dockhand refuses a database as damaged, it names the newest copy
  a migration kept, and `dockhand usage recovery` says how to put one
  back. A migration is refused where the copy it keeps isn't usable.
- **Writes to GitHub are bound to the account and to what is yours.** A
  write goes out only under the account its preview was made for; where
  the login changed in between, nothing is written and the command asks
  to be run again. Every remote write passes one ownership rule, and a
  refusal names the operation: "dockhand doesn't push a branch in
  macports/macports-ports: this operation is never allowed in the
  upstream repository, regardless of ownership".
- **serve.** serve counts the pull requests it opens each day in rows
  that outlive their branches, and a create that got no answer keeps its
  place until its pull request is found. Each pass first accounts for
  serve's own unfinished submissions; it never finishes yours, and never
  writes to a pull request it found rather than opened. serve reads its
  settings at each new action. `ship --yes` and `bump` are held before
  their check for a patch that no longer applies, as serve is.
- **Plans and selectors.** `adopt --plan` shows what adoption would
  track, and `undo --plan` what an undo would restore; neither changes
  anything. `clean`, `edit`, and `undo` take `-b`, `-p`, and `--pr`. A
  repeated `-b` is refused. `clean --delete` can forget an open branch
  with no pull request whose changes master already has. `rebase`
  accepts `--yes`, and `-V` is `--version`.
- **What update and ship say.**
  - A version may be written as upstream's tag spells it or in the
    port's form: for a Portfile that turns the tag `2026-11-23` into
    `20261123`, either selects that release.
  - Before it commits, ship lists what its updates found, first what
    holds the change, then what only informs.
  - `ship tree-sitter tree-sitter-cli`, a port and a subport that shares
    its release, updates the port and moves the subport with it.
  - `--follow-moves` writes a moved repository's name into a `go.setup`
    module path too.
  - `update --hand-edit` names the branch it wrote to and what it didn't
    refresh.
  - Where a reading of another macOS release depends on that Mac,
    `update` leaves that release's checksums as they were, names it, and
    goes on with the releases it could read, where it stopped.
- **Output dockhand didn't write is printed as it is.** A failed step's
  log lines, a commit's body and trailers, and what Tart, a guest, or a
  clone's command prints are no longer wrapped at the terminal's width.

## Upgrading from v0.8.1

- Back up first. Once v0.9.0 is installed and before any other command,
  run `dockhand backup <file>`: it reads the database without migrating
  it, and v0.8.1 has no such command. The database is migrated forward,
  through schemas 60 to 66, the first time v0.9.0 opens it, a copy of it
  as it was is kept beside it as `dockhand.db.schema-59`, and v0.8.1
  can't open it after.
- Stop every older dockhand first: quit `dockhand serve`, or `dockhand
  serve --uninstall` and `--install` after, and let any check, submit,
  or ship end. The migration refuses while another dockhand runs on the
  Mac, naming each process to stop and saying "Nothing was migrated". It
  is also refused where the Mac's process list can't be read, as inside
  a sandbox.
- Tart 2.41.1 is now the oldest Tart dockhand takes. An older one is
  refused, at setup and before a check starts a VM, with how to upgrade
  it.
- On the day of the upgrade serve opens no pull request, since that
  day's earlier openings were counted another way.
- The first check after upgrading builds again, once, the ports that
  depend on another port built in the same check.
- A failed check that serve or `--yes` started no longer keeps its clone
  for `dockhand shell`; run the check yourself, or with `--keep`, to
  have one. A `--keep` clone now stays until you remove it with
  `dockhand clean --kept`.
- `[providers.github] capacity` guards dockhand's use of your hourly API
  budget and isn't a concurrency limit; its default went from 2 to 20.
- A development or rc build asks before it migrates the default
  database, whoever last opened it, and refuses without a terminal;
  `--migrate-database` allows it for one run. `--yes` isn't an answer to
  this.
- New fields in `--json`: `pull_request.pending` from submit and ship;
  `plan` from `ship --plan` and `bump --plan`; a check's `kept_clones`
  and `identities_unread`, and its plan's `unattended` and
  `replaces_kept`; status's `kept_clones` and a canceling run's
  `cancel_requested`; review's `evaluated`, `left_out`, and `carried`;
  and `hold`, `accepted`, and `allowed` on a submission plan's upstream
  changes.

## Known issues

- While a check is running, a check of the same files on another system
  or provider is still refused; wait for it, or use `--replace`.
- `--keep-http`, `--keep-old-checksums`, `--keep-modeline`, or
  `--shared-release` changed after a version's edit was written is
  refused even where the Portfile is already as the flag asks. Give the
  flag as it was, or edit the Portfile yourself.
- A root `local` build's cancel stays unfinished on a Mac whose sudo
  hasn't passed dockhand's probe, or asks for a password at that moment;
  the cancel names the `sudo kill` command to run by hand.
- After a `local` check puts a prefix back, the newer versions it
  installed of ports you had active stay installed and inactive, and
  `port upgrade outdated` passes those ports over, though `port outdated`
  lists them. The check names each with the command that activates it,
  and `port reclaim` removes them.
- A `dockhand-check/` branch a check pushed to a fork or account you
  have since changed is never listed, so remove it on GitHub yourself.
- `impact`'s builders' row reads ports.macports.org's newest fifty builds
  of a port, so a builder that hasn't built it among them isn't named.
- Where GitHub refuses or throttles the reads of moved repositories,
  they pause for an hour: the rest of that look says no moves, and a
  later look reads them.
- As in v0.8.0, on a new macOS release, before MacPorts' builders have
  archives of a Rust or Go toolchain, the first Tart check of a Rust or
  Go port there builds the toolchain from source. The check
  says so first. Check such a port on the previous release, `--on
  tahoe`, or let the first check run.
