# dockhand v0.8.1 release notes

<!-- acceptance: pending; v0.8.1-rc1 runs the quick stage and the rows for the five fixes (plan/v081-read-and-acceptance-2026-11-21.md) -->

Five fixes on v0.8.0 for bugs that could cause harm. Nothing else changes
what a command does, and the database is the same as v0.8.0's.

## Fixes

- **An empty `--note` is refused.** On `submit`, `ship` and `bump`, an
  empty `--note`, or one of only spaces, removed the note already in the
  pull request's description without a word, which is what a shell
  substitution of a missing file passes. It's now refused, and the new
  `--no-note` removes a note. The two together are refused (#272).
- **A branch rebased with Git doesn't claim master's ports.** What a branch
  changes was read from its recorded base, so a branch you rebased onto a
  newer master yourself counted every port master changed since as its
  own: `outdated` said they were in it, `ship` could edit one into its
  worktree, and `dockhand rebase` replayed master's commits and stopped on
  a conflict. A branch's own commits now leave out what master already
  has, `rebase` replays only those and records the new base, and reading
  never moves the base (#280).
- **An update's held finding stays with the branch.** A finding that
  `update` holds for you to look at (`manifest-hook`, `mirror-conflict`,
  and an unfollowed `upstream-moved`, `upstream-renamed-port` or
  `upstream-transferred`) was dropped by one more commit or a rebase, and
  then `serve` or `ship --yes` could submit without it. It now stays while
  the branch still changes the port, through `archive --undo` too, until a
  later update of the port replaces it (#242).
- **`--accept` takes the build it names.** Where a port is checked under
  more than one set of variants, `submit --accept <port>` could accept one
  variant's failure as another's. A build's full name accepts that build,
  a bare port name takes the one failed build, or else the one with lint
  warnings, the submission records the builds it took, and lint on a
  variant build is accepted by that build's name (#235).
- **archive names a pull request only where there is one.** Its last line
  said the pull request remained for a branch that never had one.
  `abandon`, the verb older builds had, isn't a command; typing it now
  suggests `archive` (#279).

## Known issues

v0.8.0's known issues stand, except those fixed above: #272, #280, #242
and #235.
