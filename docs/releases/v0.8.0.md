# dockhand v0.8.0 release notes

<!-- acceptance: pending; v0.8.0's candidates follow v0.7.0's tag -->

The sixth release of dockhand v3, in progress on main. Its notes are
added to as each change a person sees lands.

## What's new since v0.7.0

- **`dockhand console`.** A live table of your branches, the terminal's
  size, kept current as serve works: what needs you first, then what's
  under way, then what waits on reviewers, each row its branch, ports,
  state, pull request, and the command that moves it on, with the
  journal's newest events in a pane under it. ↑ and ↓ select a row,
  PgUp, PgDn, Home, and End page, Enter shows the branch's detail in the
  pane, and `l`, `c`, `t`, and `s` run logs, check, tidy, and submit on
  the selected branch, returning to the table after. `--plain`, or no
  terminal, prints status once and then each event as a line, for
  scrollback, SSH, and screen readers. It replaces `status --watch`.
- **Merge fitness.** For a pull request's ports, status's detail and the
  console's pane say their maintainers, who the description mentions,
  who approved, and when MacPorts' 72-hour maintainer timeout passes,
  counted from the pull request's opening, as the Guide's 7.4.1 has it:
  "MacPorts' 72-hour maintainer timeout ends Mon 2 Nov 09:00 EST, in
  41h; until then only its maintainers or its author should merge it". A
  port waits unless it's nomaintainer, one of its maintainers opened the
  pull request, or one of them approved it; openmaintainer doesn't
  shorten the wait. The row's PR column says "maintainer timeout ends in
  41h" or "passed", and a draft says "draft" in its place. The
  maintainers are MacPorts' current ones, read from master's port index
  as dockhand already has it cached, so an existing or adopted pull
  request shows them at once; a new port's are read by `check --plan`.
  Of that and the branch's change record, the newer reading of master
  wins, and a port read from the record says so, "maintainers as of
  master, 2026-10-28". Who MacPorts' bot notified isn't read, so the mentions are the
  description's alone. No request is added.
- **MacPorts' builders' history.** `impact` says, for each changed port,
  where MacPorts' builders built or failed it, by each builder's latest
  build on ports.macports.org: "bazel: failed on macOS 10.13 and 10.14
  x86_64 at its dependencies; failed on macOS 14 arm64; built on the
  other 2". A failed check's offer of a baseline says where the builders
  failed the same release too, "MacPorts' builders failed exiv2 on macOS
  15 arm64 too", which can save the baseline's build. Each port is read
  once a day; the site not answering says nothing and fails nothing.
- **A moved repository, said for a current port.** A GitHub repository
  renamed or transferred is found by github.com's own redirect, each
  repository asked at most once a week, beside the look and never
  holding it up: "GitHub answers extrawurst/gitui as gitui-org/gitui
  now, which github.setup could name", with "if that's the same project"
  where the name changed, not only the owner. `outdated --current` says
  it on the port's row, `outdated <port>` on its one line.
- **PortGroup changes made visible.** Where a branch or master changes a
  PortGroup in `_resources`, the change record says which PortGroup
  files changed and the ports each moved, listed first in status. Each
  evaluation records the PortGroups it read, by version and content.
  dockhand checks, once a port is evaluated, the PortGroup options and
  procedures it relies on, so a PortGroup that drops one makes what
  reads it inconclusive, not wrong, and a PortGroup version it wasn't
  checked against is said once. A weekly job replays dockhand's
  evaluation corpus against macports-ports master's `_resources`, so a
  PortGroup change upstream that moves dockhand's answers is found
  there.
- **A check lasts across PortGroup changes it didn't read.** A check's
  result, and a passing check's reuse, is keyed by the PortGroups
  MacPorts opened each port with, where it was keyed by the whole of
  `_resources`: a change to a PortGroup the port didn't load leaves it
  standing, and a change to one it did voids it, the baseline saying
  which, "the cmake 1.1 PortGroup, which gettext, built from source,
  loaded". A dependency the check built from source counts its own
  PortGroups; one installed from an archive doesn't. A kept dependency
  archive is offered only while the PortGroups its build loaded stand,
  and a check says once when it isn't.
- **What outdated and update say.**
  - An obsolete stub, `replaced_by` another port, isn't looked up: it's
    under Not checked as "replaced_by py-ansible", and `update` of it
    names the port that replaced it, where ansible's stub was listed as
    a held major update to py-ansible's version.
  - A version a livecheck captured from a prerelease's name, as 1.4.2
    from 1.4.2pre1, is a prerelease, which a port on a stable release
    passes over. A look whose only match is a prerelease reads the port
    current and says so: "upstream's newest, 3.2.17RC1, is a prerelease,
    which a port on a stable release doesn't take".
  - A newer tag under another prefix is said: "upstream's newest tag,
    v0.12, doesn't match github.setup's tag prefix". What's offered still
    follows the port's own prefix.
  - Update says a `worksrcdir` the new source lacks before its patches'
    failures, "! worksrcdir sdk/angelscript/projects/gnuc macosx isn't in
    2.38.0's source", where it said only "No file to patch".
  - `outdated "airspy airspyhf"` is refused once, as several names in
    one argument, where it looked them up as one port and said so three
    times.
  - The php PortGroup's PECL ports are checked: 72 of the 73 that
    outdated left unchecked.
- **A renamed port is compared with its predecessor.** A port renamed by
  hand with its stub left behind, as jq to jq2, is compared with jq and
  its upstream, where it read as a new port; a subport renamed in its own
  directory is one changed subport, tidied "zsolo2: rename from zsolo,
  update to 1.1".
- **Several ports updated to one version are titled for it.** A branch
  whose commits each update one port to the same version is titled "ace,
  tao: update to 8.0.8", where submit asked for `--title`.
- **An update says when a GitHub port's release carries its source, and
  moves it there when asked.** By default an update leaves a port's
  source as it is, a port on GitHub's tarball still moving to GitHub's
  archive of the tag as before, and where the release carries its own
  source archive it says so, a notice that holds nothing: "release
  2.5.0's mindforger_2.5.0_tarball.tgz carries the source, doc, and
  deps/cmark-gfm; update --source releases fetches it". The source is
  known by what the archive holds, the repository's build files at the
  tag, the paths the Portfile names, and, for a port fetched with Git,
  its submodules, never by its name. `--source releases` makes the move,
  refusing where the archive doesn't qualify, and `--source choose`, or
  `[update] source = "choose"`, takes it where it qualifies, as
  mindforger's 2.5.0 did: the update writes `distname`,
  `extract.suffix`, a `use_` option, and `worksrcdir` where the archive
  needs them, drops `fetch.type git` and the submodule hook, fills the
  checksums, and says the move; the commit's body and the pull request
  say it too, and no Portfile comment is written. Where a source could
  have moved and didn't, the update says why. `--source keep` moves
  nothing, `--source archive` asks for GitHub's archive, and `[update]
  source` sets any of these for every update. `checksums` writes a main
  port's missing checksums, as it did a subport's.
- **Checks.** `logs` says when a check was queued, how long it waited for
  its slot, and when it finished, and status's queue says each started
  check's wait. A batch's checks, serve's, and a foreground check's count
  against one capacity, where each counted only its own, and a batch's
  wait names the checks holding the slots. Tests ended at their bound
  say so, "the tests ran past their 30m bound
  (providers.tart.test_timeout), so they were ended", where the detail
  read only "Aborted: SIGTERM received", and a `local` check's bound
  names providers.local's key. Kept archives missing, as from a database
  copy without its archives, are said once, with their count, where each
  was a line.
- **Throwing a branch away is said.** clean's refusal of an open branch,
  archive's last line, and a clean that removes nothing while archived
  branches keep their Git branches each say that `dockhand clean
  --delete <branch>` forgets it for good.
- **A faster look.** `outdated` reads the open branches once, not once a
  port, and shares one MacPorts session a port where it started three;
  a GitHub repository's tags come from `git ls-remote`, outside the
  API's limits. On 1,115 ports a warm look went from 4m49s to about two
  minutes, and a cold one from 8m36s to 120 s, with the same answers.
- **serve says a problem once.** Each of serve's workers says a problem
  the first time it finds it and again only after it has cleared, where
  a failed submission or the day's limit was said every refresh, and the
  day's look runs beside serve's loop, so a check ending during it isn't
  kept waiting.
- **Two databases on one checkout.** A `DOCKHAND_DB` copy run on its
  original's checkout no longer takes the original's tidy checkpoint
  names, which failed with "reference already exists".
- **Building on another Mac over SSH.** docs/command-provider.md gives a
  script for `[providers.command]` that builds a check's targets on a
  Mac reached over SSH, and says what it can't do; a test runs the
  example, so it can't drift.

- **Name the programs dockhand runs.** `--tool name=path`, a variable,
  or the configuration's `[tools]` table points dockhand at a particular
  git, port-tclsh, tart, go2port, cargo2port, xcodes, gh, patch, or diff,
  ahead of the usual search on `PATH`. The variables are `GIT_BIN`,
  `PORT_TCLSH_BIN`, `TART_BIN`, `GO2PORT_BIN`, `CARGO2PORT_BIN`,
  `XCODES_BIN`, `GH_BIN`, `PATCH_BIN`, and `DIFF_BIN`. A program named
  that isn't there stops the command before it runs anything. `setup`
  and `dockhand config` show what named each one. See
  `dockhand usage configuration`.
- **Code is written as it is on a terminal.** Shell completion scripts,
  `create --plan`'s Portfile, the diffs `update --plan`, `bump`'s plan,
  `revbump --plan`, and tidy's review show, and submit's preview and
  description are no longer wrapped at the terminal's width, which broke
  a Portfile's modeline and long lines, and sourced fish and bash
  completions (#88, #93).

## Upgrading from v0.7.0

- An ordinary check now builds each port's oldest and newest macOS among
  the Tart images you've set up (`minmax`), not this Mac's release alone
  (`host`). With only this Mac's image, as setup makes by default, nothing
  changes. With more images, a branch whose last plain check built `host`
  needs a check on minmax's releases before `submit`. Use `dockhand check
  --build host` for a one-shot check of this Mac's macOS alone, or set
  `build.default = "host"` to keep the old default.
- `--git` is gone; use `--tool git=<path>`. A serve agent installed with
  `--git` rewrites itself once to use `--tool` the first time it starts,
  and launchd restarts it; nothing needs doing. Run `dockhand serve
  --install` again after you change what `[tools]`, a variable, or
  `--tool` names, since the agent records each program's path when it's
  installed.
- Setup no longer copies the images a dockhand before v0.3.0 made in
  Tart's own home, `~/.tart`. If you ran one, list what's left with
  `TART_HOME=~/.tart tart list` and remove those images, stopped, with
  `TART_HOME=~/.tart tart delete <name>`, only for names that begin
  `dockhand-base-`, `dockhand-xcode-`, `dockhand-golden-`, or
  `dockhand2-`. Such a dockhand also left lock files, named
  `image-` or `setup-` and a digest, ending `.lock`, in
  `~/.tart/dockhand/locks`, which no dockhand reads now and which can go
  too. `~/.tart` is where Tart keeps everyone's VMs: never remove it,
  `~/.tart/vms`, or `~/.tart/dockhand`, while anything else is in it.
- `dockhand status --watch` is now `dockhand console`, a table of the
  branches the terminal's size with keys for logs, check, tidy, and
  submit on the row selected; `status --watch --plain` is `dockhand
  console --plain`. `status --watch` and `status --plain` are refused,
  naming the console.
- `dockhand logs <check> -p <port>` is refused now, naming `dockhand
  logs <check> <port>`, which shows the same log: `-p` chooses a branch,
  as it does in every other command.
- The database is migrated forward, through schemas 53 to 59, the
  first time v0.8.0 opens it, and a copy of it as it was is kept beside it.
  v0.7.0 can't open it after. A development or rc build asks before it
  migrates a database a release last opened; a copy named with
  DOCKHAND_DB migrates without asking. Checks recorded before say
  nothing of how long they waited for their slot, and archives kept
  before carry no PortGroups and are offered as before.
- The comparison's `github-tarball` notice is now the `source` rule, which
  also says why a GitHub port's source didn't move; a `holds.allow` naming
  `github-tarball` is refused, naming the rules, and takes `source`.
- Each branch's change record is made once more, the next time a command
  needs it, since v0.8.0 records what a rename, a PortGroup change, and
  a port's maintainers change; making it evaluates the branch's changed
  ports again.
- A check's result recorded by v0.7.0 stays keyed by the whole of
  `_resources`, so any PortGroup change still voids it; checks v0.8.0
  makes in Tart or `local` are keyed by the PortGroups they read.
- New fields in `--json`, none removed or renamed: status's
  `pull_request.merge`, with the maintainers and their
  `maintainers_basis` and `maintainers_as_of`, `mentioned`,
  `approved_by`, `draft`, and the timeout, and `detail.merge`; a
  run's `started_at` and `waited_seconds`; outdated's `repository_move`,
  `other_prefix`, and `prerelease`; update's `missing_worksrcdir`; and
  impact's `builders`.

## Known issues

<!-- acceptance: pending. Add any known issue the stage finds, and mark
those fixed on main. -->

- `impact`'s builders' row reads ports.macports.org's newest fifty builds
  of a port, so a builder that hasn't built it among them isn't named.
- Where GitHub refuses or throttles the reads of moved repositories,
  they pause for an hour: the rest of that look says no moves, and a
  later look reads them.
- MacPorts CI builds on the releases its workflow lists, macOS 15 and 26
  at master today. `submit` and the pull request say
  which of them no check covered; `--build macports-ci` checks on those
  releases, read from the last master fetched, and
  `build.default = "macports-ci"` makes it the default.
- As in v0.7.0, on a new macOS release, before MacPorts' builders have
  archives of a Rust or Go toolchain, the first Tart check of a Rust or
  Go port there builds the toolchain from source, for hours. The check
  says so first. Check such a port on the previous release, `--on
  tahoe`, or let the first check run.
