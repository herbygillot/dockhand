## Where v3 stands

The whole loop is built and has been used for real work:

- **Branches:** `setup`, `start`, `adopt`, `adopt --pr`, and `path`.
- **Authoring:** `update` with `--outdated` and `--revbump-dependents`, `checksums` with stealth updates, `revbump`, `create` for GitHub projects, and `edit`.
- **Checks:** `check` on Tart, on your fork's GitHub Actions, or on your own script. Tart covers macOS 12 through 27, each with an Xcode add-on. There are also `logs`, `retry`, `--baseline`, `queue`, `wait`, and `cancel`.
- **Shaping and submitting:** `tidy` and `undo`, `submit` with `--check` and `--passing`, and `review`.
- **Following:** `status`, `watch`, and `serve` with its daily look at your ports, and `clean` and `archive`.

Five one-port updates were submitted with it and merged on 2026-09-26 ([note](activity/2026-09-26-real-update.md)), and a two-port branch was checked on two releases. Golden Gate images, base and Xcode, were made and checked on 2026-09-27 ([note](activity/2026-09-27-golden-gate-images.md)).

The weak point the review found is the information passed between steps. Several places reduce a richer fact to a name, a flag, or one verdict, and later code guesses at the rest. Some of those reductions already give wrong answers. That is where Next begins.

## Directions

What dockhand could grow into, and what to redesign. [Directions](directions.md) (2026-10-01, from the runs' findings), [Codex's directions](codex-directions.md), the [command UX review](reviews/2026-10-02-command-ux.md), and the maintainer review survey are merged into one order in the [direction synthesis](direction-synthesis.md), which the person accepted on 2026-10-02:

- **Three layers, built bottom-up:** what dockhand knows of a branch (a coverage ledger, each finding's kind and what it holds, a record of the person's decision on a finding, readiness evaluated for a requested action, and a `Next:` that advances it), then the command surface (the UX review), then new reach.
- **The verdict comes before the UX review's chaining (§3).** Branch naming (§1, §2) can go alongside it. Editing the declaration that ran is layer 1's too, and independent.
- **Maintenance reasoning lives in the pull request and in patch headers or Portfile comments,** never only in dockhand's database.
- **A trust rule for other people's Portfiles comes before the maintainer inbox** (the blind-spots review; decided 2026-10-02). Nothing unattended evaluates a Portfile the person didn't author on the host: it goes to a guest, or the step is skipped and reported. An attended command may, and says whose Portfile it is evaluating. `trust.others = "guest"` sends attended evaluation to a guest too. The inbox's first version lists pull requests without planning or building them.
- **Running what a port installs stays under Later until layer 1 lands.** Comparing what an update's libraries declare, which runs nothing, is its first half.

Each step still becomes Next's work at the person's word.

## Maintenance

- **MacPorts compatibility.** Evaluator tests pass on Base 2.12.6, and CI runs them against the package of whichever release MacPorts currently points its users at. Version adapters follow the [Base design](macports-base-design-prospective.md): the current release plus a pinned master preview. Keep Base and PortGroup compatibility distinct ([evidence](macports-compatibility.md)).
- **Images.** Twelve images are made and checked: base and Xcode for macOS 12, 13, 14, 15, 26, and 27. Re-probe the facts table when an image is rebuilt; the 2026-09-27 probes found every earlier row unchanged. Golden Gate needs Tart 2.39.0 or newer.
- **Package boundaries.** Extend import checks when touching a boundary that matters; the command boundary test, and item 4's engine boundary test, are the models. Don't split packages by size alone. CI runs `make deadcode`, which fails on a function nothing reaches, tests included. Keep test-only exports documented as such. After a milestone, a sweep runs the tool without `-test`: what it lists, only tests reach, and each is test support, documented as such, or dead. The tool can't see an unused exported method on a type that reaches an interface or reflection, so a sweep checks those by references too.
- **Relocations.** A batch that moves a rule to its owner lists, in its note, the call sites it switched to the owner's rule, and closes with a grep across internal/ for the old rule's shape, its predicate, sentence, or switch, deleting what it finds or saying why it stays. Each of the 5897a82 review's high findings would have been caught by that grep on the day (its section 5).
- **Dependencies.** Minor releases go on main when they build and the gate passes, as 3706d086's did; a major version is measured first, by building main against it, and placed here like any fix (the person's "Let's go with you recommendation.", 2026-10-24 18:31Z). The library survey's preference for no new dependencies stands.
- **GitHub's budget.** Requests to its API are paced at 750 a minute, under its documented 900. A whole `outdated --mine` spends about 1,800 of the 5,000 an hour the person's account has, a budget shared with the GitHub CLI.
- **Test throughput.** The cost unit is the MacPorts interpreter. Keep per-test timing visible, and prefer simulated clocks for time-driven tests; v2's `workflow` tests show what wall-clock budgets do under load.
- **The test launcher.** The Makefile still shards the command package's tests as unable to run in parallel, which X1 ended on 2026-10-21 (Codex's review of 8c007979's cleanup table): re-measure and drop the shard launcher, any time.
- **Scratch runs** (done 2026-10-25, docs/development.md's "Scratch runs"). A run on a scratch clone, a measurement or a replay, sets three things, not one: MACPORTS_TREE to the clone, DOCKHAND_DB to its own database (a `.backup` copy for a replay, with `~/.dockhand/archives/` copied beside it), and DOCKHAND_CONFIG to a configuration whose `worktrees` is its own directory, as tools/acceptance/quick.sh does. MACPORTS_TREE picks the tree, not where its worktrees go: implementation's stop measurement (2026-10-25, b39a6fe3) set it alone, and its scratch branches went to the person's ~/Source/macports-branches. That root stays by design (engine.go `DefaultWorktrees`, one place a person knows, whichever clone): MACPORTS_TREE names the person's own clone as often as a scratch one, so tying the root to it would move their branches; a name already there is refused, never overwritten (engine/branches.go); and nothing sweeps the root. docs/development.md gets the three in a short paragraph, any time, docs alone, about a twentieth of a batch.

## Deferred

What dockhand won't do at all is in [principles](principles.md#what-dockhand-wont-do), since 2026-10-02: portable evidence, a scheduler, changing branches by itself, provider matrices, a QEMU provider, and v1 or v2 parity moved there from this list.

- Exporting state to Git notes, or rebuilding the database from Git metadata.
- A full-screen terminal interface (the person, 2026-10-02: there's room for one, but not now). `watch` and `status` keep their line output. The library survey's note (2026-10-02) stands: bubbletea is taken again only if `watch`'s designed panes are built.
- Fixing a Portfile's alignment automatically (the person, 2026-10-03): lining a declaration's value up with the lines around it, as MacPorts' style has it. Dockhand's edits only replace a value in place, so they keep whatever spacing the Portfile had, misaligned included.
