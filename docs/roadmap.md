## Next

Settled on 2026-09-20 from the day's survey and structural check, in ports gained per unit of work, with the index cache behind the coverage items because its cost is paid rarely, and re-sized on 2026-09-21 against the [baseline survey](activity/2026-09-21-baseline-survey.md):

2. **An outcome for ports with nothing to fetch.** Metaports with `distfiles` cleared, `_select` ports with no `master_sites`, and deprecated ports with a `replaced_by`, 441 in the baseline, 196 of them `_select` ports, are counted as unsupported today; they want their own outcome so the denominator stops lying.
3. **Literal segments of a composed version.** llvm's `${llvm_version}.0.6` yields only `17` as a candidate, and perturbing it renames the port; the literal segment `0.6` is the input, and the carrier loop's prefix and suffix inference already handles the rest. 4. **Host reads whose only consequence is a note.** php's three `file exists` sites decide a `notes-append` and nothing the edit or the fidelity comparison depends on, and they stop its SAPI and fpm subports; then the reads inside the qmake5, boost, and elisp PortGroups, each a per-group explanation of the kind `tolerateExplainedProbes` already gives compiler probes. 5. **Seeding the index cache across registrations.** The cache is keyed per repository registration, and this machine's 7 full generations out of 63 came mostly from separate registrations of the same repository re-indexing commits another registration already had; the existing seed-and-changed-paths path takes a generation from any registration, offline. Carried, unranked, and weighed when the list above drains or a real bump asks for them: the two foundation pieces of the [instance coordination note](instance-coordination.md), a stable per-process claim owner and a heartbeat keyed by database and repository; the state-boundaries review's narrower reads, still behind measurement; and the dependent verification follow-up. ## Later capabilities

### Dependent verification follow-up

Direct-dependent discovery, isolated Tart builds, per-target images, and full-cohort publication checks are implemented. Remaining work includes baseline comparison when an unrelated dependency causes a failure, a separate design for automatic downstream revision edits, and GitHub dependent coverage. Keep those separate from shared-release subports.

### Broader selectors and multi-target intake

Names and indexed subports work now; `assess` and `outdated` also support maintainer/category selection, and `assess` can scan the tree. Batch preparation remains future work: expose one result per requested target and preserve independent failures, admission rules, and attachment behavior. Do not add a generic batch interface merely to implement one shared release.

### GitHub verification refinements (done 2026-09-20; see completed capabilities)

Two of the three are done. Broader workflow coverage: the provider no longer pattern-matches `main.yml`, since a contribution confined to one port directory above an upstream base guarantees the workflow is upstream's own; it reads the file only to refuse a push trigger that would start no run, and judges the run by the jobs it carried ([note](activity/2026-09-20-workflow-read-not-matched.md)). Controlled reruns: a run that finished without succeeding is run again rather than adopted, which is what makes retrying a stopped verification work on this provider at all ([note](activity/2026-09-20-github-reruns.md)). Safe updates of already-pushed verification branches: a correction now authorizes replacing the commit it corrects, not only a published contribution's pull request head, which was the gap that made verifying an amended but unpublished contribution on the fork refuse ([note](activity/2026-09-20-correction-replaces-what-it-corrects.md)). The provider still compares before writing, so an unrecognized head is left alone. All three parts of this item are done; what is left here is the refinements the item began with as open-ended: broader workflow coverage beyond MacPorts' own file, and whether a refusal that a person can fix should close the request permanently or leave it retryable. After a local branch rename, forge verification now pushes to the PR's recorded head branch while the local name only locates the commit; see the [remote branch report](activity/2026-09-17-remote-branch-identity.md). Shared-run cancellation, missing-run diagnostics, delayed-run recovery, offline cancellation, and log-cache retention already exist; see the [GitHub exercise](activity/2026-09-15-xplr-github-exercise.md).

### Expiring credentials

Add access/refresh-token storage, expirations, and cross-process refresh rotation before enabling an authentication flow that requires expiring user tokens. Preserve the selected identity and require login again only after revocation or unusable refresh credentials. This is separate from the implemented device login and registered OAuth client.

### Reads that the state-boundaries review wants narrower

`loadExecution` reads every attempt and resource of a job under the write transaction, and the live table's two-second poll assembles full contribution history each time. The review calls these structural scaling concerns and made no measurement; extend the state performance probe with large cohorts and full live-status reads first, and narrow the working set or add a summary query only where it shows.

### Further preparation coverage

The 2026-09-21 baseline ([report](activity/2026-09-21-baseline-survey.md)) leaves 2,450 ports not covered, 5.9% of the tree, in buckets the Next section sizes: 441 with nothing to fetch, metaports and `_select` ports, which want their own outcome rather than a failure; 427 behind a pre-fetch hook the guard grammar refuses; 674 whose evaluation reads host state, 366 of them in the six frozen qt5x Portfiles, which are not worth modeling, 33 php's, and 275 others led by the pyqt5 family; 310 with no editable version input, down from 1,154, 71 of them llvm's composed version; and tails of checksum declarations outside the observed contexts (107, 61 of them php's), dependency manifests (119), calculated checksum algorithms (86), patchfiles dockhand cannot place (79), fetch customization or vendored source (78), and unknown tag conventions (63). Codeberg has a version input now and no source interpretation, so its 35 ports find their version and stop at discovery. Legacy digests are handled: a group with md5 or sha1, or without sha256, is rewritten with correct source ownership when its archive is refreshed, and `--keep-old-checksums` keeps it as written. What the baseline leaves after the queue above: the qt5x files, the other host readers less what a per-group explanation covers, and the tails; the 2,256 python stubs are not distfile ports and bump through their newest subport. FTP-only master sites are fetched since the survey tail, and checksum entries for patch files present in `files` are left as written; see the [Later-two report](activity/2026-09-18-later-two.md). A version composed from several variables, as openjdk11's is, and a commit pinned as a version, as gr-ieee802-15-4's is, are the two corpus unknowns and belong to the designs below. Arbitrary livecheck scripts, multiple independent version inputs, new release-series creation, and coordinated Rust/bootstrap maintenance still require separate designs rather than per-port special cases.

### Shared-release coverage on GitHub

Local verification of a shared release builds the newest subport by default and every subport with `--all-subports`; the GitHub provider still reports multi-target coverage as unsupported and the pull request workflow builds the siblings. Extend the GitHub provider when a shared release must be proven there before publication.

## Needs design

### Review and unattended-publication authority

`review accept` and `review dismiss` still need defined durable meaning: what creates a pending review, what acceptance authorizes, how it binds to a revision, and what dismissal closes. A manual bump/publish already records direct user intent. Implemented contribution abandonment is separate from a future review system.

Before discovery or a persistent driver can originate publishable work, define requester provenance and authority. Read-only `outdated` and starting a driver must not silently grant publication permission.

### More permissive human-edit capture

Managed amend/rebase and explicit reassociation are implemented under the [human-correction contract](human-corrections.md). Adopting unstaged tracked corrections or rebasing a checked-out branch needs crash-safe index/worktree preservation. Existing conservative preconditions remain until that design is complete. Discussed on 2026-09-20 and awaiting a decision: the unstaged-amend half is the smaller one, installing the port directory's tracked modifications into the index under the lock `amend` already holds, and the recommendation was to do that half and leave the checked-out rebase conservative; the alternative is to keep the precondition and have the refusal name `git add -u <portdir>`.

Standalone `publish` continues to require explicit verification when evidence is missing. Combined correction-and-publish commands authorize both steps; this is a settled rule, not an unimplemented feature.

### Instance coordination

Several processes on one database all drive today, arbitrated only by claims. The [instance coordination note](instance-coordination.md) records the leader-and-observer design discussed on 2026-09-18, the gotchas a walk-through found (anonymous claim owners, takeover gated by step timeouts, cancellation applied only inside cycles, driver-local progress lines), the multi-database and on-disk boundaries, and the redesigns that would make it robust: sessions with fenced leases first, then either a client-and-service split or an event journal. Two foundation pieces stand on their own: a stable per-process claim owner and a heartbeat record keyed by database and repository. The note's first draft also named two races that do not exist, corrected on 2026-09-20 after reading the code rather than inferring from a search that had not covered the right packages ([report](activity/2026-09-20-coordination-claims-corrected.md)): the Tart base images are already guarded by a reader-writer lock plus a provisioning lock under Tart's home, and capacity already unions the database's reservations with what Tart reports running on the host. What remains is one narrow window, the minutes between recording a reservation and the VM appearing in `tart list`, during which two databases sharing one Tart home can each overshoot the limit by one; it is worth a lease file only for someone who runs that way.

### Evidence across repository registrations

One database supports multiple repositories, but evidence is currently scoped to one registered clone. Decide whether identical tree/build inputs may share evidence across registrations and what repository trust checks are necessary. This is distinct from preserving identity within one contribution.
